# Overview

**Google Cloud Platform (GCP)** is Google's public cloud. Its strengths are **data and analytics** (BigQuery), **Kubernetes** (GKE — Google created Kubernetes), a **global network** (premium tier, global load balancing), **serverless containers** (Cloud Run) and **AI** (Vertex AI, Gemini).

For a .NET/full stack developer the most common setup is: **ASP.NET Core in a container on Cloud Run** + **Cloud SQL** (SQL Server or PostgreSQL) + **Cloud Storage** + **Secret Manager** + **Cloud Logging/Monitoring**, built with **Cloud Build**.

See the Azure ↔ AWS ↔ GCP service map in the AWS course. Key GCP names: Compute Engine (VMs), Cloud Run (serverless containers), GKE (Kubernetes), Cloud Storage (objects), Cloud SQL (managed relational), Firestore (documents), Pub/Sub (messaging), BigQuery (warehouse), Cloud Load Balancing, Cloud CDN, Cloud DNS, Secret Manager, Cloud KMS, Cloud Logging/Monitoring/Trace, Cloud Build, Artifact Registry.

# Lifecycle

**Deploying an ASP.NET Core API on GCP:**

1. Create a **project** (billing account linked), enable APIs (`run.googleapis.com`, `sqladmin.googleapis.com`, `secretmanager.googleapis.com`).
2. **Database:** Cloud SQL instance (SQL Server or PostgreSQL) with private IP or the Cloud SQL Auth Proxy/connector; HA (regional) and automated backups.
3. **Secrets:** store the DB password/connection string in Secret Manager.
4. **Build:** `gcloud builds submit` (Cloud Build) or GitHub Actions → container image in **Artifact Registry**.
5. **Deploy:** `gcloud run deploy` — Cloud Run gives an HTTPS URL, autoscaling (including to zero), revisions and traffic splitting.
6. **Edge:** custom domain + global external HTTPS load balancer with Cloud CDN and Cloud Armor (WAF) if needed.
7. **Operate:** Cloud Logging (stdout JSON logs collected automatically), Cloud Monitoring alerts, Cloud Trace (OpenTelemetry), Error Reporting, budgets.

# Module: Foundations

## Lesson: [Basic|High] Resource hierarchy, regions/zones and Cloud IAM

```text
Organisation (company.com)
 └── Folders (Production, Non-production, Teams)
      └── Projects (shop-prod, shop-dev)   ← billing, APIs, quotas and resources live in projects
           └── Resources (Cloud Run services, Cloud SQL instances, buckets)
```

- **Region** (e.g. `asia-south1` Mumbai, `asia-east1` Taiwan, `us-central1`) contains **zones** (`asia-south1-a/b/c`). Resources are **zonal** (VMs, disks), **regional** (Cloud Run, regional Cloud SQL, regional GKE) or **multi-regional/global** (Cloud Storage multi-region, global load balancer, BigQuery multi-region).
- **Cloud IAM:** grant **roles** (collections of permissions) to **principals** (Google accounts, groups, **service accounts**, workforce/workload identity) on a resource; policies inherit down the hierarchy.
  - Basic roles (Owner/Editor/Viewer) — too broad for production.
  - **Predefined roles** (`roles/run.invoker`, `roles/cloudsql.client`, `roles/storage.objectViewer`) — use these.
  - Custom roles when needed.
- **Service accounts** are identities for workloads (a Cloud Run service runs as a service account); use **Workload Identity Federation** for GitHub Actions/AWS/Azure to avoid service account keys.

```bash
gcloud projects add-iam-policy-binding shop-prod \
  --member="serviceAccount:shop-api@shop-prod.iam.gserviceaccount.com" --role="roles/cloudsql.client"
```

# Module: Compute

## Lesson: [Basic|High] Compute Engine, Cloud Run, GKE, App Engine and Cloud Run functions

| Service | Model | .NET use |
|---|---|---|
| **Compute Engine** | VMs (Windows Server images with IIS available; managed instance groups for autoscaling) | Lift-and-shift .NET Framework/IIS apps |
| **Cloud Run** | Serverless containers (HTTP services and jobs), scale to zero, per-request billing | **ASP.NET Core APIs and web apps** — the default choice |
| **GKE** (Standard / **Autopilot**) | Managed Kubernetes | Many microservices, teams on Kubernetes |
| **App Engine** (Standard/Flexible) | Original PaaS | Legacy; Flexible supports .NET via containers |
| **Cloud Run functions** (formerly Cloud Functions) | Event-driven functions (.NET supported) | Triggers from Pub/Sub, Storage, Eventarc |

```bash
# Build and deploy an ASP.NET Core API to Cloud Run from source (uses Cloud Build + buildpacks or your Dockerfile)
gcloud run deploy shop-api --source . --region asia-south1 --allow-unauthenticated \
  --service-account shop-api@shop-prod.iam.gserviceaccount.com \
  --set-secrets "ConnectionStrings__Shop=shop-db-cs:latest" --min-instances 0 --max-instances 20
```

```csharp
// Program.cs — Cloud Run sends the port in the PORT environment variable
var port = Environment.GetEnvironmentVariable("PORT") ?? "8080";
builder.WebHost.UseUrls($"http://0.0.0.0:{port}");
```

Cloud Run facts: each **revision** is immutable; **traffic splitting** for canary releases; concurrency (default up to 80 requests per instance); request timeout up to 60 minutes; min instances to avoid cold starts; VPC access for private Cloud SQL/Memorystore.

# Module: Storage and Databases

## Lesson: [Basic|High] Cloud Storage

Object storage in **buckets** (globally unique names), classes **Standard**, **Nearline** (≥30 days), **Coldline** (≥90 days), **Archive** (≥365 days); **Autoclass** moves objects automatically; lifecycle rules; object versioning; **signed URLs** for temporary access; uniform bucket-level access with IAM; encryption by default (Google-managed or customer-managed keys in Cloud KMS).

```csharp
var storage = await StorageClient.CreateAsync();                 // credentials from the service account automatically
await using var file = File.OpenRead(path);
await storage.UploadObjectAsync("shop-uploads-prod", $"invoices/{id}.pdf", "application/pdf", file);
var signer = UrlSigner.FromCredential(await GoogleCredential.GetApplicationDefaultAsync());
string url = await signer.SignAsync("shop-uploads-prod", $"invoices/{id}.pdf", TimeSpan.FromMinutes(15));
```

## Lesson: [Intermediate|High] Databases — Cloud SQL (SQL Server), AlloyDB, Spanner, Firestore, Bigtable, Memorystore

| Service | Type | Use |
|---|---|---|
| **Cloud SQL** | Managed **SQL Server**, PostgreSQL, MySQL | Most business apps; lift-and-shift SQL Server |
| **AlloyDB** | PostgreSQL-compatible, high performance (columnar engine for analytics) | Demanding PostgreSQL workloads |
| **Spanner** | Globally distributed, strongly consistent relational (SQL) with horizontal scale | Global financial/inventory systems needing scale + consistency |
| **Firestore** | Serverless document database with real-time listeners and offline mobile sync | Mobile/web apps, user profiles |
| **Bigtable** | Wide-column NoSQL for huge throughput (HBase API) | Time series, IoT, analytics at petabyte scale |
| **Memorystore** | Managed Redis/Valkey/Memcached | Caching, sessions |
| **BigQuery** | Serverless data warehouse (SQL over petabytes) | Analytics, BI, ML |

**Cloud SQL for SQL Server:** editions Express/Web/Standard/Enterprise (licence included), **high availability** (regional instance with a standby in another zone, automatic failover), automated backups + point-in-time recovery, read replicas, private IP, maintenance windows. Connect with:

- **Private IP** from Cloud Run/GKE via VPC (Direct VPC egress or Serverless VPC Access).
- **Cloud SQL Auth Proxy / language connectors** — IAM-authorised, encrypted tunnel without managing IP allow-lists (for SQL Server, run the proxy as a sidecar or locally).

```text
Server=10.20.0.5;Database=Shop;User Id=shop_app;Password=<from Secret Manager>;Encrypt=True;TrustServerCertificate=False
```

# Module: Integration, Networking and Security

## Lesson: [Intermediate|High] Pub/Sub, Eventarc, Cloud Tasks and BigQuery

- **Pub/Sub** — global messaging: publishers send to a **topic**; each **subscription** gets every message (pull or push to an HTTPS endpoint such as Cloud Run); at-least-once delivery (exactly-once option for pull), ordering keys, dead-letter topics, retention and replay.
- **Eventarc** — routes events from Google services (Cloud Storage object finalised, audit logs) and Pub/Sub to Cloud Run.
- **Cloud Tasks** — queue of HTTP tasks with rate limits and retries (like a background job queue for one service).
- **Cloud Scheduler** — cron jobs calling HTTP endpoints/Pub/Sub.
- **Workflows** — orchestrate services/APIs (sagas).
- **Dataflow** (Apache Beam) — stream/batch processing; **BigQuery** — load or stream data and query with SQL; Looker/Looker Studio for dashboards.

```csharp
var publisher = await PublisherClient.CreateAsync(TopicName.FromProjectTopic("shop-prod", "order-placed"));
await publisher.PublishAsync(JsonSerializer.Serialize(new { orderId, total }));
```

## Lesson: [Intermediate|Medium] VPC, load balancing, Cloud CDN, Cloud DNS and Cloud Armor

- **VPC networks are global** in GCP (subnets are regional) — one VPC can span regions.
- **Firewall rules/policies** on VPCs target instances by tags or service accounts.
- **Cloud Load Balancing:** global external Application Load Balancer (single anycast IP worldwide, routes to the nearest healthy backend — Cloud Run, GKE, instance groups, buckets), regional and internal load balancers.
- **Cloud CDN** on the load balancer; **Cloud Armor** for WAF/DDoS protection; **Cloud DNS** for managed zones; **Certificate Manager** / Google-managed SSL certificates.
- **Private Service Connect / Private Google Access** to reach Google APIs without public IPs; **Cloud NAT** for outbound internet from private resources.

## Lesson: [Intermediate|High] Security and operations — Secret Manager, KMS, Logging, Monitoring

- **Secret Manager** — versioned secrets, IAM-controlled; Cloud Run mounts them as env vars or files (`--set-secrets`).
- **Cloud KMS** — encryption keys (CMEK for Storage, Cloud SQL, BigQuery); HSM-backed keys.
- **Identity Platform / Firebase Authentication** — end-user sign-in; **Identity-Aware Proxy (IAP)** — protect internal apps with Google identity without a VPN.
- **Security Command Center**, **Organization Policies** (e.g. disallow public buckets, restrict regions), VPC Service Controls (data exfiltration perimeters).
- **Cloud Logging** (stdout/stderr JSON from Cloud Run/GKE is ingested automatically; Logs Explorer queries; log sinks to BigQuery/Storage), **Cloud Monitoring** (metrics, uptime checks, alerting, SLOs), **Cloud Trace**/**Profiler**, **Error Reporting**. ASP.NET Core: write structured JSON logs to stdout or use `Google.Cloud.Diagnostics.AspNetCore3`; OpenTelemetry exporters for traces.

# Module: Delivery and Cost

## Lesson: [Intermediate|Medium] CI/CD — Cloud Build, Artifact Registry, Cloud Deploy and GitHub Actions

```yaml
# cloudbuild.yaml — build, push and deploy on every commit (trigger from GitHub)
steps:
  - name: gcr.io/cloud-builders/docker
    args: ["build", "-t", "asia-south1-docker.pkg.dev/$PROJECT_ID/shop/api:$SHORT_SHA", "."]
  - name: gcr.io/cloud-builders/docker
    args: ["push", "asia-south1-docker.pkg.dev/$PROJECT_ID/shop/api:$SHORT_SHA"]
  - name: gcr.io/google.com/cloudsdktool/cloud-sdk
    entrypoint: gcloud
    args: ["run", "deploy", "shop-api", "--image", "asia-south1-docker.pkg.dev/$PROJECT_ID/shop/api:$SHORT_SHA", "--region", "asia-south1"]
images: ["asia-south1-docker.pkg.dev/$PROJECT_ID/shop/api:$SHORT_SHA"]
```

GitHub Actions alternative: `google-github-actions/auth` with **Workload Identity Federation** (no JSON keys) + `google-github-actions/deploy-cloudrun`. **Cloud Deploy** manages promotion pipelines (dev → staging → prod) for GKE and Cloud Run with approvals and rollbacks.

## Lesson: [Intermediate|Medium] Cost management and the Google Cloud Architecture Framework

- Pricing perks: **sustained use discounts** (automatic for VMs running much of the month), **committed use discounts** (1/3 years), **Spot VMs**, per-second billing, Cloud Run scale-to-zero, free tier.
- Controls: budgets and alerts, billing export to BigQuery for analysis, labels for cost allocation, recommender (idle VMs, oversized instances), lifecycle rules on buckets, BigQuery cost control (partitioned/clustered tables, `maximum_bytes_billed`, avoid `SELECT *`).
- **Architecture Framework pillars:** system design, operational excellence, security/privacy/compliance, reliability, cost optimisation, performance optimisation (plus sustainability guidance).

# Interview

## [Beginner|High] What is the GCP resource hierarchy?

Organisation (your domain) → folders (departments/environments) → projects → resources. Projects are the core unit: they hold resources, enabled APIs, quotas and are linked to a billing account. IAM policies and organisation policies set at higher levels are inherited by everything below.

## [Beginner|High] What is Cloud Run and why is it popular for .NET APIs?

A fully managed platform that runs any stateless HTTP container: you deploy an image (or source), get an HTTPS endpoint, automatic scaling from zero to many instances, per-request billing, revisions with traffic splitting, and integration with Secret Manager, Cloud SQL and Pub/Sub. ASP.NET Core containers run unchanged — just listen on the `PORT` environment variable.

## [Beginner|High] What are service accounts?

Identities for workloads rather than people. A Cloud Run service, VM or GKE workload runs as a service account, and IAM roles granted to that account decide what Google APIs it can call (e.g. `roles/cloudsql.client`, `roles/secretmanager.secretAccessor`). Client libraries pick up its credentials automatically; avoid downloading service account keys — use Workload Identity (Federation) instead.

## [Beginner|Medium] Compute Engine vs Cloud Run vs GKE vs App Engine?

Compute Engine: VMs with full control (legacy/IIS apps). Cloud Run: serverless containers — simplest for HTTP services and jobs. GKE: managed Kubernetes for complex microservice platforms (Autopilot reduces node management). App Engine: the original PaaS, now mostly replaced by Cloud Run for new work.

## [Intermediate|High] How do you connect a Cloud Run service to Cloud SQL for SQL Server securely?

Use a private IP Cloud SQL instance and connect from Cloud Run through VPC egress (Direct VPC egress or a Serverless VPC Access connector), or use the Cloud SQL Auth Proxy/connector which authorises with IAM and encrypts the connection. Run Cloud Run as a dedicated service account with `roles/cloudsql.client`, keep the password/connection string in Secret Manager mounted as an environment variable, and enable HA and backups on the instance.

## [Intermediate|High] Pub/Sub vs Cloud Tasks?

Pub/Sub is many-to-many event messaging: publishers send to topics and every subscription receives each message (fan-out, decoupling, streaming). Cloud Tasks is a queue of individual HTTP tasks targeted at one handler with explicit rate limits, scheduling and retries — like a background job queue. Use Pub/Sub for events, Cloud Tasks for controlled work dispatch.

## [Intermediate|High] What is BigQuery and when would you use it?

A serverless, columnar data warehouse that runs SQL over terabytes–petabytes without managing servers, billed by storage and bytes scanned (or reserved slots). Use it for analytics, reporting, log analysis and ML (BigQuery ML) — not for OLTP. Partition and cluster tables and avoid `SELECT *` to control cost.

## [Intermediate|Medium] Cloud SQL vs Spanner vs Firestore vs Bigtable?

Cloud SQL: managed SQL Server/PostgreSQL/MySQL for typical regional relational apps. Spanner: horizontally scalable, globally consistent relational database for very large or global systems. Firestore: serverless document database with real-time sync for web/mobile. Bigtable: wide-column NoSQL for massive throughput time-series/analytical workloads.

## [Intermediate|Medium] How is a GCP VPC different from AWS/Azure networks?

GCP VPC networks are global resources — one VPC spans all regions with regional subnets, and instances in different regions communicate over Google's private network without peering. AWS VPCs and Azure VNets are regional and need peering or transit gateways to connect regions. Firewall rules in GCP apply at the VPC level and can target network tags or service accounts.

## [Advanced|Medium] How do you avoid service account keys in CI/CD?

Use Workload Identity Federation: configure a workload identity pool and provider trusting GitHub Actions' (or Azure DevOps') OIDC tokens, allow it to impersonate a deploy service account with minimal roles, and authenticate in the pipeline with `google-github-actions/auth` — short-lived tokens, nothing secret stored in the CI system.

## [Scenario|High] You need to deploy an ASP.NET Core API with a SQL Server database on GCP with minimal operations work. What do you build?

Containerise the API (Dockerfile listening on PORT), push to Artifact Registry with Cloud Build, deploy to Cloud Run with a dedicated service account, min instances 1 for low latency, secrets from Secret Manager; Cloud SQL for SQL Server (HA, backups, PITR, private IP) reached via VPC egress; Cloud Logging/Monitoring alerts on errors and latency; a global HTTPS load balancer with Cloud Armor if a custom domain and WAF are needed; budgets for cost control.

## [Scenario|Medium] Logs from your .NET app on Cloud Run show up as plain text without severity. How do you fix it?

Write structured JSON logs to stdout with a `severity` field (and `message`, trace fields) — e.g. use a JSON console formatter or Google.Cloud.Diagnostics.AspNetCore3 — so Cloud Logging parses levels and fields, and include the `logging.googleapis.com/trace` field to correlate logs with Cloud Trace requests.

## [Scenario|Medium] BigQuery costs are high because analysts run large queries. How do you reduce them?

Partition tables by date and cluster by common filters, require partition filters, avoid `SELECT *`, use materialised views and BI Engine for dashboards, set per-user/per-project custom quotas and `maximum_bytes_billed`, consider slot reservations (editions) for predictable spend, and review the most expensive queries in INFORMATION_SCHEMA jobs views.

## [Beginner|Medium] What are regions, zones and multi-regions in GCP?

A region is a geographic location (asia-south1 Mumbai) with three or more zones — isolated deployment areas within the region. Zonal resources (VMs, disks) live in one zone; regional resources replicate across zones (regional Cloud SQL HA, Cloud Run); multi-regional resources (Cloud Storage multi-region, BigQuery US/EU) replicate across regions for availability and proximity.

## [Intermediate|Medium] How do you control access to a Cloud Run service?

Public services allow `allUsers` the `roles/run.invoker` role; private services require callers with run.invoker (service accounts for service-to-service with ID tokens), Identity-Aware Proxy for employees, or ingress settings restricting traffic to internal/load balancer only. Combine with application-level auth (JWT from Identity Platform/Entra) for end users.
