# Overview

**Vue.js** is a progressive JavaScript framework for building user interfaces, created by **Evan You** (ex-Google, worked on AngularJS) in 2014. "Progressive" means you can use it as a drop-in script to enhance a page, or as a full SPA framework with router, state management and SSR.

Key characteristics:

- **Single-File Components (SFCs)** — `.vue` files with `<template>`, `<script>` and `<style>` together.
- **Declarative templates** with directives (`v-if`, `v-for`, `v-model`, `v-bind`, `v-on`).
- **Fine-grained reactivity** — Vue tracks which components depend on which state (via JavaScript **Proxies** in Vue 3) and re-renders only what's needed.
- Two API styles: **Options API** (`data`, `methods`, `computed`) and **Composition API** (`ref`, `reactive`, `computed` inside `<script setup>`).
- Official ecosystem: **Vue Router**, **Pinia** (state), **Vite** (build tool, also created by Evan You), **Vue DevTools**, **Nuxt** (full-stack framework, third-party but closely aligned).

Vue sits between AngularJS-style templates and React-style components: approachable for beginners, scalable for large apps (used by Alibaba, Xiaomi, GitLab, Nintendo and many Asian companies).

# Lifecycle

**Component lifecycle (Composition API hook → Options API name):**

| Phase | Composition API | Options API | Use |
|---|---|---|---|
| Setup | `setup()` / `<script setup>` runs | `beforeCreate`, `created` | Initialise state; no DOM yet |
| Before mount | `onBeforeMount` | `beforeMount` | Template compiled, about to render |
| Mounted | `onMounted` | `mounted` | DOM available — fetch data, third-party libs, focus |
| Before update | `onBeforeUpdate` | `beforeUpdate` | State changed, before DOM patch |
| Updated | `onUpdated` | `updated` | DOM patched (avoid changing state here) |
| Before unmount | `onBeforeUnmount` | `beforeUnmount` (Vue 2: `beforeDestroy`) | Cleanup start |
| Unmounted | `onUnmounted` | `unmounted` (Vue 2: `destroyed`) | Remove listeners, timers |
| Errors | `onErrorCaptured` | `errorCaptured` | Error from a descendant |
| KeepAlive | `onActivated` / `onDeactivated` | `activated` / `deactivated` | Cached components shown/hidden |
| SSR | `onServerPrefetch` | `serverPrefetch` | Fetch data during SSR |

**Reactivity update cycle:** state change → the reactive Proxy's `set` trap triggers the effects (components, computeds, watchers) that read that property → component re-render is **queued** and batched in the next microtask (`nextTick`) → virtual DOM diff (optimised by compiler hints: static hoisting, patch flags, block tree) → DOM patched → `onUpdated`.

**App bootstrap:** `createApp(App)` → `app.use(router)`, `app.use(createPinia())`, global components/directives → `app.mount("#app")`.

## Lesson: [Basic|High] Template syntax and directives

```vue
<template>
  <p>{{ message.toUpperCase() }}</p>                    <!-- interpolation (escaped) -->
  <p v-html="trustedHtml"></p>                           <!-- raw HTML: XSS risk with user input -->
  <img :src="product.image" :alt="product.name" />       <!-- v-bind shorthand ':' -->
  <button @click="addToCart(product)">Add</button>       <!-- v-on shorthand '@' -->
  <form @submit.prevent="save">                          <!-- event modifiers: .prevent .stop .once .self -->
    <input v-model.trim="name" @keyup.enter="save" />    <!-- v-model modifiers: .trim .number .lazy -->
  </form>

  <p v-if="orders.length === 0">No orders</p>
  <p v-else-if="loading">Loading…</p>
  <ul v-else>
    <li v-for="(o, index) in orders" :key="o.id">{{ index + 1 }}. {{ o.customer }}</li>
  </ul>

  <div v-show="isOpen">Toggled with CSS display</div>
  <span v-once>{{ initialValue }}</span>                 <!-- render once -->
  <component :is="currentTab" />                         <!-- dynamic component -->
</template>
```

| Directive | Purpose |
|---|---|
| `v-bind` / `:` | Bind attribute/prop |
| `v-on` / `@` | Listen to events |
| `v-model` | Two-way binding on inputs/components |
| `v-if` / `v-else-if` / `v-else` | Conditional rendering (creates/destroys) |
| `v-show` | Toggle `display` (stays in DOM) |
| `v-for` | Lists (always with `:key`) |
| `v-html`, `v-text` | Raw HTML / text |
| `v-slot` / `#` | Named/scoped slots |
| `v-once`, `v-memo`, `v-pre`, `v-cloak` | Render optimisation / skip compilation |

Avoid `v-if` and `v-for` on the same element (in Vue 3 `v-if` has higher priority) — filter in a computed property or wrap with `<template>`.

## Lesson: [Intermediate|High] Connecting a Vue app to SQL Server (through an API)

Like every browser framework, Vue talks to an **HTTP API**, and the API talks to SQL Server (ASP.NET Core with EF Core/Dapper, or Node.js with `mssql`; with Nuxt the `server/api` routes can query SQL Server directly on the server).

```ts
// src/services/api.ts
const BASE = import.meta.env.VITE_API_URL ?? "";
export async function api<T>(path: string, init?: RequestInit): Promise<T> {
  const res = await fetch(`${BASE}${path}`, { ...init, headers: { "Content-Type": "application/json", ...init?.headers } });
  if (!res.ok) throw new Error(`API ${res.status}`);
  return res.json();
}

// src/composables/useProducts.ts
import { ref, onMounted } from "vue";
import { api } from "../services/api";
export type Product = { id: number; name: string; price: number };
export function useProducts() {
  const products = ref<Product[]>([]);
  const loading = ref(true);
  const error = ref<string | null>(null);
  onMounted(async () => {
    try { products.value = await api<Product[]>("/api/products"); }
    catch { error.value = "Could not load products"; }
    finally { loading.value = false; }
  });
  return { products, loading, error };
}
```

```vue
<!-- src/views/ProductsView.vue -->
<script setup lang="ts">
import { useProducts } from "../composables/useProducts";
const { products, loading, error } = useProducts();
</script>
<template>
  <p v-if="loading">Loading…</p>
  <p v-else-if="error">{{ error }}</p>
  <ul v-else><li v-for="p in products" :key="p.id">{{ p.name }} — ₹{{ p.price }}</li></ul>
</template>
```


# Module: Reactivity

## Lesson: [Basic|High] ref, reactive, computed and watch

```ts
import { ref, reactive, computed, watch, watchEffect } from "vue";

const count = ref(0);                         // any value; access .value in script, auto-unwrapped in templates
count.value++;

const cart = reactive({ items: [] as Item[], coupon: "" });   // objects only; deep reactive Proxy
cart.items.push({ id: 1, price: 900, qty: 2 });

const total = computed(() => cart.items.reduce((s, i) => s + i.price * i.qty, 0));   // cached until deps change

watch(count, (newVal, oldVal) => console.log(`count ${oldVal} → ${newVal}`));         // specific source, lazy
watch(() => cart.coupon, async code => { cart.discount = await validateCoupon(code); });
watch(() => props.userId, id => loadUser(id), { immediate: true });
watchEffect(() => console.log("total is", total.value));     // runs immediately, auto-tracks dependencies
```

| | `ref` | `reactive` |
|---|---|---|
| Holds | Any type (primitives too) | Objects, arrays, Maps, Sets |
| Access | `.value` in script | Direct property access |
| Reassign whole value | Yes (`x.value = newObj`) | No — replacing the variable breaks reactivity |
| Destructuring | Fine | **Loses reactivity** — use `toRefs()` |

Recommendation from the Vue docs: prefer `ref` as the primary API. `shallowRef`/`shallowReactive` for large non-deep data; `readonly()` to expose state safely; `toRaw()`/`markRaw()` to opt out.

**computed vs watch vs methods:** computed = derived value, cached; methods = called every time (event handlers or uncached work); watch = side effects in response to changes (API calls, localStorage).

## Lesson: [Intermediate|High] How Vue 3 reactivity works

- `reactive()` wraps an object in a **Proxy**: the `get` trap **tracks** which running effect (component render, computed, watcher) read the property; the `set` trap **triggers** those effects.
- `ref()` is an object with a getter/setter on `.value` doing the same tracking.
- Effects re-run → component re-render is scheduled → batched → DOM patched in the next tick (`await nextTick()` to read updated DOM).
- Vue 2 used `Object.defineProperty`, so it couldn't detect **added/deleted properties** or **array index assignment** — you needed `Vue.set`/`this.$set`. Vue 3's Proxies detect all of these.

```ts
const state = reactive({ user: { name: "Asha" } });
state.user.email = "a@x.com";        // reactive in Vue 3 (needed Vue.set in Vue 2)
const arr = reactive([1, 2, 3]);
arr[0] = 99;                          // reactive in Vue 3
```

## Lesson: [Intermediate|High] Options API vs Composition API

```vue
<!-- Options API -->
<script>
export default {
  props: { initial: { type: Number, default: 0 } },
  data() { return { count: this.initial }; },
  computed: { double() { return this.count * 2; } },
  watch: { count(n) { console.log(n); } },
  methods: { increment() { this.count++; } },
  mounted() { console.log("mounted"); },
};
</script>

<!-- Composition API with <script setup> -->
<script setup>
import { ref, computed, watch, onMounted } from "vue";
const props = defineProps({ initial: { type: Number, default: 0 } });
const count = ref(props.initial);
const double = computed(() => count.value * 2);
watch(count, n => console.log(n));
const increment = () => count.value++;
onMounted(() => console.log("mounted"));
</script>
```

| | Options API | Composition API |
|---|---|---|
| Organisation | By option type (data/methods/computed) | By **feature/logic** |
| Reuse | Mixins (name clashes, unclear origin) | **Composables** (plain functions) |
| TypeScript | Weaker inference | Excellent |
| Learning curve | Easier for beginners | More flexible, better for large apps |
| `this` | Used everywhere | No `this` |

Both are fully supported in Vue 3; new projects usually use `<script setup>` + Composition API.

# Module: Components

## Lesson: [Basic|High] Props, emits and v-model on components

```vue
<!-- ChildInput.vue -->
<script setup lang="ts">
const model = defineModel<string>({ required: true });     // Vue 3.4+: two-way binding helper
const props = withDefaults(defineProps<{ label: string; max?: number }>(), { max: 100 });
const emit = defineEmits<{ (e: "submit", value: string): void }>();
</script>
<template>
  <label>{{ label }} <input v-model="model" :maxlength="max" @keyup.enter="emit('submit', model)" /></label>
</template>

<!-- Parent.vue -->
<ChildInput v-model="search" label="Search" @submit="runSearch" />
```

- **One-way data flow**: props flow down and are **read-only** in the child (Vue warns if you mutate them). To change data, emit an event or use `v-model`.
- Prop validation (`type`, `required`, `default`, `validator`) or TypeScript types.
- `v-model` on a component = `modelValue` prop + `update:modelValue` event (multiple: `v-model:title`).
- Fallthrough attributes (`class`, `id`, listeners) apply to the root element (`inheritAttrs: false` + `v-bind="$attrs"` to control).

| Communication | How |
|---|---|
| Parent → child | Props |

## Lesson: [Intermediate|High] Composables (reusable logic)

```ts
// composables/useFetch.ts
import { ref, watchEffect, toValue, type MaybeRefOrGetter } from "vue";

export function useFetch<T>(url: MaybeRefOrGetter<string>) {
  const data = ref<T | null>(null);
  const error = ref<Error | null>(null);
  const loading = ref(false);

  watchEffect(async onCleanup => {
    const controller = new AbortController();
    onCleanup(() => controller.abort());
    loading.value = true; error.value = null;
    try {
      const res = await fetch(toValue(url), { signal: controller.signal });
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      data.value = await res.json();
    } catch (e) {
      if ((e as Error).name !== "AbortError") error.value = e as Error;
    } finally {
      loading.value = false;
    }
  });
  return { data, error, loading };
}

// In a component
const { data: orders, loading } = useFetch<Order[]>(() => `/api/orders?page=${page.value}`);
```

Composables are functions named `useXxx` that use Composition API features; each call gets its own state (or share module-level state for a singleton). **VueUse** offers 200+ ready-made composables (`useLocalStorage`, `useDebounceFn`, `useIntersectionObserver`).

## Lesson: [Intermediate|High] Pinia state management

```ts
// stores/cart.ts — setup store syntax
import { defineStore } from "pinia";
import { ref, computed } from "vue";

export const useCartStore = defineStore("cart", () => {
  const items = ref<CartItem[]>([]);
  const total = computed(() => items.value.reduce((s, i) => s + i.price * i.qty, 0));   // getter
  function add(item: CartItem) { items.value.push(item); }                              // action
  async function checkout() { await api.checkout(items.value); items.value = []; }
  return { items, total, add, checkout };
});

// In a component
const cart = useCartStore();
const { items, total } = storeToRefs(cart);    // keep reactivity when destructuring state/getters
cart.add({ id: 1, name: "Mouse", price: 900, qty: 1 });
```

**Pinia vs Vuex:** Pinia (official since 2022) has no mutations (actions change state directly), a simpler API, full TypeScript inference, modular stores by default (no nested modules/namespaces), DevTools support and a tiny size. Vuex 4 is maintenance-only. Options-store syntax (`state`, `getters`, `actions`) is also supported.

## Lesson: [Intermediate|Medium] Forms and validation

# Module: Quality and Performance

## Lesson: [Advanced|High] Performance optimisation

1. Lazy-load routes and heavy components (`() => import()`, `defineAsyncComponent`).
2. Stable `:key`s; avoid `v-if` + `v-for` together; prefer `v-show` for frequent toggles.
3. **Virtual scrolling** for long lists (vue-virtual-scroller, TanStack Virtual).
4. `shallowRef`/`shallowReactive`/`markRaw` for large immutable data or third-party instances.
5. `v-once` / `v-memo` for static or rarely changing subtrees.
6. Computed properties instead of methods in templates (cached).
7. Keep props stable so child components don't re-render unnecessarily (Vue already skips children whose props didn't change).
8. `KeepAlive` for tabs to avoid re-creating components.
9. SSR/SSG with Nuxt for first paint and SEO; lazy hydration (3.5).
10. Analyse bundles (`rollup-plugin-visualizer`), tree-shake imports, production builds.

## Lesson: [Intermediate|Medium] Testing Vue components

```ts
import { mount } from "@vue/test-utils";
import { describe, it, expect } from "vitest";
import OrderCard from "@/components/OrderCard.vue";

describe("OrderCard", () => {
  it("emits select with the order id", async () => {
    const wrapper = mount(OrderCard, { props: { order: { id: 7, customer: "Asha", total: 500, status: "paid" } } });
    await wrapper.trigger("click");
```

Use `@pinia/testing` (`createTestingPinia`) to stub stores, mock HTTP with MSW, and test user-visible behaviour (Testing Library for Vue is also available). E2E with Playwright or Cypress.

## Lesson: [Advanced|Medium] Nuxt and migrating Vue 2 → Vue 3

**Nuxt** (Nuxt 4, 2025): file-based routing (`pages/`), layouts, auto-imports of components and composables, SSR/SSG/hybrid rendering per route (`routeRules`), server API routes (`server/api` on the Nitro engine), `useFetch`/`useAsyncData` with SSR-friendly data fetching, modules ecosystem (Pinia, Tailwind, i18n, content). Deploy to Node, serverless or edge.

**Vue 2 → 3 migration** (Vue 2 is EOL since Dec 2023):

- Use the **migration build** (`@vue/compat`) to run Vue 2 code on Vue 3 with deprecation warnings, fix them incrementally, then remove compat.
- Breaking changes: `new Vue()` → `createApp()`; global API (`Vue.use`, `Vue.component`) → app instance; filters removed (use methods/computed); `v-model` on components uses `modelValue`/`update:modelValue`; `$listeners` merged into `$attrs`; `v-if` priority over `v-for`; `beforeDestroy/destroyed` → `beforeUnmount/unmounted`; `$on/$off` removed (no event bus); functional components simplified; `.sync` replaced by `v-model:prop`.
- Upgrade ecosystem: Vue Router 4, Pinia (or Vuex 4), Vuetify 3/other UI library versions, Vite instead of Vue CLI.
- Vue 2.7 can be an intermediate step (Composition API available in Vue 2).

# Interview

## [Beginner|High] What is Vue.js and why is it called progressive?

Vue is an open-source JavaScript framework for building UIs and SPAs (Evan You, 2014). It's "progressive" because you can adopt it incrementally: start by adding it to part of a page via a script tag, then grow into a full SPA with SFCs, Vue Router, Pinia, a build tool and SSR (Nuxt). It offers declarative templates, a reactive data system, components and a small, fast core.

## [Beginner|High] What are the most commonly used Vue directives?

`v-bind` (`:`) for attributes/props, `v-on` (`@`) for events (with modifiers like `.prevent`), `v-model` for two-way form binding, `v-if/v-else-if/v-else` for conditional rendering, `v-show` for CSS visibility toggling, `v-for` for lists with `:key`, `v-html`/`v-text`, `v-slot` (`#`) for slots, plus `v-once`, `v-memo`, `v-pre`, `v-cloak`. Custom directives are possible for low-level DOM access.

## [Beginner|High] What is the difference between v-if and v-show?

`v-if` conditionally renders: when false the element and its child components aren't created (or are destroyed), so toggling is expensive but the initial render is cheap. `v-show` always renders the element and toggles `display: none`, so toggling is cheap but the initial render always pays the cost. Use `v-show` for frequent toggles, `v-if` for rarely changing conditions. `v-show` doesn't work on `<template>`.

## [Beginner|High] What are computed properties and how are they different from methods and watchers?

Computed properties derive values from reactive state and are **cached** until their dependencies change — ideal for filtered lists or totals used in templates. Methods run every time they're called (re-render) — use for event handlers. Watchers run side effects when a specific value changes (API calls, saving to localStorage); `watchEffect` auto-tracks dependencies.

## [Beginner|High] What is the purpose of the `key` attribute in v-for?

`key` gives each item a unique, stable identity so Vue's virtual DOM can track, reorder and reuse elements correctly and preserve component state and DOM state (focus, input values). Without keys, Vue uses an in-place patch strategy that can show stale state when items are reordered or removed. Use unique IDs, not array indexes, for dynamic lists.

## [Beginner|Medium] How do you pass data between parent and child components?

Parent to child with **props** (read-only in the child). Child to parent by **emitting events** (`defineEmits`, `emit('save', data)`), and two-way via `v-model` on components (`defineModel`). For deeper trees use provide/inject; for global or sibling state use Pinia; parent can call child methods via template refs and `defineExpose`.

## [Intermediate|High] Explain ref vs reactive.

`ref()` wraps any value (including primitives) in an object with a reactive `.value` property; templates unwrap it automatically. `reactive()` makes an object/array/Map deeply reactive via a Proxy, accessed directly without `.value`, but you can't reassign the whole object and destructuring loses reactivity (use `toRefs`). The Vue docs recommend `ref` as the default because it works with all types and is explicit.

## [Intermediate|High] How does reactivity work in Vue 3? How is it different from Vue 2?

Vue 3 wraps state in JavaScript Proxies: getters track which effect (render, computed, watcher) accessed a property; setters trigger those effects, which re-run in a batched, asynchronous update queue. Vue 2 used `Object.defineProperty` on existing properties, so it couldn't detect new or deleted properties or direct array index/length changes, requiring `Vue.set`/`Vue.delete`. Proxies remove those caveats and improve performance and memory usage.

## [Intermediate|High] Options API vs Composition API — which and why?

The Options API organises code by option type (data, methods, computed, lifecycle) and is easy for small components and beginners. The Composition API (`setup`/`<script setup>`) organises code by logical concern, enables clean reuse via composables (replacing mixins and their naming conflicts), and gives far better TypeScript inference. For large or long-lived apps, the Composition API with `<script setup>` is generally preferred; both are supported in Vue 3.

## [Intermediate|High] What are the lifecycle hooks in Vue 3?

`setup` (replacing beforeCreate/created), `onBeforeMount`, `onMounted` (DOM ready — fetch data, init libraries), `onBeforeUpdate`, `onUpdated`, `onBeforeUnmount`, `onUnmounted` (cleanup), plus `onErrorCaptured`, `onActivated`/`onDeactivated` (KeepAlive), `onServerPrefetch` (SSR), and debug hooks `onRenderTracked`/`onRenderTriggered`. Options API equivalents use `beforeUnmount`/`unmounted` instead of Vue 2's `beforeDestroy`/`destroyed`.

## [Intermediate|High] What are slots and scoped slots?

Slots let a parent pass template content into a child component's placeholders: the default slot, named slots (`<slot name="footer">` filled with `<template #footer>`), and fallback content. Scoped slots let the child pass data back to the slot content (`<slot :item="item">` used as `<template #default="{ item }">`) — e.g. a generic table component where the parent customises how each row renders.

## [Intermediate|High] What is Pinia and how does it compare to Vuex?

Pinia is Vue's official state management library. Stores are defined with `defineStore` (state, getters, actions, or setup syntax with refs/computeds/functions). Compared with Vuex: no mutations (actions modify state directly, sync or async), no nested modules — just multiple independent stores, full TypeScript support without boilerplate, smaller size, DevTools integration and SSR support. Vuex is in maintenance mode.

## [Intermediate|Medium] What is provide/inject?

A dependency-injection mechanism: an ancestor `provide`s a value under a key and any descendant, at any depth, can `inject` it — avoiding prop drilling for things like theme, configuration or a form context. Provide refs (often `readonly`) to keep it reactive. It's not a replacement for global state management (Pinia).

## [Intermediate|Medium] How do navigation guards work in Vue Router?

Guards run during navigation and can allow, cancel (`return false`) or redirect (return a route location). Global guards: `router.beforeEach` (auth checks), `beforeResolve`, `afterEach` (analytics). Per-route: `beforeEnter`. In-component: `onBeforeRouteLeave` (unsaved changes) and `onBeforeRouteUpdate` (same component, new params). Route `meta` fields (e.g. `requiresAuth`) drive guard logic.

## [Advanced|High] What are composables and how do they differ from mixins?

Composables are functions (`useXxx`) that use Composition API primitives to encapsulate and reuse stateful logic, returning refs and functions. Unlike mixins, they make the source of each property explicit (via destructuring), avoid naming collisions, can accept arguments, can be composed together, and are fully typed. Mixins merged options implicitly, causing unclear origins and conflicts.

## [Advanced|Medium] What is nextTick and when do you need it?

Vue batches DOM updates asynchronously: after changing state, the DOM isn't updated immediately but in the next "tick" (microtask). `await nextTick()` waits until the DOM reflects the latest state — e.g. to measure an element's size or focus an input that was just rendered with `v-if`.

## [Advanced|Medium] How does Vue's compiler optimise rendering?

The template compiler analyses templates at build time: it hoists static nodes (created once), adds patch flags to dynamic nodes (so diffing only checks what can change, like text or class), and builds a block tree that tracks dynamic descendants, avoiding a full virtual DOM tree walk. Vapor Mode (in development for 3.6) goes further, compiling templates to direct DOM operations without a virtual DOM.

## [Scenario|High] A page with a list of 20,000 items is slow to render and scroll. How do you fix it?

Render only what's visible with virtual scrolling (vue-virtual-scroller/TanStack Virtual); paginate or load incrementally from the API; use stable `:key`s; store the large list with `shallowRef` (or `markRaw` items) so Vue doesn't make every nested property reactive; move filtering/sorting into computed properties; avoid heavy components per row; use `v-memo` for rows that rarely change.

## [Scenario|High] You destructure props or a reactive store and the UI stops updating. Why?

Destructuring copies the current values out of the reactive Proxy, breaking the connection. Fix: use `toRefs(reactiveObj)` or `storeToRefs(store)` for Pinia state/getters (actions can be destructured directly), access via `props.x`, or rely on Vue 3.5's compiler-supported reactive props destructure inside `<script setup>`, which keeps destructured props reactive in templates and computeds.

## [Scenario|Medium] Your company has a large Vue 2 app. Vue 2 reached EOL in December 2023. What's your plan?

Assess dependencies (Vuex, Vue Router 3, UI libraries like Vuetify 2/Element UI, plugins) and test coverage. Short term: upgrade to Vue 2.7 (Composition API) and consider extended commercial support for security. Then use the `@vue/compat` migration build on Vue 3 to fix deprecations incrementally; migrate Vue Router 3 → 4, Vuex → Pinia (store by store), Vue CLI → Vite, and UI libraries to Vue 3 versions (often the biggest effort); remove filters, the event bus and `$listeners`; add Playwright tests for critical flows before and during the migration; ship in stages.

## [Scenario|Medium] A watcher calling an API fires too often while the user types. How do you control it?

Debounce the watcher's work (`useDebounceFn` from VueUse or a debounce wrapper), add `v-model.lazy` if updating on change is enough, ignore short queries, cancel the previous request with `AbortController` via `onWatcherCleanup` (Vue 3.5) or the `onCleanup` argument so stale responses can't overwrite newer ones, and cache results.
