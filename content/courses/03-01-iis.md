# Overview

**IIS (Internet Information Services)** is Microsoft's web server built into Windows and Windows Server. It hosts websites, ASP.NET Framework applications (Web Forms, MVC 5, Web API 2, WCF), ASP.NET Core apps (via the ASP.NET Core Module), static sites, PHP/Node (via modules) and acts as a reverse proxy.

| Concept | Meaning |
|---|---|
| **Site** | A website with one or more **bindings** (protocol + IP + port + host name) and a physical path |
| **Application** | A sub-path of a site with its own application pool (e.g. `/api`) |
| **Virtual directory** | A URL path mapped to another physical folder |
| **Application pool** | A group of apps served by the same **worker process** (`w3wp.exe`) — isolation boundary |
| **Bindings** | `http *:80 www.shop.com`, `https *:443 www.shop.com` + certificate |
| **Modules / handlers** | Pipeline components (authentication, compression, rewrite) and request processors (static files, ASP.NET, ASP.NET Core Module) |

# Lifecycle

**How IIS processes a request:**

1. **HTTP.sys** (kernel-mode driver) receives the request on port 80/443, decrypts TLS (or the worker does), and checks its **kernel-mode cache** — cached static responses return immediately without user mode.
2. HTTP.sys routes the request to the **request queue** of the right application pool (based on the site binding and URL).
3. **WAS** (Windows Process Activation Service) and **W3SVC** manage configuration and start a **worker process (`w3wp.exe`)** for the pool if none is running (on-demand start).
4. The worker process runs the **IIS integrated pipeline**: native and managed **modules** handle events in order — BeginRequest → Authenticate → Authorize → ResolveCache → MapHandler → AcquireState → **ExecuteHandler** → ReleaseState → UpdateCache → Log → EndRequest.
5. The **handler** chosen by path/extension produces the response: StaticFileModule (files), ASP.NET (`System.Web` for .aspx/MVC 5), or **AspNetCoreModuleV2** (ASP.NET Core).
6. The response goes back through HTTP.sys to the client; the request is logged (W3C log).

**App pool lifecycle:** started on first request (or always running) → serves requests → idle timeout (20 min default) shuts it down → **recycled** periodically (1,740 minutes default = 29 h), on config changes, memory limits or crashes (rapid-fail protection stops the pool after repeated crashes).

# Module: IIS Architecture

## Lesson: [Basic|High] Installing IIS and its core components

```powershell
# Windows Server
Install-WindowsFeature -Name Web-Server, Web-Asp-Net45, Web-Windows-Auth, Web-Http-Redirect, Web-Dyn-Compression -IncludeManagementTools
# Windows 10/11
Enable-WindowsOptionalFeature -Online -FeatureName IIS-WebServerRole, IIS-ASPNET45, IIS-ManagementConsole -All
```

| Component | Mode | Role |
|---|---|---|
| **HTTP.sys** | Kernel | Listens on ports, request queues per app pool, kernel caching, TLS (with SChannel) |
| **WAS** | User (service) | Reads configuration, manages app pools and worker process lifetime |
| **W3SVC** | User (service) | Adapter between HTTP.sys and WAS for HTTP |
| **w3wp.exe** | User (process) | Worker process: runs the pipeline, modules and your application |
| `applicationHost.config` | File | Server-wide configuration (sites, pools, bindings, global modules) |

Default site: "Default Web Site" bound to `*:80`, physical path `C:\inetpub\wwwroot`.

## Lesson: [Basic|High] Sites, bindings, applications and virtual directories

```powershell
Import-Module WebAdministration

New-Item -ItemType Directory C:\sites\shop -Force
New-WebAppPool -Name "ShopPool"
New-Website -Name "Shop" -PhysicalPath "C:\sites\shop" -ApplicationPool "ShopPool" -Port 80 -HostHeader "www.shop.com"
New-WebBinding -Name "Shop" -Protocol https -Port 443 -HostHeader "www.shop.com" -SslFlags 1      # 1 = SNI
New-WebApplication -Site "Shop" -Name "api" -PhysicalPath "C:\sites\shop-api" -ApplicationPool "ShopApiPool"
New-WebVirtualDirectory -Site "Shop" -Name "downloads" -PhysicalPath "D:\shared\downloads"
```

- **Binding** = protocol + IP (or `*`) + port + host header. Several sites can share port 80/443 if host names differ.
- **SNI** (Server Name Indication) lets many HTTPS sites with different certificates share one IP:443.
- An **application** under a site (`/api`) can run in a different app pool and has its own `web.config` root for ASP.NET.
- A **virtual directory** only maps a URL to a folder (no separate app/pool).
- `hosts` file (`C:\Windows\System32\drivers\etc\hosts`) can map `www.shop.com` to `127.0.0.1` for local testing.

## Lesson: [Intermediate|High] Application pools — identity, pipeline mode, recycling and isolation

| Setting | Options / default | Notes |
|---|---|---|
| .NET CLR version | v4.0 / v2.0 / **No Managed Code** | ASP.NET Framework 4.x → v4.0; **ASP.NET Core → No Managed Code** |
| Managed pipeline mode | **Integrated** / Classic | Integrated = ASP.NET modules in the IIS pipeline (use this); Classic = legacy ISAPI style |
| Identity | **ApplicationPoolIdentity** / NetworkService / LocalSystem / custom account | ApplicationPoolIdentity = virtual account `IIS AppPool\ShopPool` — grant folder permissions to it |
| Enable 32-bit applications | False | True only for old 32-bit native dependencies |
| Start mode | OnDemand / **AlwaysRunning** | AlwaysRunning + Application Initialization removes the first-request delay |
| Idle timeout | 20 minutes | Set 0 for always-warm apps |
| Regular recycling | 1,740 minutes | Schedule at a quiet time or disable if not needed |
| Rapid-fail protection | 5 failures in 5 minutes | Pool stops → **503 Service Unavailable** |
| Maximum worker processes | 1 | >1 = "web garden" (in-process session/cache not shared) |

```powershell
Set-ItemProperty IIS:\AppPools\ShopPool -Name managedRuntimeVersion -Value ""          # No Managed Code (ASP.NET Core)
Set-ItemProperty IIS:\AppPools\ShopPool -Name startMode -Value AlwaysRunning
Set-ItemProperty IIS:\AppPools\ShopPool -Name processModel.idleTimeout -Value "00:00:00"
icacls C:\sites\shop /grant "IIS AppPool\ShopPool:(OI)(CI)RX"                            # read & execute for the pool identity
icacls C:\sites\shop\logs /grant "IIS AppPool\ShopPool:(OI)(CI)M"                        # modify for log folder
Restart-WebAppPool -Name ShopPool
```

**Recycling** starts a new worker process and drains the old one (overlapped recycle) — in-memory state (InProc session, caches, static variables) is lost. That's why web farms and recycles need out-of-process session (SQL/Redis).

**Database access with ApplicationPoolIdentity:** with Windows authentication to SQL Server on the same machine, create a login for `IIS AppPool\ShopPool`; for a remote SQL Server, the machine account (`DOMAIN\WEBSERVER$`) is used — or run the pool as a domain service account / use SQL authentication.

# Module: Hosting .NET Applications

## Lesson: [Intermediate|High] Hosting ASP.NET Framework apps (Web Forms, MVC 5, Web API 2)

1. Install IIS with **ASP.NET 4.x** (`Web-Asp-Net45`) — .NET Framework 4.8 is part of Windows Server.
2. App pool: **.NET CLR v4.0, Integrated pipeline**.
3. Publish from Visual Studio (Folder or Web Deploy profile) with **Release** configuration — `Web.Release.config` transforms apply (connection strings, `compilation debug="false"`, `customErrors On`).
4. Copy to the site folder; `bin\` contains your DLLs; `web.config` at the root.
5. Grant the pool identity read access; write access only to folders that need it (uploads, `App_Data`, logs).

```xml
<!-- web.config essentials for production -->
<system.web>
  <compilation debug="false" targetFramework="4.8" />
  <customErrors mode="RemoteOnly" defaultRedirect="~/Error" />
  <httpRuntime targetFramework="4.8" enableVersionHeader="false" maxRequestLength="10240" />
  <sessionState mode="SQLServer" sqlConnectionString="..." />          <!-- web farm -->
</system.web>
<system.webServer>
  <httpErrors errorMode="DetailedLocalOnly" />
  <security><requestFiltering removeServerHeader="true"><requestLimits maxAllowedContentLength="10485760" /></requestFiltering></security>
  <staticContent><clientCache cacheControlMode="UseMaxAge" cacheControlMaxAge="7.00:00:00" /></staticContent>
</system.webServer>
```

`system.web` = ASP.NET settings; `system.webServer` = IIS settings (integrated mode). Changing `web.config` or `bin\` contents **restarts the application domain**.

## Lesson: [Intermediate|High] Hosting ASP.NET Core on IIS — in-process vs out-of-process

**Prerequisite:** install the **.NET Hosting Bundle** (runtime + ASP.NET Core Module V2) on the server, then restart IIS (`net stop was /y && net start w3svc`).

```text
In-process (default, fastest):   HTTP.sys → w3wp.exe [ ANCM → your app via IISHttpServer ]
Out-of-process:                  HTTP.sys → w3wp.exe [ ANCM ] ──HTTP──▶ dotnet.exe/YourApp.exe [ Kestrel ]
```

```xml
<!-- web.config generated by dotnet publish -->
<configuration>
  <location path="." inheritInChildApplications="false">
    <system.webServer>
      <handlers>
        <add name="aspNetCore" path="*" verb="*" modules="AspNetCoreModuleV2" resourceType="Unspecified" />
      </handlers>
      <aspNetCore processPath="dotnet" arguments=".\Shop.Web.dll" stdoutLogEnabled="false" stdoutLogFile=".\logs\stdout"
                  hostingModel="inprocess">
        <environmentVariables>
          <environmentVariable name="ASPNETCORE_ENVIRONMENT" value="Production" />
        </environmentVariables>
      </aspNetCore>
    </system.webServer>
  </location>
</configuration>
```

Steps: `dotnet publish -c Release -o C:\sites\shop` → app pool **No Managed Code** → site pointing to the publish folder → bindings + certificate → permissions → browse. For **self-contained** publishes, `processPath` is `.\Shop.Web.exe`.

| | In-process | Out-of-process |
|---|---|---|
| Server | IIS HTTP server inside w3wp | Kestrel in a separate process |
| Performance | Higher (no extra hop) | Lower (loopback proxy) |
| Apps per pool | **One** ASP.NET Core app per app pool | Several possible |
| Use when | Default | Need Kestrel-specific features or multiple apps per pool |

**Zero-downtime-ish deploys:** drop an `app_offline.htm` file in the site folder (ANCM shuts the app down and serves that page), copy new files, delete the file. Web Deploy can do this automatically (`-enableRule:AppOffline`).

## Lesson: [Intermediate|High] HTTPS, certificates, authentication and security hardening

**HTTPS:** import the certificate (PFX) into `Local Machine\Personal` (or use the Centralized Certificate Store), add an `https` binding with SNI, redirect HTTP → HTTPS (URL Rewrite rule or app-level `UseHttpsRedirection`), enable HSTS. Free certificates: **win-acme** automates Let's Encrypt issuance and renewal for IIS.

```powershell
$cert = Import-PfxCertificate -FilePath C:\certs\shop.pfx -CertStoreLocation Cert:\LocalMachine\My -Password (Read-Host -AsSecureString)
New-WebBinding -Name Shop -Protocol https -Port 443 -HostHeader www.shop.com -SslFlags 1
(Get-WebBinding -Name Shop -Protocol https).AddSslCertificate($cert.Thumbprint, "My")
```

**Authentication options (IIS level):**

| Mode | Use |
|---|---|
| Anonymous | Public sites (app handles login with cookies/JWT) |
| **Windows Authentication** (Negotiate/Kerberos, NTLM) | Intranet apps with Active Directory — `[Authorize]` and `User.Identity.Name` = `DOMAIN\user` |
| Basic | Avoid (only over HTTPS, legacy) |
| Client certificate mapping | Machine-to-machine |

**Hardening checklist:** remove unused modules/handlers and the default site, least-privilege pool identities, disable directory browsing, remove `Server`/`X-Powered-By`/`X-AspNet-Version` headers, request filtering (limits, blocked extensions like `.config`), disable TLS 1.0/1.1 and weak ciphers (IIS Crypto tool), keep Windows patched, custom error pages, log retention, separate app pools per site.

## Lesson: [Intermediate|Medium] URL Rewrite, reverse proxy (ARR), compression and caching

```xml
<system.webServer>
  <rewrite>
    <rules>
      <!-- Force HTTPS -->
      <rule name="HTTPS redirect" stopProcessing="true">
        <match url="(.*)" />
        <conditions><add input="{HTTPS}" pattern="off" /></conditions>
        <action type="Redirect" url="https://{HTTP_HOST}/{R:1}" redirectType="Permanent" />
      </rule>
      <!-- SPA fallback: unknown paths → index.html (Angular/React hosted on IIS) -->
      <rule name="SPA fallback" stopProcessing="true">
        <match url=".*" />
        <conditions logicalGrouping="MatchAll">
          <add input="{REQUEST_FILENAME}" matchType="IsFile" negate="true" />
          <add input="{REQUEST_FILENAME}" matchType="IsDirectory" negate="true" />
          <add input="{REQUEST_URI}" pattern="^/api/" negate="true" />
        </conditions>
        <action type="Rewrite" url="/index.html" />
      </rule>
      <!-- Reverse proxy /node/* to a Node.js or Next.js app on port 3000 (requires ARR with proxy enabled) -->
      <rule name="Proxy to Node" stopProcessing="true">
        <match url="^node/(.*)" />
        <action type="Rewrite" url="http://localhost:3000/{R:1}" />
      </rule>
    </rules>
  </rewrite>
  <urlCompression doStaticCompression="true" doDynamicCompression="true" />
</system.webServer>
```

- **Redirect** (301/302 — browser goes to a new URL) vs **Rewrite** (server serves different content, URL unchanged).
- **ARR (Application Request Routing):** reverse proxy and load balancer — server farms with health tests, sticky sessions; lets IIS front Node.js, Next.js, Kestrel or other servers.
- **Output caching / kernel caching** for static and cacheable responses; `clientCache` sets `Cache-Control` for static files; static and dynamic compression (gzip; Brotli via the IIS Compression module).

# Module: Operations

## Lesson: [Intermediate|High] Logging, Failed Request Tracing and troubleshooting HTTP errors

**Where to look:**

1. **IIS logs** (`C:\inetpub\logs\LogFiles\W3SVC<siteId>\`) — every request with status, **sub-status** and Win32 status (`sc-status`, `sc-substatus`, `sc-win32-status`) and `time-taken`.
2. **Event Viewer → Windows Logs → Application/System** — app crashes, ASP.NET Core startup failures, WAS pool stops.
3. **Failed Request Tracing (FREB)** — enable on the site, add a rule (e.g. status 500 or time > 5 s) → detailed XML trace of every module step in `inetpub\logs\FailedReqLogFiles`.
4. ASP.NET Core **stdout log** (`stdoutLogEnabled="true"`, create the `logs` folder) and your app's own logs.
5. **Worker Processes** (IIS Manager) — currently executing requests per pool.

| Error | Meaning | Typical fix |
|---|---|---|
| 401.1 / 401.2 | Logon failed / auth method not enabled | Enable the right authentication mode; check credentials |
| 403.14 | Directory listing denied | Missing default document or app not deployed |
| 404.0 / 404.3 | Not found / MIME map missing | Wrong path; add `<mimeMap>` for e.g. `.json`, `.woff2`, `.webmanifest` |
| 404.13 | Request too large | Raise `maxAllowedContentLength` |
| 500.19 | Config error | Invalid/duplicated web.config section, missing module (URL Rewrite, ANCM), locked section |
| 500.21 | Handler not recognised | ASP.NET not installed or pool in Classic mode |
| **500.30** | ASP.NET Core app failed to start (in-process) | Startup exception — stdout log, Event Viewer, run `dotnet app.dll` manually |
| 500.31 / 500.32 | Runtime not found / bitness mismatch | Install the right .NET runtime/Hosting Bundle; 32/64-bit settings |
| **502.5** | Process failure (out-of-process) | Same as 500.30 |
| 502.3 | Bad gateway / timeout from backend | Long requests, ARR/ANCM timeout settings |
| **503** | Service unavailable | App pool stopped (rapid-fail, wrong identity password), queue full |

## Lesson: [Advanced|Medium] Web farms, deployment automation and performance tuning

**Web farm (multiple IIS servers):**

- Load balancer in front (hardware, Azure Load Balancer/Application Gateway, or ARR).
- Same code and config on every node — deploy with Web Deploy, Azure DevOps or **IIS Shared Configuration** + DFS-replicated content.
- **Machine key** (ASP.NET Framework: `<machineKey>` for ViewState/Forms auth) or **Data Protection keys** (ASP.NET Core: shared folder/Redis/Blob) must be identical across nodes.
- Session out-of-process (SQL Server/Redis) or sticky sessions.

**Deployment automation:**

```powershell
# Web Deploy (msdeploy) from a build agent
msdeploy.exe -verb:sync -source:contentPath="C:\build\publish" -dest:contentPath="Shop",computerName="https://web01:8172/msdeploy.axd",userName="deploy",password="***",authType="Basic" -enableRule:AppOffline -allowUntrusted
```

Azure DevOps: deployment group/agent on the server + "IIS Web App Manage" and "IIS Web App Deploy" tasks; GitHub Actions: self-hosted runner + PowerShell.

**Performance tuning:** AlwaysRunning + Application Initialization (warm-up), disable idle timeout for busy apps, schedule recycling at off-peak times, enable compression and static caching, HTTP/2 (and HTTP/3 on Server 2022+), check queue length and `Requests/Sec` counters, avoid web gardens for stateful apps, use async code to avoid thread-pool starvation, keep `debug="false"`.

# Interview

## [Beginner|High] What is IIS and what can it host?

Microsoft's Windows web server. It hosts static sites, ASP.NET Framework apps (Web Forms, MVC 5, Web API 2, WCF), ASP.NET Core apps via the ASP.NET Core Module, and through modules/ARR can proxy to Node.js, Next.js or other servers. It provides bindings, HTTPS, authentication (including Windows auth), compression, caching, URL rewriting and logging.

## [Beginner|High] What is an application pool and why is it used?

A group of one or more applications served by the same worker process (`w3wp.exe`) with shared settings: .NET CLR version, pipeline mode, identity, recycling and limits. Pools isolate applications — a crash, memory leak or recycle in one pool doesn't affect apps in other pools — and define the security identity the app runs as.

## [Beginner|High] What is w3wp.exe?

The IIS worker process. Each application pool runs in its own w3wp.exe (or several in a web garden); it hosts the IIS pipeline, modules and your application code (including in-process ASP.NET Core apps). You attach the Visual Studio debugger to w3wp.exe to debug IIS-hosted apps and see it in Task Manager with the pool identity as the user.

## [Beginner|High] How do you deploy an ASP.NET Core app to IIS?

Install the .NET Hosting Bundle on the server, `dotnet publish -c Release`, create an app pool with "No Managed Code", create a site pointing to the publish folder with bindings and a certificate, grant the pool identity read permissions (write for logs/uploads), set environment variables (ASPNETCORE_ENVIRONMENT, connection strings) and browse. The published web.config configures the ASP.NET Core Module (in-process by default).

## [Beginner|Medium] What is the difference between a site, an application and a virtual directory?

A site is the top-level website with bindings and a root folder. An application is a sub-path that is its own ASP.NET application (own web.config root, can use a different app pool). A virtual directory just maps a URL path to a physical folder inside an application without being a separate app.

## [Intermediate|High] In-process vs out-of-process hosting for ASP.NET Core in IIS?

In-process runs the app inside the IIS worker process using IIS's HTTP server — no extra network hop, best performance, but only one ASP.NET Core app per pool. Out-of-process runs the app as a separate Kestrel process with IIS (ANCM) forwarding requests over loopback — slower, but multiple apps per pool and Kestrel-specific features. Configured with `hostingModel` in web.config / `AspNetCoreHostingModel` in the project.

## [Intermediate|High] What is app pool recycling and what are its effects?

IIS periodically (default every 29 hours), on configuration changes, memory/request limits or on demand starts a new worker process and shuts down the old one. It frees leaked memory and refreshes the app, but in-memory state is lost (InProc session, MemoryCache, static data) and the first request after startup may be slow. Schedule recycles off-peak, use out-of-process state and warm-up (Application Initialization).

## [Intermediate|High] What is ApplicationPoolIdentity and how do you give it permissions?

A per-pool virtual account (`IIS AppPool\<PoolName>`) created automatically, with minimal privileges. Grant it NTFS rights on the site folders (`icacls ... /grant "IIS AppPool\ShopPool":RX`), and for SQL Server with Windows authentication create a login for it locally or for the computer account (`DOMAIN\SERVER$`) when SQL is remote — or use a dedicated domain service account.

## [Intermediate|High] How do you troubleshoot a 500.30 / 502.5 error with ASP.NET Core on IIS?

The app failed to start. Check Event Viewer (Application log) for the ANCM and app exceptions, enable `stdoutLogEnabled` with a writable logs folder, run `dotnet YourApp.dll` from the publish folder on the server to see errors, verify the Hosting Bundle/runtime version and bitness, the app pool "No Managed Code", file permissions, environment-specific configuration (missing connection string, Key Vault access) and database connectivity at startup.

## [Intermediate|Medium] What does HTTP.sys do?

A kernel-mode HTTP listener used by IIS (and optionally ASP.NET Core directly). It accepts connections, parses requests, handles TLS with SChannel, maintains a request queue per application pool, serves cached responses from kernel mode and enforces limits — keeping IIS robust because requests queue in the kernel even while a worker process restarts.

## [Intermediate|Medium] URL Rewrite vs Redirect? How do you host an Angular/React SPA on IIS?

A redirect tells the browser to request a different URL (301/302, address bar changes); a rewrite serves a different resource internally with the URL unchanged. For SPAs, add a rewrite rule that sends every request that isn't an existing file, folder or `/api/` path to `/index.html`, so deep links work on refresh; add MIME types if needed and cache static assets.

## [Advanced|Medium] How do you set up a web farm with IIS?

Multiple IIS servers behind a load balancer with health checks; identical code and config deployed by automation or shared configuration; shared machine key / Data Protection keys so cookies and ViewState validate on any node; out-of-process session (SQL Server/Redis) or sticky sessions; centralised logging; shared or replicated file storage for uploads; rolling deployments one node at a time.

## [Advanced|Medium] What is a web garden and when should you avoid it?

An application pool with more than one worker process. It can help apps limited by per-process locks, but in-process state (session, cache, static variables) isn't shared between the processes, causing inconsistent behaviour. Most apps should use one worker per pool and scale out across servers instead.

## [Scenario|High] After deployment the site returns 503 Service Unavailable. What do you check?

The application pool is likely stopped: open IIS Manager → Application Pools; check Event Viewer System log for WAS errors — rapid-fail protection after repeated crashes, wrong or expired password for a custom identity, missing .NET version, or a crash at startup. Fix the cause and start the pool. Also check the request queue limit and that the binding/host name is correct.

## [Scenario|High] An intranet ASP.NET app on IIS must use Windows login and query SQL Server as the user. How do you configure it?

Enable Windows Authentication (disable Anonymous) on the site, `[Authorize]` in the app, and either connect to SQL Server with the app pool identity (simplest — grant that account the needed DB permissions and use `User.Identity.Name` for auditing) or, if SQL must see the end user, configure Kerberos constrained delegation (SPNs for the service account, delegation to the SQL service) and impersonation — more complex, so usually avoided.

## [Scenario|Medium] The first request every morning takes 30 seconds. How do you fix it?

The app pool shuts down after the idle timeout (20 min) or recycled overnight, so the first request starts the worker, JITs code and warms caches. Set the pool's Start Mode to AlwaysRunning, idle timeout to 0, enable Application Initialization with `preloadEnabled` on the site (and a warm-up URL), schedule recycling during low traffic, and consider ReadyToRun publishing to reduce JIT time.

# Cheatsheet

## Request path

HTTP.sys (kernel, queue, cache, TLS) → WAS/W3SVC → w3wp.exe (app pool) → integrated pipeline modules → handler (static / ASP.NET / AspNetCoreModuleV2) → logging → response.

## App pool settings

CLR v4.0 (Framework) / No Managed Code (Core) · Integrated pipeline · ApplicationPoolIdentity · AlwaysRunning + idle 0 for warm apps · recycle off-peak · rapid-fail → 503.

## ASP.NET Core on IIS

Hosting Bundle · `dotnet publish` · web.config `aspNetCore` (inprocess) · stdout log for 500.30 · `app_offline.htm` for deploys · one in-process app per pool.

## Config & features

applicationHost.config (server) · web.config (site/app) · bindings + SNI certificates · Windows auth for intranet · URL Rewrite (HTTPS, SPA fallback) · ARR reverse proxy/farms · compression · FREB tracing.

## Error codes

401 auth · 403.14 no default doc · 404.3 MIME · 500.19 config · 500.21 handler · 500.30/502.5 Core startup · 502.3 backend timeout · 503 pool stopped.
