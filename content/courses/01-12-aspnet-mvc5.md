# Overview

**ASP.NET MVC** (2009) brought the **Model–View–Controller** pattern to ASP.NET on .NET Framework as an alternative to Web Forms: no ViewState, no page life cycle, full control of HTML, clean URLs and testable controllers. **MVC 5** (2013) is the final version; its successor is **ASP.NET Core MVC**.

| Part | Responsibility | Example |
|---|---|---|
| **Model** | Data and business rules (entities, view models, validation) | `Product`, `ProductViewModel` |
| **View** | Presentation — Razor templates producing HTML | `Views/Products/Index.cshtml` |
| **Controller** | Handles the request, calls services, chooses the view/result | `ProductsController.Index()` |

| | Web Forms | MVC 5 | ASP.NET Core MVC |
|---|---|---|---|
| Model | Event-driven pages, ViewState | Request → controller action → view | Same as MVC 5, rebuilt |
| HTML control | Generated by controls | Full | Full |
| Testability | Poor | Good | Very good (built-in DI) |
| Platform | .NET Framework, IIS | .NET Framework, IIS (System.Web) | Cross-platform, Kestrel |
| DI | Third-party | Third-party (Unity, Autofac, Ninject) | Built in |

# Lifecycle

**The MVC 5 request life cycle (inside IIS + System.Web):**

```text
1. Browser → IIS → ASP.NET pipeline (HttpApplication events, Global.asax)
2. UrlRoutingModule (PostResolveRequestCache) matches the URL against RouteTable.Routes
3. Matched route → MvcRouteHandler → creates MvcHandler (an IHttpHandler)
4. MvcHandler.ProcessRequest → ControllerBuilder → IControllerFactory (DefaultControllerFactory or your DI factory)
      creates the controller, e.g. ProductsController
5. Controller.Execute → ControllerActionInvoker:
      a. finds the action method (name + HTTP verb + selectors)
      b. Authentication filters → Authorization filters ([Authorize])
      c. Model binding: route values, query string, form → action parameters; validation → ModelState
      d. Action filters OnActionExecuting → ACTION METHOD runs → OnActionExecuted
      e. Action returns an ActionResult (ViewResult, JsonResult, RedirectResult …)
      f. Result filters OnResultExecuting → ActionResult.ExecuteResult → OnResultExecuted
6. ViewResult → ViewEngines (RazorViewEngine) locate the .cshtml → compiled into a class → rendered with layout/partials → HTML
7. Exception filters handle errors at any step ([HandleError]) → Application_Error as last resort
8. Response flows back through the remaining pipeline events (EndRequest) to the browser
```

# Module: Project Structure and Routing

## Lesson: [Basic|High] MVC 5 folder structure explained

```text
ShopMvc/                                  (ASP.NET Web Application, .NET Framework 4.8, MVC template)
├── App_Data/                             local database files, not web-accessible
├── App_Start/                            startup configuration called from Global.asax
│   ├── RouteConfig.cs                    conventional routes ("{controller}/{action}/{id}")
│   ├── FilterConfig.cs                   global filters (HandleErrorAttribute, AuthorizeAttribute)
│   ├── BundleConfig.cs                   CSS/JS bundles and minification
│   ├── IdentityConfig.cs, Startup.Auth.cs  ASP.NET Identity + OWIN cookie authentication
│   └── UnityConfig.cs                    dependency injection container (if added)
├── Areas/                                sub-applications, each with its own Controllers/Models/Views
│   └── Admin/  (AdminAreaRegistration.cs, Controllers/, Views/)
├── Content/                              CSS (bootstrap.css, Site.css), images
├── Controllers/                          HomeController.cs, ProductsController.cs, AccountController.cs
├── fonts/                                icon fonts
├── Models/                               entities, view models, DbContext (often moved to separate projects)
├── Scripts/                              jQuery, jquery.validate, bootstrap.js, your JS
├── Views/
│   ├── Shared/                           _Layout.cshtml, Error.cshtml, partials (_LoginPartial.cshtml), EditorTemplates/, DisplayTemplates/
│   ├── Home/                             Index.cshtml, About.cshtml (folder name = controller name)
│   ├── Products/                         Index.cshtml, Details.cshtml, Create.cshtml, Edit.cshtml
│   ├── _ViewStart.cshtml                 sets Layout for all views
│   └── web.config                        Razor config (namespaces for views) + blocks direct access to .cshtml
├── Global.asax / Global.asax.cs          Application_Start: AreaRegistration, FilterConfig, RouteConfig, BundleConfig
├── Startup.cs                            OWIN startup (Identity, SignalR)
├── packages.config                       NuGet packages
├── Web.config (+ Web.Debug/Release.config transforms)
└── ShopMvc.csproj
```

**Conventions:** a controller class ends with `Controller` and lives in `Controllers/`; its views are in `Views/<ControllerName>/<ActionName>.cshtml`; shared views in `Views/Shared`. Layered solutions usually add `Shop.Core` (domain), `Shop.Data` (EF/Dapper), `Shop.Services` projects referenced by the web project.

## Lesson: [Basic|High] Routing — conventional and attribute routes

```csharp
// App_Start/RouteConfig.cs
public static class RouteConfig
{
    public static void RegisterRoutes(RouteCollection routes)
    {
        routes.IgnoreRoute("{resource}.axd/{*pathInfo}");
        routes.MapMvcAttributeRoutes();                         // enable [Route] attributes (MVC 5)

        routes.MapRoute(
            name: "ProductBySlug",
            url: "products/{category}/{slug}",
            defaults: new { controller = "Products", action = "BySlug" });

        routes.MapRoute(
            name: "Default",
            url: "{controller}/{action}/{id}",
            defaults: new { controller = "Home", action = "Index", id = UrlParameter.Optional });
    }
}

// Attribute routing
[RoutePrefix("orders")]
public class OrdersController : Controller
{
    [Route("")] public ActionResult Index() => View();
    [Route("{id:int}")] public ActionResult Details(int id) => View(_orders.Get(id));
    [Route("customer/{customerId:int}/{year:int:min(2000)?}")] public ActionResult ByCustomer(int customerId, int? year) => View();
}
```

Routes are checked **in order** — put specific routes before the generic default. `Url.Action("Details", "Orders", new { id = 5 })` and `Html.ActionLink` generate URLs from routes, so URLs change in one place.

# Module: Controllers and Views

## Lesson: [Basic|High] Controllers, actions and action results

```csharp
public class ProductsController : Controller
{
    private readonly IProductService _products;
    public ProductsController(IProductService products) => _products = products;    // needs a DI container in MVC 5

    public ActionResult Index(string q, int page = 1) => View(_products.Search(q, page));

    public ActionResult Details(int id)
    {
        var p = _products.Get(id);
        if (p == null) return HttpNotFound();
        return View(p);
    }

    [HttpGet] public ActionResult Create() => View(new ProductEditModel());

    [HttpPost, ValidateAntiForgeryToken]
    public ActionResult Create(ProductEditModel model)
    {
        if (!ModelState.IsValid) return View(model);           // redisplay with validation messages
        _products.Add(model);
        TempData["Message"] = "Product created";
        return RedirectToAction(nameof(Index));                // Post-Redirect-Get pattern
    }

    public async Task<ActionResult> Export() => File(await _products.ExportCsvAsync(), "text/csv", "products.csv");
    public JsonResult Lookup(string term) => Json(_products.Lookup(term), JsonRequestBehavior.AllowGet);
}
```

| ActionResult | Helper | Purpose |
|---|---|---|
| `ViewResult` | `View()` | Render a view |
| `PartialViewResult` | `PartialView()` | Render a partial (AJAX) |
| `RedirectToRouteResult` | `RedirectToAction()` | Redirect to an action |
| `RedirectResult` | `Redirect(url)` | Redirect to a URL |
| `JsonResult` | `Json()` | JSON (GET needs `AllowGet`) |
| `ContentResult` | `Content()` | Plain text/HTML |
| `FileResult` | `File()` | Downloads |
| `HttpStatusCodeResult` / `HttpNotFoundResult` | `new HttpStatusCodeResult(400)` / `HttpNotFound()` | Status codes |
| `EmptyResult` | — | Nothing |

Action selectors: `[HttpGet]`, `[HttpPost]`, `[ActionName("Delete")]`, `[NonAction]` (public method that isn't an action), `[ChildActionOnly]`.

## Lesson: [Basic|High] Razor views, layouts, HTML helpers and partial views

```cshtml
@model ShopMvc.Models.ProductEditModel
@{
    ViewBag.Title = "Create product";
}
<h2>@ViewBag.Title</h2>

@using (Html.BeginForm("Create", "Products", FormMethod.Post))
{
    @Html.AntiForgeryToken()
    @Html.ValidationSummary(true, "", new { @class = "text-danger" })

    @Html.LabelFor(m => m.Name)
    @Html.TextBoxFor(m => m.Name, new { @class = "form-control" })
    @Html.ValidationMessageFor(m => m.Name)

    @Html.DropDownListFor(m => m.CategoryId, Model.Categories, "-- choose --")
    @Html.EditorFor(m => m.Price)

    <button type="submit" class="btn btn-primary">Save</button>
}

@Html.Partial("_ProductTips")                       @* partial view, uses current model unless passed *@
@Html.Action("TopSellers", "Products")               @* child action: runs a controller action and renders its result *@

@section scripts {
    @Scripts.Render("~/bundles/jqueryval")
}
```

```cshtml
@* Views/Shared/_Layout.cshtml *@
<!DOCTYPE html>
<html>
<head><title>@ViewBag.Title - Divakar Shop</title>@Styles.Render("~/Content/css")</head>
<body>
    @Html.Partial("_LoginPartial")
    <div class="container">@RenderBody()</div>
    @Scripts.Render("~/bundles/jquery")
    @RenderSection("scripts", required: false)
</body>
</html>
```

Razor basics: `@expression` (HTML-encoded automatically), `@{ code block }`, `@if/@foreach`, `@Html.Raw(x)` (no encoding — dangerous), `@* comment *@`, `@:` text line. Views are compiled into classes deriving from `WebViewPage<TModel>` the first time they are requested (or at build with `MvcBuildViews`).

**Partial view vs child action:** a partial renders a template with data you pass; a child action (`Html.Action`) runs a full controller action (with its own data access and filters) — useful for widgets like a cart summary on every page. (ASP.NET Core replaces child actions with view components.)

**Display/editor templates:** `Views/Shared/EditorTemplates/DateTime.cshtml` customises `Html.EditorFor` for every `DateTime` property.

## Lesson: [Intermediate|High] Passing data — ViewData, ViewBag, TempData, Session and strongly typed models

| Mechanism | Type | Lifetime | Typical use |
|---|---|---|---|
| **Strongly typed model** | `View(model)` + `@model` | One request | The main data — IntelliSense, compile-time checks (preferred) |
| ViewData | `ViewDataDictionary` (string keys) | Current request, controller → view | Small extras |
| ViewBag | `dynamic` wrapper over ViewData | Current request | Title, small extras (no compile-time checking) |
| **TempData** | Dictionary backed by Session (default) | Until read in a **subsequent** request | Messages after redirect (Post-Redirect-Get) |
| Session | `Session["key"]` | User session | Cart, wizard state |

`TempData.Keep("key")` keeps a value for another request; `TempData.Peek("key")` reads without marking it for deletion.

# Module: Model Binding, Validation and Filters

## Lesson: [Intermediate|High] Model binding and validation

The **DefaultModelBinder** fills action parameters and complex objects from **value providers**: form fields, route data, query string, posted files — matching by name (including nested `Address.City`, indexed `Lines[0].Qty`).

```csharp
public class ProductEditModel
{
    [Required, StringLength(200)]
    public string Name { get; set; }

    [Range(0.01, 1000000), DataType(DataType.Currency)]
    public decimal Price { get; set; }

    [Display(Name = "Category")]
    public int CategoryId { get; set; }

    [Remote("IsNameUnique", "Products", ErrorMessage = "Name already exists")]   // AJAX validation
    public string Code { get; set; }

    public IEnumerable<SelectListItem> Categories { get; set; }
}

// Custom validation attribute
public class FutureDateAttribute : ValidationAttribute
{
    public override bool IsValid(object value) => value is DateTime d && d > DateTime.Today;
}
```

- `ModelState.IsValid` after binding; add your own errors with `ModelState.AddModelError("Name", "...")`.
- **Unobtrusive client validation** (jquery.validate + jquery.validate.unobtrusive) uses `data-val-*` attributes generated from the annotations — client validation is a convenience; server checks are mandatory.
- `IValidatableObject` for cross-field rules; FluentValidation as an alternative library.
- **Over-posting/mass assignment:** bind to view models (or `[Bind(Include = "Name,Price")]`) — never bind directly to EF entities with sensitive fields like `IsAdmin`.

## Lesson: [Intermediate|High] Filters — authentication, authorization, action, result and exception

| Filter (MVC 5) | Interface | Runs | Built-in examples |
|---|---|---|---|
| Authentication | `IAuthenticationFilter` | First — establishes identity | Custom token checks |
| Authorization | `IAuthorizationFilter` | Before model binding/action | `[Authorize]`, `[AllowAnonymous]`, `[RequireHttps]`, `[ValidateAntiForgeryToken]`, `[ChildActionOnly]` |
| Action | `IActionFilter` | Before/after the action method | `[OutputCache]` (also result), custom logging/auditing |
| Result | `IResultFilter` | Before/after the result executes | Modify view data, timing |
| Exception | `IExceptionFilter` | When an unhandled exception occurs | `[HandleError]` |

```csharp
public class LogActionAttribute : ActionFilterAttribute
{
    public override void OnActionExecuting(ActionExecutingContext ctx)
        => Trace.WriteLine($"→ {ctx.ActionDescriptor.ControllerDescriptor.ControllerName}.{ctx.ActionDescriptor.ActionName}");
    public override void OnActionExecuted(ActionExecutedContext ctx)
        => Trace.WriteLine($"← done, exception: {ctx.Exception?.Message}");
}

// Registration levels: global (FilterConfig), controller, action
public class FilterConfig
{
    public static void RegisterGlobalFilters(GlobalFilterCollection filters)
    {
        filters.Add(new HandleErrorAttribute());          // shows Views/Shared/Error.cshtml when customErrors is On
        filters.Add(new AuthorizeAttribute());            // whole site requires login ([AllowAnonymous] to opt out)
        filters.Add(new LogActionAttribute());
    }
}
```

Order: authentication → authorization → (model binding) → action filters → action → action filters (after) → result filters → result → result filters (after); exception filters on errors. The `Order` property and scope (global → controller → action) control ordering.

# Module: Application Concerns

## Lesson: [Intermediate|High] Dependency injection, bundling, Identity and Web API 2 in MVC 5

**Dependency injection** — MVC 5 has no built-in container; plug one in through `DependencyResolver`:

```csharp
// Unity.Mvc5 — App_Start/UnityConfig.cs
public static void RegisterComponents()
{
    var container = new UnityContainer();
    container.RegisterType<ShopDbContext>(new PerRequestLifetimeManager());
    container.RegisterType<IProductService, ProductService>();
    DependencyResolver.SetResolver(new UnityDependencyResolver(container));
}
```

(Autofac: `builder.RegisterControllers(...)`, `DependencyResolver.SetResolver(new AutofacDependencyResolver(container))`.)

**Bundling and minification:**

```csharp
bundles.Add(new ScriptBundle("~/bundles/jquery").Include("~/Scripts/jquery-{version}.js"));
bundles.Add(new StyleBundle("~/Content/css").Include("~/Content/bootstrap.css", "~/Content/site.css"));
BundleTable.EnableOptimizations = true;   // or compilation debug="false" in web.config
```

**ASP.NET Identity + OWIN:** `Startup.Auth.cs` configures cookie authentication (`UseCookieAuthentication`), external logins (Google, Microsoft), `UserManager`/`SignInManager` with EF tables (`AspNetUsers`, `AspNetRoles`); `[Authorize(Roles = "Admin")]` protects actions.

**Web API 2** in the same project: `ApiController` classes under `/api/...`, configured in `WebApiConfig.Register` (`config.MapHttpAttributeRoutes()`), returning data with content negotiation (JSON/XML). MVC and Web API 2 have **separate** pipelines, filters and DI resolvers in .NET Framework — ASP.NET Core unifies them.

## Lesson: [Intermediate|High] Error handling, custom error pages and logging in MVC 5

Layers of error handling:

1. **try/catch** in actions/services for expected failures (show a validation message, return 404/409).
2. **Exception filters** — `[HandleError(ExceptionType = typeof(DbUpdateException), View = "DatabaseError")]` or a custom `IExceptionFilter` that logs and shows a view (only for exceptions inside MVC actions/results).
3. **Controller.OnException** override — per-controller handling.
4. **`Application_Error`** in Global.asax — catches everything else (routing errors, errors outside MVC), log and redirect.
5. **web.config** — `customErrors` (ASP.NET) and `httpErrors` (IIS) for friendly pages for 404/500.

```csharp
public class GlobalExceptionFilter : IExceptionFilter
{
    public void OnException(ExceptionContext ctx)
    {
        Log.Error(ctx.Exception, "Unhandled error in {Controller}", ctx.RouteData.Values["controller"]);
        if (ctx.HttpContext.Request.IsAjaxRequest())
        {
            ctx.Result = new JsonResult { Data = new { error = "Something went wrong" }, JsonRequestBehavior = JsonRequestBehavior.AllowGet };
            ctx.HttpContext.Response.StatusCode = 500;
        }
        else ctx.Result = new ViewResult { ViewName = "Error" };
        ctx.ExceptionHandled = true;
        ctx.HttpContext.Response.TrySkipIisCustomErrors = true;
    }
}
```

```xml
<system.web>
  <customErrors mode="On" defaultRedirect="~/Error">
    <error statusCode="404" redirect="~/Error/NotFound" />
  </customErrors>
</system.web>
<system.webServer>
  <httpErrors errorMode="Custom" existingResponse="Replace">
    <remove statusCode="404" /><error statusCode="404" path="/Error/NotFound" responseMode="ExecuteURL" />
  </httpErrors>
</system.webServer>
```

## Lesson: [Advanced|High] MVC 5 vs ASP.NET Core MVC and migration

| Topic | MVC 5 (.NET Framework) | ASP.NET Core MVC |
|---|---|---|
| Hosting | IIS only (System.Web) | Kestrel, IIS, Linux, containers |
| Startup | Global.asax + App_Start + web.config | `Program.cs` (WebApplication builder) + `appsettings.json` |
| Pipeline | HttpModules/HttpHandlers | Middleware |
| DI | Third-party via DependencyResolver | Built in |
| MVC + Web API | Separate frameworks | One framework (`ControllerBase`) |
| Child actions | `Html.Action` | View components |
| Helpers | HTML helpers | Tag helpers (+ HTML helpers) |
| Bundling | System.Web.Optimization | Static files + build tools (Vite/Webpack/LibMan) or WebOptimizer |
| Config | `ConfigurationManager.AppSettings` | `IConfiguration`, Options pattern |
| Auth | OWIN/Identity 2, Forms auth | ASP.NET Core Identity, cookie/JWT handlers |
| Static files | Served by IIS | `UseStaticFiles()` from `wwwroot` |

**Migration path:** move business/data logic into libraries; create a new ASP.NET Core project; port controllers (mostly the same code), views (mostly the same Razor, replace child actions and bundling), filters (similar interfaces), configuration and DI; use the **.NET Upgrade Assistant** and **System.Web adapters**; for big apps migrate incrementally behind **YARP** (route migrated paths to the new app, the rest to the old app, share authentication).

# Interview

## [Beginner|High] What is MVC? Explain Model, View and Controller.

An architectural pattern separating concerns: the Model holds data and business rules, the View renders the UI (Razor templates), and the Controller receives requests, works with the model/services and chooses the response. Benefits: testable controllers, clean URLs, full HTML control, parallel work on UI and logic.

## [Beginner|High] Explain the ASP.NET MVC 5 request life cycle.

Request → IIS/ASP.NET pipeline → UrlRoutingModule matches a route → MvcRouteHandler → MvcHandler → controller factory creates the controller → ControllerActionInvoker selects the action → authentication and authorization filters → model binding and validation → action filters (before) → action executes and returns an ActionResult → action filters (after) → result filters → result executes (ViewResult → Razor view engine finds and renders the view) → response. Exception filters handle errors along the way.

## [Beginner|High] Describe the MVC 5 folder structure.

`Controllers` (classes ending in Controller), `Models`, `Views/<Controller>/<Action>.cshtml` with `Views/Shared` for layouts/partials and `_ViewStart.cshtml`, `App_Start` (RouteConfig, FilterConfig, BundleConfig, IdentityConfig), `Areas` for modules with their own MVC folders, `Content` (CSS), `Scripts` (JS), `App_Data`, `Global.asax` for startup, `Web.config` (plus `Views/web.config` for Razor settings).

## [Beginner|High] ViewData vs ViewBag vs TempData?

ViewData is a string-keyed dictionary and ViewBag a dynamic wrapper over the same data — both live only for the current request (controller → view). TempData survives until it is read in a subsequent request (stored in session by default), so it's used for messages after a redirect; `Keep`/`Peek` retain it longer. Prefer strongly typed view models for real data.

## [Beginner|High] What types of ActionResult are there?

ViewResult (`View`), PartialViewResult, RedirectResult/RedirectToRouteResult (`Redirect`, `RedirectToAction`), JsonResult, ContentResult, FileResult (`File`), JavaScriptResult, HttpStatusCodeResult/HttpNotFoundResult, EmptyResult. Actions can also return plain types, which are converted to ContentResult.

## [Intermediate|High] What are filters in MVC? Name the types and their order.

Attributes/classes that run logic before or after stages of action execution: authentication filters, authorization filters (`[Authorize]`), action filters (`OnActionExecuting/Executed`), result filters (`OnResultExecuting/Executed`) and exception filters (`[HandleError]`). Order: authentication → authorization → action → result, with exception filters on errors; they can be applied globally, per controller or per action.

## [Intermediate|High] Conventional routing vs attribute routing?

Conventional routes are defined centrally (`MapRoute("{controller}/{action}/{id}")`) and matched in order. Attribute routing (MVC 5, `routes.MapMvcAttributeRoutes()`) puts `[Route]`/`[RoutePrefix]` on controllers/actions — clearer for REST-style or custom URLs, with inline constraints (`{id:int}`). Both can be combined; attribute routes are usually registered first.

## [Intermediate|High] How does model binding and validation work?

The DefaultModelBinder uses value providers (form, route, query string, files) to fill action parameters by name, including complex and nested objects and collections. Data annotations and `IValidatableObject` validate the model; errors go into `ModelState`, checked with `ModelState.IsValid`. Unobtrusive jQuery validation mirrors the rules on the client. Use view models to avoid over-posting.

## [Intermediate|High] Partial view vs child action (vs view component in Core)?

A partial view is a reusable template rendered with data you pass (`Html.Partial`). A child action (`Html.Action`) invokes a controller action that loads its own data and returns a partial — for self-contained widgets. ASP.NET Core removed child actions in favour of view components, which are lighter (no full action pipeline).

## [Intermediate|Medium] How do you implement dependency injection in MVC 5?

Use a container (Unity, Autofac, Ninject, Simple Injector), register services with lifetimes (per-request for DbContext), and set it as the MVC `DependencyResolver` (and a separate resolver for Web API 2). The controller factory then constructs controllers with their dependencies through constructor injection.

## [Intermediate|Medium] What is the Post-Redirect-Get pattern and why use it?

After a successful POST, redirect (302) to a GET action instead of returning a view. It prevents duplicate submissions when the user refreshes, gives a clean URL, and pairs with TempData for success messages.

## [Intermediate|Medium] How do you prevent CSRF and XSS in MVC 5?

CSRF: `@Html.AntiForgeryToken()` in forms and `[ValidateAntiForgeryToken]` on POST actions (plus SameSite cookies). XSS: Razor encodes `@` output by default — avoid `Html.Raw` on user input, validate input, use Content Security Policy. Also `[Authorize]`, HTTPS, parameterised queries, and view models against over-posting.

## [Advanced|Medium] How do you handle errors globally in MVC 5?

Register a global exception filter (`HandleErrorAttribute` or a custom `IExceptionFilter`) for errors inside controllers/views, override `OnException` where needed, use `Application_Error` in Global.asax for everything else (including 404s from routing), log with a logging framework, and configure `customErrors`/`httpErrors` for friendly error pages with correct status codes.

## [Advanced|Medium] What are Areas and when do you use them?

Areas divide a large MVC application into functional sections (Admin, Billing, Reports), each with its own Controllers, Models and Views and route registration (`AreaRegistration`). They keep large projects organised and allow same-named controllers in different areas. In ASP.NET Core they work similarly with `[Area("Admin")]`.

## [Scenario|High] You must migrate a large MVC 5 app to ASP.NET Core without stopping feature work. How?

Incremental migration: create an ASP.NET Core app in front with YARP proxying unmigrated routes to the MVC 5 app; share authentication (shared cookie/data protection or a common identity provider) and session via System.Web adapters; move shared logic into netstandard libraries; migrate controller by controller (largely copy with small changes), replace child actions with view components, bundling with a build tool, `HttpContext.Current` usages with injected services; delete old routes as they move.

## [Scenario|Medium] An action returns stale data because of `[OutputCache]`. How do you fix it while keeping performance?

Review the cache key: vary by the right parameters (`VaryByParam`, `VaryByCustom` for user/culture), shorten the duration, use `Location = Client`/`None` for per-user data, or move to data caching in the service layer with explicit invalidation when data changes (remove the cache entry on update). Never cache personalised pages server-side without varying by user.

# Cheatsheet

## Request life cycle

UrlRoutingModule → MvcRouteHandler → MvcHandler → ControllerFactory → ActionInvoker → authN/authZ filters → model binding → action filters → action → result filters → ActionResult.ExecuteResult → view engine → response.

## Folders

App_Start (Route/Filter/Bundle/Identity config) · Controllers · Models · Views (+Shared, _ViewStart, web.config) · Areas · Content · Scripts · Global.asax · Web.config.

## Data to views

Strongly typed model > ViewData/ViewBag (this request) · TempData (next request) · Session (user).

## Filters

Authentication → Authorization → Action → Result · Exception · global/controller/action scope.

## MVC 5 → Core

Global.asax → Program.cs · modules → middleware · child actions → view components · HTML helpers → tag helpers · DependencyResolver → built-in DI · separate Web API → unified controllers.
