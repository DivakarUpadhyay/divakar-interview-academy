# Overview

**Object-Oriented Programming (OOP)** organises code around **objects** — bundles of data (state) and behaviour (methods) — instead of loose functions and global data. C# is designed around OOP, and every .NET interview tests it.

The **four pillars**:

| Pillar | One line | C# features |
|---|---|---|
| Encapsulation | Hide internal state; expose a controlled API | `private` fields, properties, access modifiers |
| Abstraction | Show *what* an object does, hide *how* | `interface`, `abstract class` |
| Inheritance | Reuse and extend a base type ("is-a") | `: BaseClass`, `virtual`/`override`, `sealed` |
| Polymorphism | One interface, many implementations | Overloading (compile time), overriding (runtime) |

# Versions

OOP is a paradigm, not a versioned product, but C# has added OOP-related features over time:

| C# | OOP-related additions |
|---|---|
| 1.0 | Classes, interfaces, inheritance, virtual/override, abstract, sealed, properties, events |
| 2.0 | Generics, static classes, partial classes |
| 3.0 | Auto-properties, object initialisers, extension methods |
| 8.0 | **Default interface methods** (interfaces can contain implementations) |
| 9.0 | Records (value equality), `init` accessors, covariant return types |
| 11 | `required` members, static abstract members in interfaces |
| 12 | Primary constructors for classes and structs |
| 14 | Extension members (extension properties) |

History: Simula 67 introduced classes; Smalltalk (1970s) popularised "everything is an object"; C++, Java and C# made OOP mainstream.

# Lifecycle

**Object lifecycle in .NET**

1. **Type loading** — the first time a type is used, the CLR loads it and runs its **static constructor** once.
2. **Allocation** — `new` reserves memory on the managed heap (value types: inline).
3. **Construction** — field initialisers run, then base-class constructor, then the derived constructor body (`: base(...)` / `: this(...)` chaining).
4. **Use** — methods called, state changes through its public API.
5. **Unreachable** — no references remain.
6. **Collection** — GC reclaims memory; a finaliser runs first if defined.
7. **Disposal** (optional, deterministic) — `Dispose()` via `using` releases unmanaged resources earlier.

**OOP design lifecycle (OOAD):** requirements → identify nouns (classes) and verbs (methods) → define responsibilities and relationships (UML class diagram) → apply principles (SOLID) and patterns → implement → unit test → refactor.

# Module: Classes and Objects

## Lesson: [Basic|High] Class, object, fields, properties and methods

A **class** is a blueprint; an **object** is an instance created from it at runtime.

```csharp
public class BankAccount
{
    private decimal _balance;                       // field (state) — private
    public string Owner { get; }                    // read-only property
    public decimal Balance => _balance;             // computed property

    public BankAccount(string owner, decimal opening = 0)   // constructor
    {
        Owner = owner;
        _balance = opening;
    }

    public void Deposit(decimal amount)             // method (behaviour)
    {
        if (amount <= 0) throw new ArgumentOutOfRangeException(nameof(amount));
        _balance += amount;
    }
}

var acc = new BankAccount("Divakar", 500);           // object
acc.Deposit(250);
Console.WriteLine(acc.Balance);                      // 750
```

## Lesson: [Basic|High] Constructors: default, parameterised, static, private, chaining

```csharp
public class Logger
{
    public static readonly DateTime LoadedAt;
    static Logger() { LoadedAt = DateTime.UtcNow; }      // static ctor: once per type, before first use

    public string Name { get; }
    public Logger() : this("default") { }                // chaining to another ctor
    public Logger(string name) { Name = name; }
}

public class Settings
{
    private Settings() { }                               // private ctor: no outside 'new'
    public static Settings Load() => new Settings();     // factory method / Singleton
}

public class Admin : User
{
    public Admin(string email) : base(email) { }         // call base constructor
}
```

- If you write no constructor, C# provides a parameterless one. Writing any constructor removes it.
- Order: static fields → static ctor (once) → instance field initialisers → base ctor → derived ctor body.
- Copy constructor: a constructor taking another instance of the same type (records generate one).

## Lesson: [Basic|High] Access modifiers

| Modifier | Accessible from |
|---|---|
| `public` | Everywhere |
| `private` | Same class only (default for class members) |
| `protected` | Same class and derived classes |
| `internal` | Same assembly (default for top-level types) |
| `protected internal` | Same assembly **or** derived classes anywhere |
| `private protected` | Derived classes **in the same assembly** only |
| `file` (C# 11) | Same source file (for types) |

> **Interview tip:** the default access for class members is `private`; for a top-level class it is `internal`.

## Lesson: [Basic|Medium] Static members, static classes and partial classes

```csharp
public static class MathHelper                   // cannot be instantiated or inherited
{
    public static double Square(double x) => x * x;
}

public class Counter
{
    public static int Instances;                 // shared across all objects
    public Counter() => Instances++;
}

public partial class Customer { public string Name { get; set; } = ""; }   // file 1
public partial class Customer { public string Display() => Name.ToUpper(); } // file 2 (e.g. generated code)
```

Static members belong to the **type**, not to an object. Avoid mutable static state in web apps — it is shared by every request and thread.

# Module: The Four Pillars

## Lesson: [Basic|High] Encapsulation

Encapsulation = keep data **private** and allow changes only through methods that enforce the rules (invariants).

```csharp
// Bad: anyone can put the object in an invalid state
public class OrderBad { public List<OrderLine> Lines = new(); public decimal Total; }

// Good: the object protects its invariants
public class Order
{
    private readonly List<OrderLine> _lines = [];
    public IReadOnlyList<OrderLine> Lines => _lines;
    public decimal Total => _lines.Sum(l => l.Price * l.Qty);

    public void AddLine(Product p, int qty)
    {
        if (qty <= 0) throw new ArgumentException("Qty must be positive");
        _lines.Add(new OrderLine(p.Id, p.Price, qty));
    }
}
```

Benefits: validation in one place, freedom to change internals, fewer bugs.

## Lesson: [Basic|High] Abstraction

Abstraction = expose only what callers need and hide implementation details. In C# you abstract with **interfaces** and **abstract classes**.

```csharp
public interface IPaymentGateway
{
    Task<PaymentResult> ChargeAsync(decimal amount, string currency, string token);
}

public class RazorpayGateway : IPaymentGateway { /* HTTP calls, signatures, retries hidden here */ }
public class StripeGateway : IPaymentGateway { /* ... */ }

public class CheckoutService(IPaymentGateway gateway)     // depends on the abstraction only
{
    public Task<PaymentResult> Pay(Order o) => gateway.ChargeAsync(o.Total, "INR", o.CardToken);
}
```

> **Interview tip:** encapsulation is about *hiding data* (how state is protected); abstraction is about *hiding complexity* (what is exposed). They work together.

## Lesson: [Basic|High] Inheritance

A derived class inherits members of a base class and can extend or override them. C# supports **single class inheritance** and **multiple interface implementation**.

```csharp
public abstract class Employee
{
    public string Name { get; }
    protected Employee(string name) => Name = name;
    public abstract decimal MonthlyPay();                       // must override
    public virtual string Describe() => $"{Name}: {MonthlyPay():C}";  // may override
}

public class Permanent(string name, decimal salary) : Employee(name)
{
    public override decimal MonthlyPay() => salary / 12;
}

public sealed class Contractor(string name, decimal rate, int hours) : Employee(name)
{
    public override decimal MonthlyPay() => rate * hours;
    public override string Describe() => base.Describe() + " (contract)";
}
```

Types of inheritance: single, multilevel (A→B→C), hierarchical (B and C from A). **Multiple class inheritance is not allowed** (avoids the diamond problem); use interfaces instead.

## Lesson: [Basic|High] Polymorphism: overloading vs overriding

**Compile-time (static) polymorphism** — method **overloading**: same name, different parameter lists, chosen by the compiler. Operator overloading is also compile-time.

**Runtime (dynamic) polymorphism** — method **overriding**: a `virtual`/`abstract` base method replaced with `override` in a derived class; the actual object type decides at runtime.

```csharp
public class Calculator
{
    public int Add(int a, int b) => a + b;                 // overloads
    public double Add(double a, double b) => a + b;
    public int Add(int a, int b, int c) => a + b + c;
}

List<Employee> staff = [new Permanent("Asha", 1_200_000), new Contractor("Ravi", 900, 160)];
foreach (var e in staff)
    Console.WriteLine(e.Describe());     // each object's own override runs
```

**Method hiding (`new`)** is different: the method chosen depends on the *variable's* type, not the object's.

```csharp
class A { public virtual string Who() => "A"; public string Name() => "A"; }
class B : A { public override string Who() => "B"; public new string Name() => "B"; }
A x = new B();
Console.WriteLine(x.Who());   // B  (override — runtime type)
Console.WriteLine(x.Name());  // A  (hiding — compile-time type)
```

# Module: Interfaces and Abstract Classes

## Lesson: [Intermediate|High] Interface vs abstract class

| | Interface | Abstract class |
|---|---|---|
| Purpose | A **contract** / capability ("can do") | A **partial base implementation** ("is a") |
| Multiple | A class can implement many | A class can inherit only one |
| Fields / state | No instance fields | Can have fields and state |
| Constructors | No | Yes |
| Implementation | Default methods allowed since C# 8 | Abstract and concrete members |
| Access modifiers | Members public by default | Any |
| Use when | Unrelated types share behaviour; for DI and mocking | Related types share code and state |

```csharp
public interface IShape { double Area(); string Name => GetType().Name; }  // default implementation (C# 8)

public abstract class Shape : IShape
{
    public abstract double Area();
    public override string ToString() => $"{GetType().Name} area={Area():F2}";  // shared code
}
public class Circle(double r) : Shape { public override double Area() => Math.PI * r * r; }
```

## Lesson: [Intermediate|Medium] Explicit interface implementation

Used when two interfaces have the same member, or to hide a member from the class's public API.

```csharp
public interface IPrinter { void Print(); }
public interface IScanner { void Print(); }   // same name

public class Mfp : IPrinter, IScanner
{
    void IPrinter.Print() => Console.WriteLine("printing");
    void IScanner.Print() => Console.WriteLine("printing scan log");
}

var m = new Mfp();
((IPrinter)m).Print();   // only callable through the interface
```

## Lesson: [Intermediate|Medium] Sealed classes, virtual, override, base and new

- `virtual` — the base method can be overridden.
- `override` — replaces a virtual/abstract member.
- `sealed override` — stops further overriding down the chain.
- `sealed class` — cannot be inherited (e.g. `string`); also lets the JIT devirtualise calls.
- `base.Method()` — call the base implementation from the override.
- `new` — hides a base member (rarely what you want; the compiler warns without it).
- Static methods can't be virtual (except static abstract interface members in C# 11 for generic math).

# Module: Relationships and Design

## Lesson: [Intermediate|High] Association, aggregation and composition

| Relationship | Meaning | Lifetime | Example |
|---|---|---|---|
| Association | "uses" / knows about | Independent | `Teacher` ↔ `Student` |
| Aggregation | "has-a", weak ownership | Part can exist without whole | `Department` has `Employees` |
| Composition | "owns-a", strong ownership | Part dies with whole | `Order` owns `OrderLines`; `House` owns `Rooms` |
| Inheritance | "is-a" | — | `Car` is a `Vehicle` |

```csharp
public class Order               // composition: lines are created and owned by the order
{
    private readonly List<OrderLine> _lines = [];
    public void Add(string sku, int qty) => _lines.Add(new OrderLine(sku, qty));
}

public class Department          // aggregation: employees exist independently
{
    public List<Employee> Members { get; } = [];
}
```

## Lesson: [Intermediate|High] Composition over inheritance

Deep inheritance trees are fragile: a change in the base class ripples down ("fragile base class problem"), and you inherit things you don't need. **Prefer composing objects from small pieces** and inheriting only for true "is-a" relationships.

```csharp
// Inheritance explosion: EmailNotifier, SmsNotifier, EmailAndSmsNotifier, LoggedEmailNotifier...
// Composition: combine behaviours at runtime
public interface IChannel { Task SendAsync(string to, string msg); }

public class Notifier(IEnumerable<IChannel> channels)
{
    public Task NotifyAsync(string to, string msg) => Task.WhenAll(channels.Select(c => c.SendAsync(to, msg)));
}
```

## Lesson: [Intermediate|Medium] Object equality, GetHashCode and ToString

```csharp
public sealed class Money : IEquatable<Money>
{
    public decimal Amount { get; }
    public string Currency { get; }
    public Money(decimal amount, string currency) => (Amount, Currency) = (amount, currency);

    public bool Equals(Money? other) => other is not null && Amount == other.Amount && Currency == other.Currency;
    public override bool Equals(object? obj) => Equals(obj as Money);
    public override int GetHashCode() => HashCode.Combine(Amount, Currency);
    public override string ToString() => $"{Amount} {Currency}";
}
// Or simply: public record Money(decimal Amount, string Currency);  — generates all of the above
```

Rule: equal objects **must** return equal hash codes, otherwise `Dictionary`/`HashSet` lookups fail.

## Lesson: [Advanced|Medium] Cohesion, coupling and the Law of Demeter

- **High cohesion:** a class does one focused job; its members belong together.
- **Low coupling:** classes depend on few others, through abstractions.
- **Law of Demeter** ("talk to friends, not strangers"): avoid `order.Customer.Address.City.Name` chains; ask the object to do the work: `order.ShippingCity()`.
- **Tell, don't ask:** tell the object what to do rather than pulling data out and deciding for it.

These lead straight into SOLID, covered in the next course.

# Interview

## [Beginner|High] What are the four pillars of OOP? Explain each with an example.

1. **Encapsulation** — private state with a controlled public API. `BankAccount` keeps `_balance` private and exposes `Deposit()` that rejects negative amounts.
2. **Abstraction** — expose *what*, hide *how*. `IPaymentGateway.ChargeAsync()` hides HTTP calls, signatures and retries.
3. **Inheritance** — a derived class reuses and extends a base. `Contractor : Employee` reuses `Name` and `Describe()`.
4. **Polymorphism** — the same call behaves differently by type. `employee.MonthlyPay()` runs the `Permanent` or `Contractor` override at runtime.

## [Beginner|High] What is the difference between a class and an object?

A class is a **type definition** (blueprint) describing fields, properties and methods; it exists in code and metadata. An object is an **instance** of that class created at runtime with `new`, occupying memory with its own state. One class, many objects.

## [Beginner|High] What is the difference between method overloading and method overriding?

| Overloading | Overriding |
|---|---|
| Same name, **different parameters** | Same signature in a derived class |
| Same class (or derived) | Requires `virtual`/`abstract` + `override` |
| Resolved at **compile time** | Resolved at **runtime** by the object's type |
| Return type alone can't differ | Return type the same (covariant returns allowed since C# 9) |

## [Beginner|High] What is the difference between an abstract class and an interface? When do you use which?

An abstract class can hold state, constructors and shared implementation, and a class can inherit only one. An interface is a contract; a class can implement many, and it has no instance state (default methods are allowed since C# 8). Use an **interface** for capabilities and dependency injection (`IEmailSender`) and an **abstract class** when related types share code and state (`Shape`, `Employee`). A common design is to use both: the interface for consumers, an abstract base for shared code.

## [Beginner|High] Does C# support multiple inheritance?

Not for classes — a class has exactly one base class, which avoids the **diamond problem** (ambiguity when two parents implement the same member). A class can implement **multiple interfaces**. If two interfaces declare the same member, use explicit interface implementation to disambiguate.

## [Beginner|High] What are access modifiers? What are the defaults?

`public`, `private`, `protected`, `internal`, `protected internal`, `private protected` (plus `file` for types). Defaults: class members are `private`; top-level types are `internal`; interface members are `public`.

## [Beginner|Medium] What is a constructor? Can it be private or static?

A constructor initialises a new object and has the class's name and no return type. A **private** constructor prevents outside instantiation (Singleton, factory methods, static-like classes). A **static** constructor takes no parameters and no access modifier, runs **once** before the type is first used, and initialises static data. Constructors can be overloaded and chained with `this(...)`/`base(...)`. They are not inherited.

## [Beginner|Medium] What is the `sealed` keyword?

A `sealed` class can't be inherited (e.g. `string`). A `sealed override` method can't be overridden further. Use it to lock down security-sensitive or invariant-heavy types. It also gives a small performance gain because the JIT can devirtualise calls.

## [Intermediate|High] What is the difference between method overriding and method hiding (`new`)?

With **override**, the runtime type decides which method runs — true polymorphism. With **hiding** (`new`), the **compile-time variable type** decides: `A x = new B(); x.Name()` calls `A.Name()`. Hiding breaks polymorphism and is usually a design smell. The compiler warns if you hide a member without the `new` keyword.

## [Intermediate|High] What is the difference between composition and inheritance? Why "favour composition"?

Inheritance is a static "is-a" relationship fixed at compile time; subclasses depend on base-class internals, so base changes can break them. Composition is "has-a": an object holds other objects (often via interfaces) and delegates to them. You can swap them at runtime, test them in isolation and avoid class explosions. Use inheritance only when the subtype really is a substitutable kind of the base (see LSP).

## [Intermediate|High] Explain association, aggregation and composition with examples.

All three are "uses/has" relationships of different strength. **Association**: two classes know about each other and have independent lifetimes (Doctor–Patient). **Aggregation**: whole–part where the part can exist alone (Team–Player; delete the team and the players remain). **Composition**: whole–part with shared lifetime (Order–OrderLine, House–Room; delete the order and its lines go too).

## [Intermediate|High] Can you create an instance of an abstract class? Can an abstract class have a constructor?

You can't instantiate it with `new`. It **can** have constructors, usually `protected`, which derived classes call via `: base(...)` to initialise shared state. An abstract class can also have no abstract members at all; it's then just a base that must not be used directly.

## [Intermediate|Medium] What are virtual methods? Why aren't methods virtual by default in C#?

A `virtual` method can be overridden in derived classes. C# makes methods **non-virtual by default** (unlike Java) for performance (non-virtual calls are direct and can be inlined) and versioning safety: designers must explicitly allow overriding, so a new base method can't accidentally change the behaviour of subclasses.

## [Intermediate|Medium] What is a static class? Static vs singleton?

A static class can't be instantiated or inherited and contains only static members (e.g. `Math`, extension method holders). A **singleton** is a normal class with one instance. It can implement interfaces, be passed as a dependency, be lazily created and be mocked. In ASP.NET Core you usually get singleton behaviour by registering a service with `AddSingleton` rather than writing the pattern by hand.

## [Intermediate|Medium] Why must you override GetHashCode when you override Equals?

Hash-based collections (`Dictionary`, `HashSet`) first compare hash codes to find a bucket, then call `Equals`. If two equal objects return different hash codes, lookups miss and duplicates appear. The contract: `a.Equals(b)` ⇒ `a.GetHashCode() == b.GetHashCode()`. Use `HashCode.Combine(...)`, or use a `record`, which generates both.

## [Intermediate|Medium] What is an interface default method (C# 8) and why was it added?

Interfaces can now include a method body. It was added so library authors can **add members to a published interface without breaking existing implementers**, and for Java/Swift interop. The default implementation is only reachable through the interface type, not through the class variable.

## [Advanced|Medium] What are cohesion and coupling? How do you measure them in practice?

Cohesion is how strongly related a class's responsibilities are; coupling is how much a class depends on others. Aim for high cohesion and low coupling. Signs of trouble: classes named `Manager`/`Helper`/`Utils` with unrelated methods, constructors with 8+ dependencies, and changes that ripple across many files. Tools: Visual Studio code metrics (class coupling, maintainability index), NDepend, SonarQube.

## [Advanced|Low] What are covariant return types (C# 9)?

An override can return a **more derived** type than the base method. For example, `Animal.Clone()` returns `Animal`, and `Dog.Clone()` can be declared to return `Dog`. Callers then don't need to cast.

## [Scenario|High] You have `Bird` with a `Fly()` method and now need `Penguin`. How do you model it?

Making `Penguin : Bird` and throwing `NotSupportedException` from `Fly()` violates Liskov substitution: callers that loop over birds and call `Fly()` will crash. Split the capability out: `Bird` (common: eat, lay eggs) plus an `IFlyable` interface implemented only by birds that fly. Code that needs flying asks for `IFlyable`. This is composition of capabilities over a deep hierarchy.

## [Scenario|High] A `ReportGenerator` class has methods for fetching data, formatting PDF and Excel, emailing and logging. It's 3,000 lines. How would you refactor it?

Identify the responsibilities and extract each into a focused class behind an interface: `IReportDataSource`, `IReportFormatter` (with `PdfFormatter` and `ExcelFormatter`), `IReportSender` and `ILogger`. `ReportGenerator` then orchestrates them, receiving them by constructor injection. Add unit tests around the current behaviour **before** extracting (characterisation tests), then refactor in small steps. Result: SRP, OCP (new format = new formatter class) and easy mocking.

## [Scenario|Medium] Your team adds a new payment method every quarter, and each time someone edits a big switch statement in `PaymentService`. What design would you suggest?

Replace the switch with **polymorphism**: an `IPaymentMethod` interface with one class per method (Card, UPI, Wallet, BankTransfer). Register all of them in DI, and have a resolver pick the right one by key. Adding a method means adding a class and a DI registration, without touching existing code (Open/Closed principle, Strategy pattern).

## [Scenario|Medium] An interviewer asks you to design classes for a parking lot. What would you show?

Start with the nouns: `ParkingLot` (has `Levels`), `Level` (has `Spots`), `ParkingSpot` (abstract: `Compact`, `Large`, `Motorbike`, `EvCharging`), `Vehicle` (abstract: `Car`, `Bike`, `Truck`), `Ticket`, `Payment`, `EntryGate`/`ExitGate`. Behaviour: `ParkingLot.Park(vehicle)` finds a fitting spot (Strategy for allocation), issues a `Ticket`; `Exit(ticket)` calculates the fee (Strategy for pricing) and frees the spot. Mention encapsulation (spot availability private), polymorphism (`CanFit(vehicle)`), concurrency (two cars taking the same spot: lock per level or an atomic DB update), and extensibility (new vehicle types).

# Cheatsheet

## Four pillars in one line each

- **Encapsulation** — private data, public methods that guard rules.
- **Abstraction** — interfaces/abstract classes expose *what*, hide *how*.
- **Inheritance** — `Derived : Base` reuses and extends ("is-a").
- **Polymorphism** — overloading (compile time) and overriding (runtime).

## Interface vs abstract class

| | Interface | Abstract class |
|---|---|---|
| Inherit many? | Yes | No (one) |
| State/fields | No | Yes |
| Constructor | No | Yes |
| Default implementation | Yes (C# 8+) | Yes |
| Best for | Contracts, DI, mocking | Shared base code |

## Keywords

| Keyword | Meaning |
|---|---|
| `virtual` | May be overridden |
| `abstract` | Must be overridden; no body |
| `override` | Replaces base virtual/abstract |
| `sealed` | No further inheritance/override |
| `new` | Hides a base member (no polymorphism) |
| `base` | Access base members/constructor |
| `this` | Current instance / chain constructors |
| `static` | Belongs to the type |

## Relationships

- Association: uses (independent lifetimes)
- Aggregation: has-a (part survives)
- Composition: owns-a (part dies with whole)
- Inheritance: is-a
- Prefer composition; inherit only for true substitutable "is-a".

## Constructor order

Static field initialisers → static ctor (once) → instance field initialisers (derived, then base) → base ctor body → derived ctor body.

## Equality checklist

- Override `Equals(object)`, implement `IEquatable<T>`, override `GetHashCode` with `HashCode.Combine`.
- Or use `record` for value equality for free.
