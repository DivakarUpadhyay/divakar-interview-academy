# Overview

**Amazon Web Services (AWS)** is the largest public cloud provider (since 2006), with 200+ services across 30+ regions. As a .NET/full stack developer you mainly need: **IAM**, **compute** to run APIs, **databases**, **storage**, **networking**, **messaging**, **monitoring** and **deployment automation**.

# Lifecycle

**Deploying a .NET API to AWS (typical path):**

1. **Account setup** — organisation, root user locked down with MFA, IAM Identity Center users/roles, budgets.
2. **Network** — a VPC with public subnets (load balancer) and private subnets (app, database) across 2–3 AZs.
3. **Data** — RDS for SQL Server (Multi-AZ) or Aurora PostgreSQL in private subnets; credentials in Secrets Manager.
4. **Compute** — container image in **ECR** → **ECS Fargate** service behind an **Application Load Balancer** (or Elastic Beanstalk / Lambda).
5. **Edge** — Route 53 DNS → CloudFront (CDN, TLS via ACM certificate) → ALB.
6. **CI/CD** — GitHub Actions/CodePipeline: build, test, push image, deploy new task definition.
7. **Operate** — CloudWatch logs/metrics/alarms, X-Ray/OpenTelemetry traces, CloudTrail audit, cost alerts.

# Module: Foundations

## Lesson: [Basic|High] Regions, availability zones, the shared responsibility model and IAM

- **Region** — a geographic area (e.g. `ap-south-1` Mumbai, `ap-northeast-1` Tokyo, `us-east-1` N. Virginia) with multiple **Availability Zones (AZs)** — separate data centres with independent power/network. Deploy across ≥2 AZs for high availability.
- **Edge locations** — CloudFront/Route 53 points of presence close to users.
- **Shared responsibility:** AWS secures the cloud (hardware, facilities, hypervisor, managed service internals); **you** secure what's in the cloud (IAM, data, OS patches on EC2, network rules, app code, encryption settings).

**IAM (Identity and Access Management):**

| Concept | Meaning |
|---|---|
| User / group | People (prefer IAM Identity Center/SSO for humans) |
| **Role** | Identity assumed by services or people for temporary credentials — EC2 instance roles, ECS task roles, Lambda execution roles |
| **Policy** | JSON document allowing/denying actions on resources |
| Least privilege | Grant only needed actions/resources |
| Root user | Only for account-level tasks; MFA, no access keys |

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["s3:GetObject", "s3:PutObject"],
    "Resource": "arn:aws:s3:::shop-uploads-prod/*"
  }]
}
```

Applications on AWS should use **roles** (temporary credentials provided automatically to the SDK) — never hard-coded access keys.

# Module: Compute

## Lesson: [Basic|High] EC2, Elastic Beanstalk, ECS/Fargate, EKS, App Runner and Lambda

| Service | You manage | Good for .NET |
|---|---|---|
| **EC2** | VM: OS, IIS/Kestrel, patches, scaling (Auto Scaling groups) | Lift-and-shift .NET Framework/IIS apps (Windows AMIs) |
| **Elastic Beanstalk** | Just upload the app; Beanstalk creates EC2, load balancer, auto scaling | Quick hosting of ASP.NET Core (Linux) or .NET Framework on IIS (Windows) |
| **App Runner** | Container image or source; fully managed HTTPS service | Simple containerised APIs |
| **ECS + Fargate** | Container task definitions and services; no servers | Most containerised .NET microservices |
| **EKS** | Kubernetes cluster (managed control plane) | Teams standardised on Kubernetes |
| **Lambda** | Functions; pay per request and duration; scales to zero | Event-driven code, APIs with spiky traffic |

```bash
# ASP.NET Core on Lambda behind API Gateway (Amazon.Lambda.AspNetCoreServer.Hosting)
dotnet new install Amazon.Lambda.Templates
dotnet new serverless.AspNetCoreMinimalAPI -n ShopApi
# Program.cs: builder.Services.AddAWSLambdaHosting(LambdaEventSource.HttpApi);
dotnet lambda deploy-serverless
```

```csharp
// A plain Lambda function handler (S3 upload event → create thumbnail)
public class Function
{
    public async Task Handler(S3Event evt, ILambdaContext ctx)
    {
        foreach (var record in evt.Records)
            ctx.Logger.LogInformation($"New file {record.S3.Object.Key} in {record.S3.Bucket.Name}");
    }
}
```

**Auto Scaling:** EC2 Auto Scaling groups or ECS service auto scaling based on CPU, request count or SQS queue depth; place instances/tasks in multiple AZs behind an ALB.

# Module: Storage and Databases

## Lesson: [Basic|High] S3, EBS and EFS

| Service | Type | Use |
|---|---|---|
| **S3** | Object storage (buckets, keys) — 11 nines durability | Uploads, images, static websites, backups, data lake |
| **EBS** | Block storage volumes attached to one EC2 instance | OS and database disks |
| **EFS** / FSx | Shared file systems (NFS / Windows SMB with FSx for Windows) | Shared content across servers |

S3 features: **storage classes** (Standard, Intelligent-Tiering, Standard-IA, Glacier tiers for archives), **lifecycle rules**, **versioning**, **pre-signed URLs** (temporary upload/download links), server-side encryption (SSE-S3/SSE-KMS, on by default), **Block Public Access** (keep on unless hosting public content via CloudFront).

```csharp
var s3 = new AmazonS3Client();                                   // credentials from the IAM role
await s3.PutObjectAsync(new PutObjectRequest { BucketName = "shop-uploads-prod", Key = $"invoices/{id}.pdf", FilePath = path });
var url = await s3.GetPreSignedURLAsync(new GetPreSignedUrlRequest
{
    BucketName = "shop-uploads-prod", Key = $"invoices/{id}.pdf", Expires = DateTime.UtcNow.AddMinutes(15)
});
```

## Lesson: [Intermediate|High] Databases — RDS for SQL Server, Aurora, DynamoDB and ElastiCache

**Amazon RDS** — managed relational databases: **SQL Server** (Express, Web, Standard, Enterprise editions; licence included or BYOL on RDS Custom), PostgreSQL, MySQL, MariaDB, Oracle, Db2.

- **Multi-AZ** — synchronous standby in another AZ, automatic failover (HA).
- **Read replicas** — asynchronous copies for read scaling (SQL Server Enterprise supports read replicas).
- **Automated backups** (point-in-time restore, 1–35 days) and manual snapshots.
- Runs in private subnets; access controlled by **security groups**; encryption with KMS.
- RDS for SQL Server has no `sysadmin` — some features (some SQL Agent features, native backup to S3 via stored procedures, SSIS/SSRS support with options) differ from on-prem.

```json
// appsettings.Production.json — connection string with credentials loaded from Secrets Manager at startup
"ConnectionStrings": { "Shop": "Server=shop-db.abc123.ap-south-1.rds.amazonaws.com,1433;Database=Shop;Encrypt=True;" }
```

**Aurora** — AWS's cloud-native MySQL/PostgreSQL-compatible engine: storage replicated 6 ways across 3 AZs, up to 15 low-latency read replicas, fast failover, Aurora Serverless v2 (scales capacity automatically), Global Database for multi-region.

**DynamoDB** — fully managed key-value/document NoSQL with single-digit-ms latency at any scale:

- Tables with a **partition key** (and optional **sort key**); access patterns designed up front (single-table design).
- Capacity modes: **on-demand** (pay per request) or provisioned (with auto scaling).
- **GSIs/LSIs** (secondary indexes), **DynamoDB Streams** (change events → Lambda), TTL, transactions, global tables (multi-region).

**ElastiCache** (Redis/Valkey/Memcached) — managed in-memory cache for sessions and query caching; **MemoryDB** for durable Redis.

# Module: Networking, Integration and Security

## Lesson: [Intermediate|High] VPC, security groups, load balancers, Route 53, CloudFront and API Gateway

```text
Route 53 (DNS) → CloudFront (CDN, WAF, TLS) → Application Load Balancer (public subnets, 2+ AZs)
   → ECS tasks / EC2 instances (private subnets) → RDS (private subnets, Multi-AZ)
   NAT Gateway in public subnet gives private resources outbound internet access
```

| Component | Meaning |
|---|---|
| **VPC** | Your private network (CIDR range, e.g. 10.0.0.0/16) in a region |
| Subnets | Public (route to an Internet Gateway) or private; one per AZ |
| **Security group** | Stateful firewall on instances/ENIs — allow rules only (e.g. RDS SG allows 1433 only from the app SG) |
| Network ACL | Stateless subnet-level firewall (allow/deny) |
| NAT Gateway | Outbound internet for private subnets |
| VPC endpoints | Private access to S3/DynamoDB/other services without internet |
| **ALB** | Layer 7 load balancer (HTTP routing, host/path rules, TLS) — for web apps |
| NLB | Layer 4 (TCP/UDP), very high throughput, static IPs |
| **Route 53** | DNS + health checks + routing policies (latency, weighted, failover, geolocation) |
| **CloudFront** | CDN with edge caching, TLS (ACM certificates), origin access to S3 |
| **API Gateway** | Managed API front door: REST/HTTP/WebSocket APIs, auth (Cognito/JWT/IAM), throttling, Lambda integration |

## Lesson: [Intermediate|High] Messaging and events — SQS, SNS, EventBridge, Kinesis and Step Functions

| Service | Pattern | Use |
|---|---|---|
| **SQS** | Queue (standard: at-least-once, best-effort order; FIFO: exactly-once processing, ordered) | Decouple services, background jobs, buffering |
| **SNS** | Pub/sub topic → many subscribers (SQS, Lambda, HTTP, email, SMS) | Fan-out notifications |
| **EventBridge** | Event bus with rules routing events (AWS services, SaaS, your apps), scheduler | Event-driven architectures, cron jobs |
| **Kinesis Data Streams** / MSK | Ordered, replayable streams | Clickstreams, IoT telemetry, analytics |
| **Step Functions** | Workflow/state machine orchestration | Sagas, multi-step processes with retries |

```csharp
var sqs = new AmazonSQSClient();
await sqs.SendMessageAsync(queueUrl, JsonSerializer.Serialize(new OrderPlaced(orderId)));
var resp = await sqs.ReceiveMessageAsync(new ReceiveMessageRequest { QueueUrl = queueUrl, MaxNumberOfMessages = 10, WaitTimeSeconds = 20 });   // long polling
foreach (var m in resp.Messages)
{
    await HandleAsync(m.Body);                                  // idempotent handler
    await sqs.DeleteMessageAsync(queueUrl, m.ReceiptHandle);    // delete only after success; otherwise it reappears after the visibility timeout
}
```

Dead-letter queues capture messages that fail repeatedly (`maxReceiveCount`).

## Lesson: [Intermediate|High] Security, secrets, monitoring and governance

- **KMS** — encryption keys for S3, EBS, RDS, Secrets Manager; envelope encryption.
- **Secrets Manager** (rotation for RDS passwords) / **SSM Parameter Store** — load secrets into .NET configuration (`Amazon.Extensions.Configuration.SystemsManager`) via the task/instance role.
- **ACM** — free TLS certificates for ALB/CloudFront/API Gateway with auto-renewal.
- **Cognito** — user sign-up/sign-in (user pools) issuing JWTs, social/SAML federation.
- **WAF + Shield** — web application firewall and DDoS protection on CloudFront/ALB/API Gateway.
- **CloudWatch** — metrics, logs (Logs Insights queries), alarms, dashboards; **X-Ray**/ADOT (OpenTelemetry) for traces.
- **CloudTrail** — audit log of every API call in the account; **Config** — resource compliance history; **GuardDuty** — threat detection; **Security Hub** — findings overview.
- **Organizations + SCPs**, tagging, **Budgets** and **Cost Explorer** for governance.

## Lesson: [Intermediate|High] Infrastructure as code and CI/CD — CloudFormation, CDK, CodePipeline, GitHub Actions

```csharp
// AWS CDK in C# — a Fargate service behind a load balancer in ~10 lines
public class ShopStack : Stack
{
    public ShopStack(Construct scope, string id) : base(scope, id)
    {
        var vpc = new Vpc(this, "Vpc", new VpcProps { MaxAzs = 2 });

            TaskImageOptions = new ApplicationLoadBalancedTaskImageOptions { Image = ContainerImage.FromAsset("../src/Shop.Api"), ContainerPort = 8080 }
        });
    }
}
// cdk deploy
```

## Lesson: [Advanced|Medium] Well-Architected Framework and cost management

**AWS Well-Architected Framework — six pillars:** Operational excellence, Security, Reliability, Performance efficiency, Cost optimisation, Sustainability.

Cost levers: right-size instances (Compute Optimizer), **Savings Plans/Reserved Instances** for steady load, **Spot** instances for interruptible work, Graviton (ARM) instances for .NET (cheaper per performance), Lambda/Fargate for spiky workloads, S3 lifecycle to cheaper tiers, turn off non-prod at night, delete idle resources (unattached EBS, old snapshots, idle NAT gateways and load balancers), Budgets with alerts, cost allocation tags.

# Interview

## [Beginner|High] What are regions and availability zones?

A region is a geographic area (Mumbai, Singapore, Tokyo…) containing multiple isolated availability zones — separate data centres with independent power, cooling and networking connected by low-latency links. Deploying across at least two AZs protects against a data-centre failure; multiple regions protect against regional outages and serve global users.

## [Beginner|High] Explain the shared responsibility model.

AWS is responsible for security *of* the cloud — physical data centres, hardware, networking, virtualisation and the internals of managed services. The customer is responsible for security *in* the cloud — IAM users and policies, data and its encryption, network configuration (security groups), OS patching on EC2, application code and secrets. The split shifts with the service: more customer responsibility on EC2, less on Lambda/S3.

## [Beginner|High] What is IAM and what is the difference between a user and a role?

IAM controls who can do what on which AWS resources using JSON policies. A user is a long-term identity (person or legacy app) with credentials; a role is an identity without permanent credentials that is assumed to obtain temporary credentials — used by EC2 instances, ECS tasks, Lambda functions, other accounts and federated users. Applications should use roles, not access keys.

## [Beginner|High] EC2 vs Elastic Beanstalk vs ECS/Fargate vs Lambda for hosting a .NET API?

EC2: full VMs you manage (good for legacy IIS apps). Elastic Beanstalk: PaaS that provisions EC2, load balancing and scaling for you — quick hosting. ECS on Fargate: run containers without managing servers — the common choice for containerised ASP.NET Core microservices. Lambda: functions billed per request that scale to zero — great for event-driven or spiky APIs, with cold starts and time limits (15 min).

## [Beginner|High] What is S3 and what are storage classes?

Simple Storage Service: object storage for files of any size in buckets, highly durable (11 nines), accessed over HTTPS/SDK. Storage classes trade price vs access speed: Standard (frequent), Intelligent-Tiering (automatic), Standard-IA/One Zone-IA (infrequent), Glacier Instant/Flexible/Deep Archive (archives). Lifecycle rules move objects between classes automatically.

## [Intermediate|High] How do you host SQL Server on AWS?

Amazon RDS for SQL Server (managed: backups, patching, Multi-AZ failover, read replicas on Enterprise; licence included), RDS Custom for SQL Server (OS access, BYOL), or SQL Server on EC2 (full control, Always On, SSIS/SSRS on the box). Place databases in private subnets, restrict security groups to the app tier, encrypt with KMS and store credentials in Secrets Manager.

## [Intermediate|High] Security group vs network ACL?

Security groups are stateful firewalls attached to instances/network interfaces with allow rules only — return traffic is automatically allowed. Network ACLs are stateless rules on subnets with both allow and deny, evaluated in order, requiring explicit rules for return traffic. Security groups are the primary control; NACLs add coarse subnet-level protection.

## [Intermediate|High] SQS vs SNS vs EventBridge?

SQS is a message queue — consumers pull messages, each processed by one consumer, with retries and DLQs (decoupling and buffering). SNS is pub/sub — a message published to a topic is pushed to all subscribers (fan-out, notifications). EventBridge is an event bus with content-based routing rules from AWS services, SaaS and apps, plus a scheduler — for event-driven architectures. Common combination: SNS/EventBridge fan-out to several SQS queues.

## [Intermediate|High] What is DynamoDB and how do you design keys?

A fully managed NoSQL key-value/document database with consistent single-digit-ms latency at any scale. Items are stored by partition key (and optional sort key); design starts from access patterns — choose a high-cardinality partition key to spread load, a sort key for ranges/ordering, and GSIs for other access patterns (often single-table design). Use on-demand or provisioned capacity with auto scaling.

## [Intermediate|Medium] ALB vs NLB vs API Gateway?

ALB is a layer-7 HTTP/HTTPS load balancer with host/path routing, WebSockets and TLS termination — for web apps and containers. NLB is layer 4 (TCP/UDP), extremely fast with static IPs — for non-HTTP protocols or extreme throughput. API Gateway is a managed API front door with authentication, throttling, API keys, request validation and direct Lambda integration — for public/serverless APIs.

## [Intermediate|Medium] How do you manage secrets for a .NET app on AWS?

Store them in Secrets Manager (with rotation for database credentials) or SSM Parameter Store (SecureString), grant the app's IAM role permission to read only those secrets, and load them into `IConfiguration` at startup with the AWS configuration provider or SDK. No secrets in appsettings, environment files in source control or container images.

## [Advanced|Medium] How do you make an application highly available on AWS?

Run stateless app instances/tasks in at least two AZs behind an ALB with health checks and auto scaling; use Multi-AZ databases (RDS/Aurora) and replicated storage (S3); externalise sessions (ElastiCache/DynamoDB); use queues to absorb spikes; Route 53 health checks and failover routing to a second region for disaster recovery; automate infrastructure with IaC and test failures.

## [Advanced|Medium] What are the pillars of the AWS Well-Architected Framework?

Operational excellence (automation, observability, runbooks), Security (identity, protection, detection), Reliability (recover from failure, scale), Performance efficiency (right resources, experiment), Cost optimisation (pay for what you need) and Sustainability (minimise environmental impact). AWS offers a Well-Architected Tool to review workloads against them.

## [Scenario|High] Your ASP.NET Core API on ECS must read files from S3 and connect to RDS SQL Server. How do you set up access securely?

Give the ECS task a task IAM role with a least-privilege policy for the specific S3 bucket/prefix; the AWS SDK picks up temporary credentials automatically. Put RDS in private subnets with a security group allowing port 1433 only from the ECS service's security group; store the DB credentials in Secrets Manager (readable by the task role) and load them at startup; enforce TLS (`Encrypt=True`) and KMS encryption at rest.

## [Scenario|Medium] A company is moving from Azure to AWS. How would you map their stack (App Service, Azure SQL, Blob, Service Bus, Key Vault, App Insights)?

App Service → Elastic Beanstalk, App Runner or ECS Fargate; Azure SQL → RDS for SQL Server (or Aurora PostgreSQL if re-platforming); Blob Storage → S3; Service Bus queues/topics → SQS/SNS (or Amazon MQ for AMQP compatibility); Key Vault → Secrets Manager + KMS; Application Insights → CloudWatch + X-Ray/OpenTelemetry; Azure DevOps pipelines can deploy to AWS or move to GitHub Actions/CodePipeline. Migrate data with AWS DMS and test performance and IAM thoroughly.

## [Scenario|Medium] Your AWS bill doubled this month. How do you investigate and reduce it?

Use Cost Explorer grouped by service, account and tags to find the jump (often data transfer, NAT gateway traffic, oversized RDS/EC2, forgotten resources or logging volume). Fix: right-size or stop idle resources, Savings Plans for steady compute, S3 lifecycle policies, VPC endpoints to avoid NAT charges for S3/DynamoDB traffic, reduce CloudWatch log retention, set Budgets alerts and tagging policies to prevent recurrence.
