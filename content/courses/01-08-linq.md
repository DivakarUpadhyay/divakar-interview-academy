# Overview

**LINQ** (Language Integrated Query) adds query capabilities directly to C#. One syntax works over many data sources:

| Provider | Data source | Runs |
|---|---|---|
| LINQ to Objects | `IEnumerable<T>` — arrays, lists, dictionaries | In memory |
| LINQ to Entities (EF Core) | `IQueryable<T>` → SQL | In the database |
| LINQ to XML | `XDocument`, `XElement` | In memory |
| PLINQ | `.AsParallel()` | Parallel, in memory |
| Others | Cosmos DB SDK, MongoDB driver, OData | Remote |

LINQ is built on C# 3.0 features: **extension methods**, **lambda expressions**, **anonymous types**, `var`, **object initialisers** and **expression trees**.

# Versions

| Year | .NET / C# | LINQ additions |
|---|---|---|

| 2022 | .NET 7 | `Order()`, `OrderDescending()` |
| 2024 | .NET 9 | `CountBy`, `AggregateBy`, `Index()` |
| 2025 | .NET 10 | `LeftJoin`, `RightJoin` operators; `System.Linq.AsyncEnumerable` (async LINQ over `IAsyncEnumerable<T>`) in the box |

# Lifecycle

**How a LINQ query executes:**

1. **Define** — you compose operators (`Where`, `Select`, ...). Nothing runs yet; you've built a query object (an iterator chain, or an expression tree for `IQueryable`).
2. **Enumerate** — execution starts when you iterate (`foreach`) or call an immediate operator: `ToList`, `ToArray`, `ToDictionary`, `Count`, `Sum`, `First`, `Any`, ...
3. **Pull pipeline (LINQ to Objects)** — each element flows through `Where` → `Select` → consumer one at a time (streaming). Some operators must buffer everything first (`OrderBy`, `GroupBy`, `Reverse`, `Distinct` partially).
4. **Translation (IQueryable)** — the provider (EF Core) walks the expression tree, translates it to SQL, sends it to the DB and materialises results.
5. **Re-enumeration** re-runs the whole query — cache with `ToList()` if you need the results more than once.

# Module: LINQ Basics

## Lesson: [Basic|High] Query syntax vs method syntax

```csharp
var products = new List<Product>
{
    new(1, "Laptop", "Electronics", 65000, 5),
    new(2, "Mouse", "Electronics", 900, 50),
    new(3, "Desk", "Furniture", 9000, 0),
    new(4, "Chair", "Furniture", 6500, 12),
};

// Query syntax (SQL-like) — compiled into method calls
var q1 = from p in products
         where p.Price > 5000
         orderby p.Price descending
         select new { p.Name, p.Price };

// Method syntax (fluent, lambda-based) — same result
var q2 = products.Where(p => p.Price > 5000)
                 .OrderByDescending(p => p.Price)
                 .Select(p => new { p.Name, p.Price });

public record Product(int Id, string Name, string Category, decimal Price, int Stock);
```

Query syntax supports `from, where, select, orderby, group … by … into, join … on … equals, let`. Everything else (`Count`, `First`, `Distinct`, `Skip`, `Take`, `Any`, `Sum`) needs method syntax. Most teams use method syntax; query syntax is nicer for multi-joins and `let`.

## Lesson: [Basic|High] Deferred vs immediate execution

```csharp
var numbers = new List<int> { 1, 2, 3 };
var evens = numbers.Where(n => n % 2 == 0);    // deferred: nothing executed yet
numbers.Add(4);
Console.WriteLine(string.Join(",", evens));     // 2,4  — query ran now, saw the added item

var snapshot = numbers.Where(n => n > 1).ToList();   // immediate: executed and stored
numbers.Add(10);
Console.WriteLine(snapshot.Count);                   // 3 — unaffected
```

| Deferred (return a query) | Immediate (execute now) |
|---|---|
| `Where`, `Select`, `SelectMany`, `OrderBy`, `ThenBy`, `GroupBy`, `Join`, `Skip`, `Take`, `Distinct`, `Concat`, `Zip` | `ToList`, `ToArray`, `ToDictionary`, `ToHashSet`, `ToLookup`, `Count`, `Sum`, `Min`, `Max`, `Average`, `First`, `Single`, `Any`, `All`, `Contains`, `Aggregate` |

> **Interview tip:** "Multiple enumeration" — iterating a deferred query twice runs it twice (two DB round trips for EF). Materialise once with `ToList()` if you need it again.

## Lesson: [Basic|High] Filtering, projection and ordering

```csharp
var inStock = products.Where(p => p.Stock > 0);
var withIndex = products.Where((p, i) => i % 2 == 0);           // overload with index

var names = products.Select(p => p.Name);
var dto = products.Select(p => new ProductDto(p.Id, p.Name.ToUpper()));

var sorted = products.OrderBy(p => p.Category)                   // primary sort
                     .ThenByDescending(p => p.Price)             // secondary sort
                     .ToList();

var electronics = products.OfType<Product>().Where(p => p.Category == "Electronics");   // OfType filters by type
```

Calling `OrderBy` twice replaces the first sort — use `ThenBy` for secondary keys. LINQ `OrderBy` is a **stable** sort.

## Lesson: [Basic|High] Element, quantifier and partitioning operators

| Operator | Empty sequence | More than one match |
|---|---|---|
| `First()` | throws | returns first |
| `FirstOrDefault()` | default/null | returns first |
| `Single()` | throws | **throws** |
| `SingleOrDefault()` | default/null | **throws** |
| `Last()` / `LastOrDefault()` | throws / default | returns last |
| `ElementAt(i)` / `ElementAtOrDefault(i)` | throws / default | — |

```csharp
bool anyOut = products.Any(p => p.Stock == 0);     // stops at first match
bool allPriced = products.All(p => p.Price > 0);
bool hasMouse = products.Select(p => p.Name).Contains("Mouse");

var page2 = products.OrderBy(p => p.Id).Skip(10).Take(10);
var whileCheap = products.OrderBy(p => p.Price).TakeWhile(p => p.Price < 10000);
foreach (var batch in products.Chunk(100)) { /* process 100 at a time (.NET 6) */ }
var cheapest = products.MinBy(p => p.Price);       // .NET 6 — returns the element, not the value
```

Use `Any()` instead of `Count() > 0` — `Any` stops at the first element.

# Module: Grouping, Joins and Aggregation

## Lesson: [Intermediate|High] Grouping

```csharp
var byCategory = products
    .GroupBy(p => p.Category)
    .Select(g => new
    {
        Category = g.Key,
        Count = g.Count(),
        TotalValue = g.Sum(p => p.Price * p.Stock),
        MostExpensive = g.MaxBy(p => p.Price)!.Name
    });

// query syntax with 'into'
var q = from p in products
        group p by p.Category into g
        where g.Count() > 1
        select new { g.Key, Avg = g.Average(p => p.Price) };

// group by multiple keys (anonymous type)
var multi = orders.GroupBy(o => new { o.CustomerId, o.OrderDate.Year });

// ToLookup: immediate, re-usable grouping (key -> IEnumerable)
ILookup<string, Product> lookup = products.ToLookup(p => p.Category);
var furniture = lookup["Furniture"];               // empty sequence if key missing (no exception)

// .NET 9 shortcuts
var counts = products.CountBy(p => p.Category);                     // KeyValuePair<string,int>
var totals = products.AggregateBy(p => p.Category, 0m, (sum, p) => sum + p.Price);
```

## Lesson: [Intermediate|High] Joins: inner, left, group join, cross

```csharp
var customers = new[] { new Customer(1, "Acme"), new Customer(2, "Zen"), new Customer(3, "Nova") };
var orders = new[] { new Order(101, 1, 500m), new Order(102, 1, 250m), new Order(103, 2, 900m) };

// INNER JOIN
var inner = customers.Join(orders, c => c.Id, o => o.CustomerId, (c, o) => new { c.Name, o.Id, o.Total });

// query syntax
var inner2 = from c in customers
             join o in orders on c.Id equals o.CustomerId
             select new { c.Name, o.Total };

// LEFT JOIN — classic GroupJoin + SelectMany + DefaultIfEmpty
var left = from c in customers
           join o in orders on c.Id equals o.CustomerId into custOrders
           from o in custOrders.DefaultIfEmpty()
           select new { c.Name, OrderId = o?.Id, Total = o?.Total ?? 0 };

// .NET 10: built-in LeftJoin operator
var left10 = customers.LeftJoin(orders, c => c.Id, o => o.CustomerId, (c, o) => new { c.Name, Total = o?.Total ?? 0 });

// GROUP JOIN — each customer with its orders
var perCustomer = customers.GroupJoin(orders, c => c.Id, o => o.CustomerId,
    (c, os) => new { c.Name, Orders = os.Count(), Sum = os.Sum(o => o.Total) });

// CROSS JOIN
var cross = from size in new[] { "S", "M" } from color in new[] { "Red", "Blue" } select size + color;

record Customer(int Id, string Name);
record Order(int Id, int CustomerId, decimal Total);
```

Query syntax `join` uses `equals` (not `==`) and the outer key must be on the left.

## Lesson: [Intermediate|High] Aggregation and SelectMany

```csharp
int count = products.Count(p => p.Stock > 0);
decimal total = products.Sum(p => p.Price);
decimal avg = products.Average(p => p.Price);
decimal max = products.Max(p => p.Price);            // value
Product priciest = products.MaxBy(p => p.Price)!;    // element (.NET 6)

// Aggregate = fold/reduce
string csv = products.Select(p => p.Name).Aggregate((a, b) => a + "," + b);
int factorial = Enumerable.Range(1, 5).Aggregate(1, (acc, n) => acc * n);    // 120

// SelectMany flattens nested collections
var allLines = orders.SelectMany(o => o.Lines);                      // IEnumerable<Line>
var tags = posts.SelectMany(p => p.Tags).Distinct();
var pairs = customers.SelectMany(c => c.Orders, (c, o) => new { c.Name, o.Id });
```

`Select` → one output per input (can produce `IEnumerable<IEnumerable<T>>`); `SelectMany` → flattens to `IEnumerable<T>`.

## Lesson: [Intermediate|Medium] Set operators and generation

```csharp
int[] a = [1, 2, 3, 4], b = [3, 4, 5];
a.Union(b);        // 1 2 3 4 5  (distinct)
a.Concat(b);       // 1 2 3 4 3 4 5  (keeps duplicates)
a.Intersect(b);    // 3 4
a.Except(b);       // 1 2
a.Distinct();
products.DistinctBy(p => p.Category);                 // .NET 6
customersA.ExceptBy(customersB.Select(c => c.Id), c => c.Id);

Enumerable.Range(1, 10);              // 1..10
Enumerable.Repeat("x", 3);            // x x x
Enumerable.Empty<int>();
a.Zip(b, (x, y) => x * y);            // pairs element-wise
a.Reverse(); a.Append(9); a.Prepend(0);
foreach (var (index, item) in products.Index()) { }   // .NET 9
```

Custom equality for `Distinct/Union/Intersect/Except` on classes: implement `IEquatable<T>` + `GetHashCode`, pass an `IEqualityComparer<T>`, use records, or use the `*By` variants.

# Module: LINQ Internals and EF Core

## Lesson: [Intermediate|High] IEnumerable vs IQueryable

| | `IEnumerable<T>` | `IQueryable<T>` |
|---|---|---|
| Namespace | System.Collections.Generic | System.Linq |
| Lambdas compiled to | Delegates (`Func<T,bool>`) | **Expression trees** (`Expression<Func<T,bool>>`) |
| Execution | In memory (LINQ to Objects) | Translated by a provider (SQL) and run remotely |
| Filtering big tables | Loads everything, filters in RAM | `WHERE` runs in the database |
| Use | Collections already in memory | EF Core `DbSet`s, remote sources |

```csharp
IQueryable<Order> q = db.Orders.Where(o => o.Total > 1000);      // nothing sent yet
q = q.OrderBy(o => o.CreatedAt).Take(20);                         // still composing
Console.WriteLine(q.ToQueryString());                             // see the SQL (EF Core 5+)
var list = await q.ToListAsync();                                 // SELECT TOP(20) ... WHERE Total > 1000 ORDER BY ...

IEnumerable<Order> bad = db.Orders;                               // as IEnumerable
var slow = bad.Where(o => o.Total > 1000).ToList();               // SELECT * FROM Orders, then filter in memory!
```

## Lesson: [Advanced|Medium] Expression trees and dynamic queries

An expression tree is **code as data**: a tree of `Expression` nodes that a provider can inspect and translate.

```csharp
Func<int, bool> del = n => n > 5;                      // compiled code
Expression<Func<int, bool>> expr = n => n > 5;         // data structure
Console.WriteLine(expr.Body);                          // (n > 5)
var compiled = expr.Compile();                         // can still compile and run

// Build a filter dynamically: p => p.Price > minPrice
var param = Expression.Parameter(typeof(Product), "p");
var body = Expression.GreaterThan(Expression.Property(param, nameof(Product.Price)), Expression.Constant(5000m));
var lambda = Expression.Lambda<Func<Product, bool>>(body, param);
var results = db.Products.Where(lambda);

// Simpler: compose conditionally
IQueryable<Product> query = db.Products;
if (category is not null) query = query.Where(p => p.Category == category);
if (minPrice is not null) query = query.Where(p => p.Price >= minPrice);
```

Libraries: `System.Linq.Dynamic.Core` (string-based dynamic LINQ), `LinqKit` (PredicateBuilder for OR conditions).

## Lesson: [Advanced|High] LINQ with EF Core: what translates and common pitfalls

- **Projection** with `Select` into DTOs fetches only needed columns and needs no tracking.
- Methods EF can't translate (your own C# methods) cause an exception (EF Core 3.0+ no longer silently evaluates on the client, except in the final `Select`).
- `Contains` on a local list → `WHERE Id IN (...)` (EF 8+ can send it as a JSON parameter for plan reuse).
- **N+1**: looping over orders and touching `o.Customer` with lazy loading → one query per order. Use `Include` or projection.
- `Count()` vs `Any()`: use `AnyAsync()` for existence.
- `First` without `OrderBy` → nondeterministic order.
- String comparisons follow DB collation (often case-insensitive in SQL Server).
- Use async operators (`ToListAsync`, `FirstOrDefaultAsync`) in web apps.

```csharp
var summaries = await db.Customers
    .Where(c => c.IsActive)
    .Select(c => new CustomerSummary(c.Id, c.Name, c.Orders.Count, c.Orders.Sum(o => (decimal?)o.Total) ?? 0))
    .OrderByDescending(s => s.Total)
    .Take(10)
    .ToListAsync(ct);
```

## Lesson: [Advanced|Medium] Performance and PLINQ

- LINQ to Objects allocates iterators and delegates: fine for most code, measure in hot paths (tight loops over millions of items may prefer `for`/`Span<T>`).
- .NET 7–9 heavily optimised `Sum`, `Min`, `Max`, `Average`, `Order`, `Count` (vectorised for arrays/spans).
- Avoid `Count()` on `IEnumerable` when you only need "any"; prefer `TryGetNonEnumeratedCount`.
- Prefer `HashSet.Contains` over `list.Contains` inside a `Where` (O(1) vs O(n)).
- **PLINQ**: `source.AsParallel().Where(...).Select(...)` uses multiple cores for CPU-bound work on large data; order not preserved unless `AsOrdered()`; not useful for I/O-bound work or small collections.

```csharp
var allowed = new HashSet<int>(allowedIds);
var filtered = items.Where(i => allowed.Contains(i.Id));       // O(n) instead of O(n*m)

var primes = Enumerable.Range(2, 5_000_000).AsParallel().Where(IsPrime).Count();
```

# Interview

## [Beginner|High] What is LINQ and what are its advantages?

LINQ (Language Integrated Query, C# 3.0/.NET 3.5) gives a uniform, strongly typed query syntax for in-memory collections, databases (EF Core), XML and more. Advantages: compile-time checking and IntelliSense, less boilerplate than loops, readable declarative code, composable queries, deferred execution, and one skill across data sources.

## [Beginner|High] What is deferred execution? Which operators execute immediately?

A deferred query isn't executed when defined. It runs each time it is enumerated, so it sees the current data. `Where`, `Select`, `OrderBy`, `GroupBy`, `Skip`/`Take` and `Join` are deferred. `ToList`, `ToArray`, `ToDictionary`, `Count`, `Sum`, `Max`, `First`, `Single`, `Any`, `All` and `Aggregate` execute immediately. Pitfalls: enumerating the same query twice runs it twice; captured variables are read at execution time, not definition time.

## [Beginner|High] What is the difference between First, FirstOrDefault, Single and SingleOrDefault?

`First` returns the first match and throws if there are none. `FirstOrDefault` returns default/null if there are none. `Single` expects **exactly one** match and throws for none or several. `SingleOrDefault` returns default for none and throws for several. Use `Single` when duplicates would indicate a data bug (unique keys). Use `First` with an `OrderBy` for "top 1". In EF, `Single` fetches 2 rows to check uniqueness.

## [Beginner|High] What is the difference between Select and SelectMany?

`Select` projects each element to exactly one result; if the result is a collection you get nested collections. `SelectMany` projects each element to a sequence and **flattens** them into one sequence. Example: `orders.Select(o => o.Lines)` gives `IEnumerable<List<Line>>`, while `orders.SelectMany(o => o.Lines)` gives `IEnumerable<Line>`.

## [Beginner|High] What is the difference between IEnumerable and IQueryable?

`IEnumerable<T>` executes in memory with compiled delegates (LINQ to Objects). `IQueryable<T>` builds an expression tree that a provider (EF Core) translates into SQL and executes in the database. Filtering an `IQueryable` reduces the rows transferred; casting a `DbSet` to `IEnumerable` before `Where` loads the whole table into memory. Keep queries as `IQueryable` until the final materialisation.

## [Beginner|Medium] Query syntax vs method syntax — which is better?

They compile to the same method calls. Query syntax reads like SQL and is convenient for joins, `let` and grouping. Method syntax supports every operator (`Count`, `Distinct`, `Take`, `Any`...) and is more common in codebases. They can be mixed: `(from p in products where p.Stock > 0 select p).Count()`.

## [Intermediate|High] How do you perform a left outer join in LINQ?

Before .NET 10: `GroupJoin` followed by `SelectMany` with `DefaultIfEmpty()`. In query syntax: `join o in orders on c.Id equals o.CustomerId into g from o in g.DefaultIfEmpty() select new { c.Name, Total = o == null ? 0 : o.Total }`. .NET 10 adds a `LeftJoin` operator, and EF Core 10 translates it to `LEFT JOIN`. In EF Core you often don't need explicit joins at all: navigation properties generate them.

## [Intermediate|High] Write a LINQ query to find the second highest salary.

```csharp
var second = employees.Select(e => e.Salary).Distinct()
                      .OrderByDescending(s => s).Skip(1).FirstOrDefault();
// Nth highest: .Skip(n - 1)
// with ties (employees having that salary):
var who = employees.Where(e => e.Salary == second);
```

## [Intermediate|High] How do you group data and get counts or sums per group?

`GroupBy(key)` followed by `Select(g => new { g.Key, Count = g.Count(), Total = g.Sum(x => x.Amount) })`. Group by multiple keys with an anonymous type: `GroupBy(o => new { o.CustomerId, o.Date.Year })`. Filter groups with `Where` after grouping (like SQL `HAVING`). .NET 9 adds `CountBy` and `AggregateBy` for the common cases.

## [Intermediate|High] What is the difference between `Any()` and `Count() > 0`?

`Any()` stops at the first element (O(1) for most sequences); in EF it generates `EXISTS`, which is efficient. `Count()` enumerates everything (for non-collections) or runs `COUNT(*)` over all matching rows. Use `Any()` to check existence. (For `ICollection<T>`, `Count()` uses the `Count` property, but `Any()` is still clearer.)

## [Intermediate|Medium] What is the difference between `ToList()`, `ToArray()`, `ToDictionary()` and `ToLookup()`?

All materialise immediately. `ToList` gives a growable `List<T>`, `ToArray` a fixed array (slightly more compact). `ToDictionary(key)` maps unique keys to values and **throws on duplicate keys**. `ToLookup(key)` groups into a key → many-values structure, allows duplicates, and returns an empty sequence for missing keys.

## [Intermediate|Medium] What is the difference between `Union` and `Concat`? `Distinct` with custom objects?

`Concat` appends one sequence to another, keeping duplicates. `Union` returns distinct elements from both. For classes, `Distinct`/`Union` use default equality (reference equality unless `Equals`/`GetHashCode` are overridden). Use records, implement `IEquatable<T>`, pass an `IEqualityComparer<T>`, or use `DistinctBy`/`UnionBy` (.NET 6).

## [Intermediate|Medium] What does `let` do in query syntax?

It introduces a range variable that stores an intermediate calculation, so you don't repeat it: `from p in products let discounted = p.Price * 0.9m where discounted > 1000 select new { p.Name, discounted }`. It compiles to a `Select` into an anonymous type.

## [Advanced|High] What are expression trees and why does EF Core need them?

An expression tree (`Expression<Func<T,bool>>`) represents code as an inspectable data structure instead of compiled IL. EF Core walks the tree to understand the lambda (`o => o.Total > 1000`) and translate it into SQL. That's why only translatable constructs work in `IQueryable` queries. You can build expression trees dynamically for runtime filters, or compile them into delegates.

## [Advanced|High] What is the N+1 problem in LINQ/EF and how do you fix it?

One query loads N parent rows, then accessing a navigation property per row triggers N extra queries (lazy loading, or querying inside a loop). Fix: eager load with `Include`/`ThenInclude`, project with `Select` into DTOs (one SQL with joins/subqueries), use `AsSplitQuery()` for multiple collection includes, or batch-load children with `Where(x => ids.Contains(x.ParentId))`. Detect it with EF logging, MiniProfiler or Application Insights dependency counts.

## [Advanced|Medium] Why might a LINQ query throw "could not be translated"?

The expression contains something the provider can't convert to SQL: a custom C# method, an unsupported .NET method, complex client-side logic, or certain `GroupBy` shapes. EF Core 3.0+ throws instead of silently evaluating on the client (except in the final projection). Fix: rewrite with translatable operations, move the logic after `AsEnumerable()`/`ToListAsync()` (only after filtering), map a DB function (`HasDbFunction`) or use raw SQL.

## [Advanced|Medium] When would you use PLINQ, and when not?

For CPU-bound operations on large in-memory collections where each element's work is independent (image processing, heavy calculations): `AsParallel()` spreads the work across cores. Not for I/O-bound work (use async with `Task.WhenAll`/`Parallel.ForEachAsync`), small collections (overhead dominates), order-sensitive results (unless `AsOrdered`, which costs), or code with shared mutable state (race conditions).

## [Scenario|High] A report screen calls `db.Orders.ToList().Where(o => o.CustomerId == id)` and is slow with 2 million orders. What's wrong?

`ToList()` executes immediately and loads all 2 million rows into memory, then filters in C#. Move the filter before materialisation: `await db.Orders.Where(o => o.CustomerId == id).Select(o => new OrderDto(...)).ToListAsync()`. The `WHERE` then runs in SQL with an index on `CustomerId`. Add paging and `AsNoTracking`, and project only the needed columns.

## [Scenario|High] Given a list of employees, write LINQ to return each department's highest-paid employee and the department's average salary.

```csharp
var result = employees
    .GroupBy(e => e.Department)
    .Select(g => new
    {
        Department = g.Key,
        TopEarner = g.MaxBy(e => e.Salary)!.Name,
        AverageSalary = g.Average(e => e.Salary),
        Headcount = g.Count()
    })
    .OrderByDescending(x => x.AverageSalary);
```

For ties at the top, use `g.Where(e => e.Salary == g.Max(x => x.Salary))`.

## [Scenario|Medium] Find duplicate emails in a customer list and keep only the first record of each.

```csharp
var duplicates = customers.GroupBy(c => c.Email.ToLowerInvariant())
                          .Where(g => g.Count() > 1)
                          .Select(g => new { Email = g.Key, Count = g.Count() });

var deduped = customers.DistinctBy(c => c.Email.ToLowerInvariant()).ToList();   // keeps first occurrence
// pre-.NET 6: customers.GroupBy(c => c.Email).Select(g => g.First())
```

## [Scenario|Medium] A method returns `IEnumerable<Order>` from a DB query, and two `foreach` loops over it hit the database twice. Why, and how do you fix it?

The method returns a deferred query, so each enumeration executes it again (two SQL round trips, possibly different results). Materialise once with `ToList()`/`ToListAsync()`, and return `IReadOnlyList<Order>` to make it explicit. Analyzers (CA1851, ReSharper's "possible multiple enumeration") warn about this.

## Deferred vs immediate

Deferred: returns `IEnumerable`/`IQueryable`. Immediate: returns a value, collection or element.

## IEnumerable vs IQueryable

Delegates, in memory vs expression trees, translated to SQL. Keep `IQueryable` until `ToListAsync()`.

```csharp
list.OrderByDescending(x => x.Salary).Skip(1).First();          // 2nd highest
list.GroupBy(x => x.Dept).Select(g => new { g.Key, C = g.Count() });
list.GroupBy(x => x.Email).Where(g => g.Count() > 1);            // duplicates
from c in cs join o in os on c.Id equals o.CId into g from o in g.DefaultIfEmpty() select ...;  // left join
words.GroupBy(w => w).ToDictionary(g => g.Key, g => g.Count());  // word frequency
string.Join(",", list.Select(x => x.Name));
nested.SelectMany(x => x.Items);
```

## Pitfalls

`ToList()` too early · multiple enumeration · `Count() > 0` instead of `Any()` · `First` without `OrderBy` · N+1 with lazy loading · untranslatable methods in `IQueryable` · `list.Contains` in loops (use `HashSet`).
