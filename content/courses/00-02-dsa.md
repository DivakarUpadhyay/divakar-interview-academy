# Overview

A **data structure** is a way to organise data in memory; an **algorithm** is a step-by-step procedure to solve a problem using it. The right choice is the difference between a page that loads in 50 ms and one that times out.

| Need | Data structure | .NET type | Used inside |
|---|---|---|---|
| Ordered list, index access | Dynamic array | `List<T>`, `T[]` | Almost everything |
| Fast lookup by key | Hash table | `Dictionary<K,V>`, `HashSet<T>` | Caches, EF Core change tracker, ASP.NET routing tables |
| Last-in-first-out | Stack | `Stack<T>` | Call stack, undo, expression parsing |
| First-in-first-out | Queue | `Queue<T>`, `Channel<T>` | Thread pool work queue, message queues |
| Sorted data, range queries | Balanced tree / B-tree | `SortedDictionary` (red-black tree), `SortedSet` | **SQL Server indexes (B+ trees)**, file systems |
| Smallest/largest first | Heap | `PriorityQueue<T,P>` | Schedulers, Dijkstra, top-K |
| Prefix search | Trie | — (custom) | Autocomplete, routers |
| Relationships | Graph | adjacency lists | Social networks, maps, dependency resolution (DI containers, NuGet) |

# Lifecycle

**How to solve an algorithm problem (interview or real work):**

1. **Understand** — restate the problem, inputs, outputs, constraints (n up to 10⁵? sorted? duplicates? negative numbers?).
2. **Examples** — work through a small case by hand, including edge cases (empty, one element, all same).
3. **Brute force** — say the simplest solution and its complexity.
4. **Optimise** — look for a better data structure (hash map, heap, sorting first) or pattern (two pointers, sliding window, BFS, DP).
5. **Code** — clean, with meaningful names.
6. **Test** — run your examples and edge cases through the code.
7. **Analyse** — state time and space complexity; mention trade-offs.

# Module: Measuring Algorithms

## Lesson: [Basic|High] Big-O notation — time and space complexity

**Big-O** describes how the running time (or memory) grows as the input size *n* grows, ignoring constants.

| Big-O | Name | Example | n = 1,000,000 → roughly |
|---|---|---|---|
| O(1) | Constant | Array index, dictionary lookup | 1 step |
| O(log n) | Logarithmic | Binary search, B-tree index seek | 20 steps |
| O(n) | Linear | Loop over a list, table scan | 1,000,000 |
| O(n log n) | Linearithmic | Good sorting (merge, heap, quick average) | 20,000,000 |
| O(n²) | Quadratic | Nested loops over the same data, bubble sort | 10¹² — too slow |
| O(2ⁿ) | Exponential | All subsets, naive Fibonacci | impossible |
| O(n!) | Factorial | All permutations | impossible |

```csharp
bool ContainsDuplicate_N2(int[] a)            // O(n²) time, O(1) space
{
    for (int i = 0; i < a.Length; i++)
        for (int j = i + 1; j < a.Length; j++)
            if (a[i] == a[j]) return true;
    return false;
}

bool ContainsDuplicate_N(int[] a)             // O(n) time, O(n) space — trade memory for speed
{
    var seen = new HashSet<int>();
    foreach (var x in a) if (!seen.Add(x)) return true;
    return false;
}
```

Rules: drop constants (O(2n) → O(n)); keep the dominant term (O(n² + n) → O(n²)); different inputs get different letters (O(a + b), O(a × b)); **amortised** O(1) means usually O(1), occasionally more (e.g. `List<T>.Add` when it must grow).

Best / average / worst case: quicksort is O(n log n) on average but O(n²) in the worst case; hash lookups are O(1) average, O(n) worst (all keys collide).

# Module: Linear Data Structures

## Lesson: [Basic|High] Arrays and dynamic arrays (how List<T> grows)

An **array** is a contiguous block of memory: element *i* is at `start + i × elementSize`, so index access is O(1) and iteration is cache-friendly. Size is fixed.

A **dynamic array** (`List<T>`) wraps an array and grows when full:

```text
Capacity 4: [a][b][c][d]        Add(e) → no room
Allocate capacity 8, copy 4 items: [a][b][c][d][e][ ][ ][ ]
```

Doubling makes `Add` **amortised O(1)**: n adds cost about 2n copies in total.

| Operation | Array / List<T> |
|---|---|
| Get/set by index | O(1) |
| Add at end | O(1) amortised |
| Insert/remove at start or middle | O(n) — shift elements |
| Search unsorted | O(n) |
| Search sorted (binary search) | O(log n) |

```csharp
var list = new List<int>(capacity: 10_000);   // pre-size when you know the count → no re-allocations
```

## Lesson: [Basic|High] Linked lists, stacks and queues

**Linked list:** nodes scattered in memory, each pointing to the next (and previous, in a doubly linked list).

```csharp
public class Node<T>(T value) { public T Value = value; public Node<T>? Next; }

Node<int>? Reverse(Node<int>? head)            // classic interview question — O(n) time, O(1) space
{
    Node<int>? prev = null;
    while (head != null)
    {
        var next = head.Next;
        head.Next = prev;      // flip the pointer
        prev = head;
        head = next;
    }
    return prev;
}
```

| | Array/List | Linked list |
|---|---|---|
| Index access | O(1) | O(n) |
| Insert/delete at a known node | O(n) shift | O(1) relink |
| Memory | Compact, cache-friendly | Extra pointer per node, cache misses |

**Stack** (LIFO) and **queue** (FIFO) are usually built on arrays (circular buffer for queues):

```csharp
bool IsBalanced(string s)                    // stack: matching brackets
{
    var stack = new Stack<char>();
    var pairs = new Dictionary<char, char> { [')'] = '(', [']'] = '[', ['}'] = '{' };
    foreach (char c in s)
    {
        if (c is '(' or '[' or '{') stack.Push(c);
        else if (pairs.TryGetValue(c, out var open) && (stack.Count == 0 || stack.Pop() != open)) return false;
    }
    return stack.Count == 0;
}
```

The **call stack** is literally a stack of frames; **recursion** uses it, which is why deep recursion overflows it.

## Lesson: [Intermediate|High] Hash tables — how Dictionary works inside

A **hash table** maps a key to a slot ("bucket") using a **hash function**:

```text
key "pen" → GetHashCode() = 193410 → 193410 % 8 buckets = bucket 2 → entry ("pen", 10)
```

Steps for `dict["pen"]`:

1. Compute `hash = key.GetHashCode()`.
2. `bucket = hash % bucketCount`.
3. Walk the entries in that bucket comparing hashes and then `Equals` until found.

**Collisions** (two keys in the same bucket) are inevitable. Strategies: **chaining** (each bucket holds a small list — .NET `Dictionary` uses chaining through an entries array) or **open addressing** (probe the next free slot). When the table fills up (load factor), it **resizes** to a larger prime size and re-hashes everything — O(n) once, amortised O(1).

Why `Equals` and `GetHashCode` must agree: if two equal keys produce different hashes, they land in different buckets and lookups fail. If a key's hash changes after insertion (mutable key), the entry becomes unreachable.

```csharp
public record ProductKey(string Sku, int Warehouse);   // records implement value-based Equals/GetHashCode
var stock = new Dictionary<ProductKey, int> { [new("PEN-1", 3)] = 50 };
Console.WriteLine(stock[new("PEN-1", 3)]);            // 50 — found because equal keys hash equally
```

Classic use — **two-sum in O(n)**:

```csharp
int[] TwoSum(int[] nums, int target)
{
    var seen = new Dictionary<int, int>();           // value → index
    for (int i = 0; i < nums.Length; i++)
    {
        if (seen.TryGetValue(target - nums[i], out int j)) return [j, i];
        seen[nums[i]] = i;
    }
    return [];
}
```

# Module: Trees, Heaps and Graphs

## Lesson: [Intermediate|High] Trees, binary search trees and traversals

A **tree** is nodes connected parent → children with no cycles. A **binary search tree (BST)** keeps `left < node < right`, so search, insert and delete are O(height): O(log n) when balanced, O(n) when it degenerates into a line (inserting sorted data).

```csharp
public class TreeNode(int val) { public int Val = val; public TreeNode? Left, Right; }

bool Contains(TreeNode? n, int x) =>
    n != null && (x == n.Val || (x < n.Val ? Contains(n.Left, x) : Contains(n.Right, x)));

void InOrder(TreeNode? n, List<int> output)   // left, node, right → sorted order for a BST
{
    if (n == null) return;
    InOrder(n.Left, output); output.Add(n.Val); InOrder(n.Right, output);
}

int Height(TreeNode? n) => n == null ? 0 : 1 + Math.Max(Height(n.Left), Height(n.Right));

List<List<int>> LevelOrder(TreeNode? root)    // BFS with a queue
{
    var result = new List<List<int>>();
    if (root == null) return result;
    var q = new Queue<TreeNode>([root]);
    while (q.Count > 0)
    {
        var level = new List<int>();
        for (int size = q.Count; size > 0; size--)
        {
            var n = q.Dequeue();
            level.Add(n.Val);
            if (n.Left != null) q.Enqueue(n.Left);
            if (n.Right != null) q.Enqueue(n.Right);
        }
        result.Add(level);
    }
    return result;
}
```

Traversals: **pre-order** (node, left, right — copy a tree), **in-order** (sorted output), **post-order** (children first — delete a tree, evaluate expressions), **level-order/BFS**.

**Balanced trees** keep height O(log n) automatically: AVL, **red-black** (.NET `SortedDictionary`/`SortedSet`), and **B-trees/B+ trees** — very wide trees (hundreds of keys per node) designed for disks. **SQL Server indexes are B+ trees**: an index seek on a table of 10 million rows touches only 3–4 pages (root → intermediate → leaf).

## Lesson: [Intermediate|Medium] Heaps and priority queues, tries

A **binary heap** is a complete binary tree stored in an array where every parent ≤ its children (min-heap). The smallest item is always at index 0.

| Operation | Cost |
|---|---|
| Peek min | O(1) |
| Insert (bubble up) | O(log n) |
| Remove min (move last to top, sift down) | O(log n) |
| Build from n items | O(n) |

Array layout: children of index *i* are at `2i+1` and `2i+2`, parent at `(i−1)/2` — no pointers needed.

```csharp
// Top-K largest numbers in O(n log k) with a min-heap of size k
int[] TopK(int[] nums, int k)
{
    var heap = new PriorityQueue<int, int>();
    foreach (var n in nums)
    {
        heap.Enqueue(n, n);
        if (heap.Count > k) heap.Dequeue();   // drop the smallest
    }
    return heap.UnorderedItems.Select(x => x.Element).ToArray();
}
```

A **trie** (prefix tree) stores strings character by character; finding all words with a prefix costs O(length of prefix) — autocomplete and routing tables.

```csharp
public class Trie
{
    private sealed class Node { public Dictionary<char, Node> Next = []; public bool End; }
    private readonly Node _root = new();
    public void Insert(string word)
    {
        var node = _root;
        foreach (var c in word)
        {
            if (!node.Next.TryGetValue(c, out var child)) node.Next[c] = child = new Node();
            node = child;
        }
        node.End = true;
    }
    public bool StartsWith(string prefix)
    {
        var node = _root;
        foreach (var c in prefix)
        {
            if (!node.Next.TryGetValue(c, out var child)) return false;
            node = child;
        }
        return true;
    }
}
```

## Lesson: [Intermediate|High] Graphs — BFS, DFS and shortest paths

A **graph** is vertices connected by edges (directed or undirected, weighted or not). Store it as an **adjacency list** (`Dictionary<int, List<int>>`) — memory O(V + E).

```csharp
// BFS: shortest path in an unweighted graph (fewest hops)
int ShortestHops(Dictionary<int, List<int>> g, int start, int goal)
{
    var dist = new Dictionary<int, int> { [start] = 0 };
    var q = new Queue<int>([start]);
    while (q.Count > 0)
    {
        int u = q.Dequeue();
        if (u == goal) return dist[u];
        foreach (int v in g.GetValueOrDefault(u, []))
            if (dist.TryAdd(v, dist[u] + 1)) q.Enqueue(v);
    }
    return -1;
}

// DFS: count islands in a grid (connected components)
int Islands(char[][] grid)
{
    int count = 0;
    void Sink(int r, int c)
    {
        if (r < 0 || c < 0 || r >= grid.Length || c >= grid[0].Length || grid[r][c] != '1') return;
        grid[r][c] = '0';
        Sink(r + 1, c); Sink(r - 1, c); Sink(r, c + 1); Sink(r, c - 1);
    }
    for (int r = 0; r < grid.Length; r++)
        for (int c = 0; c < grid[0].Length; c++)
            if (grid[r][c] == '1') { count++; Sink(r, c); }
    return count;
}
```

| Algorithm | Solves | Complexity |
|---|---|---|
| BFS | Shortest path (unweighted), level by level | O(V + E) |
| DFS | Connectivity, cycle detection, paths, backtracking | O(V + E) |
| **Dijkstra** (with a heap) | Shortest path with non-negative weights (maps, routing) | O((V + E) log V) |
| Topological sort | Order tasks with dependencies (build systems, DI, course prerequisites) | O(V + E) |
| Union-Find | Grouping/connected components quickly | ~O(1) per operation |

# Module: Searching and Sorting

## Lesson: [Basic|High] Binary search and how sorting algorithms work

**Binary search** — on sorted data, halve the range each step: O(log n).

```csharp
int BinarySearch(int[] a, int target)
{
    int lo = 0, hi = a.Length - 1;
    while (lo <= hi)
    {
        int mid = lo + (hi - lo) / 2;         // avoids int overflow of (lo + hi)
        if (a[mid] == target) return mid;
        if (a[mid] < target) lo = mid + 1; else hi = mid - 1;
    }
    return -1;
}
```

**Sorting algorithms:**

| Algorithm | Idea | Best / Avg / Worst | Space | Stable |
|---|---|---|---|---|
| Bubble | Swap adjacent out-of-order pairs repeatedly | n / n² / n² | 1 | Yes |
| Selection | Pick the minimum, put it in front | n² / n² / n² | 1 | No |
| Insertion | Insert each item into the sorted left part | n / n² / n² | 1 | Yes — great for small/nearly sorted |
| **Merge** | Split in halves, sort each, merge | n log n (all) | n | Yes |
| **Quick** | Pick a pivot, partition smaller/larger, recurse | n log n / n log n / n² | log n | No |
| **Heap** | Build a heap, extract max repeatedly | n log n (all) | 1 | No |
| Counting/Radix | Count occurrences of small integer keys | n + k | n + k | Yes |

```csharp
void QuickSort(int[] a, int lo, int hi)
{
    if (lo >= hi) return;
    int pivot = a[(lo + hi) / 2], i = lo, j = hi;
    while (i <= j)
    {
        while (a[i] < pivot) i++;
        while (a[j] > pivot) j--;
        if (i <= j) { (a[i], a[j]) = (a[j], a[i]); i++; j--; }
    }
    QuickSort(a, lo, j); QuickSort(a, i, hi);
}

int[] MergeSort(int[] a)
{
    if (a.Length <= 1) return a;
    var left = MergeSort(a[..(a.Length / 2)]);
    var right = MergeSort(a[(a.Length / 2)..]);
    var result = new int[a.Length];
    int l = 0, r = 0, k = 0;
    while (l < left.Length && r < right.Length) result[k++] = left[l] <= right[r] ? left[l++] : right[r++];
    while (l < left.Length) result[k++] = left[l++];
    while (r < right.Length) result[k++] = right[r++];
    return result;
}
```

In practice: `Array.Sort`/`List.Sort` use **introsort** (quicksort, switching to heapsort if recursion gets too deep and insertion sort for small parts — unstable); LINQ `OrderBy` is a **stable** sort. SQL Server sorts in memory or spills to tempdb when the memory grant is too small.

# Module: Problem-Solving Patterns

## Lesson: [Intermediate|High] Recursion, two pointers and sliding window

**Recursion** = a function calling itself with a smaller input until a **base case**. Every recursion uses stack space; convert to iteration when depth may be large.

```csharp
long Factorial(int n) => n <= 1 ? 1 : n * Factorial(n - 1);
```

**Two pointers** — walk from both ends or at two speeds, O(n) instead of O(n²):

```csharp
bool IsPalindrome(string s)
{
    int i = 0, j = s.Length - 1;
    while (i < j)
    {
        if (!char.IsLetterOrDigit(s[i])) { i++; continue; }
        if (!char.IsLetterOrDigit(s[j])) { j--; continue; }
        if (char.ToLowerInvariant(s[i++]) != char.ToLowerInvariant(s[j--])) return false;
    }
    return true;
}
// Fast/slow pointers detect a cycle in a linked list (Floyd's algorithm).
```

**Sliding window** — maintain a window over a sequence and move its edges:

```csharp
int LongestUniqueSubstring(string s)          // "abcabcbb" → 3
{
    var lastSeen = new Dictionary<char, int>();
    int best = 0, start = 0;
    for (int end = 0; end < s.Length; end++)
    {
        if (lastSeen.TryGetValue(s[end], out int prev) && prev >= start) start = prev + 1;
        lastSeen[s[end]] = end;
        best = Math.Max(best, end - start + 1);
    }
    return best;
}
```

Other patterns: prefix sums (range sums in O(1)), binary search on the answer, monotonic stack (next greater element), intervals (sort by start, merge).

## Lesson: [Advanced|High] Greedy, dynamic programming and backtracking

**Greedy** — make the locally best choice each step; works when that provably leads to the global best (activity selection, coin change with standard coins, Dijkstra, Huffman coding).

**Dynamic programming (DP)** — the problem has **overlapping subproblems** and **optimal substructure**; store answers to subproblems instead of recomputing.

```csharp
// Fibonacci: naive recursion O(2ⁿ) → DP O(n)
long Fib(int n)
{
    if (n < 2) return n;
    long a = 0, b = 1;
    for (int i = 2; i <= n; i++) (a, b) = (b, a + b);
    return b;
}

// Coin change: fewest coins to make an amount (bottom-up table)
int MinCoins(int[] coins, int amount)
{
    var dp = new int[amount + 1];
    Array.Fill(dp, int.MaxValue); dp[0] = 0;
    for (int x = 1; x <= amount; x++)
        foreach (int c in coins)
            if (c <= x && dp[x - c] != int.MaxValue) dp[x] = Math.Min(dp[x], dp[x - c] + 1);
    return dp[amount] == int.MaxValue ? -1 : dp[amount];
}
```

Approach: define the state (`dp[i]` = answer for the first i items/amount i), the transition (how `dp[i]` uses smaller states), base cases, and the order of filling. Top-down = recursion + memo (`Dictionary` cache); bottom-up = table.

**Backtracking** — build candidates step by step and undo choices that can't lead to a solution (permutations, subsets, N-Queens, Sudoku):

```csharp
List<List<int>> Subsets(int[] nums)
{
    var result = new List<List<int>>();
    void Go(int i, List<int> current)
    {
        if (i == nums.Length) { result.Add([.. current]); return; }
        Go(i + 1, current);                    // skip nums[i]
        current.Add(nums[i]); Go(i + 1, current); current.RemoveAt(current.Count - 1);   // take it, then undo
    }
    Go(0, []);
    return result;
}
```

# Interview

## [Beginner|High] What is Big-O notation? Give examples.

It describes how an algorithm's time or memory grows with input size n, ignoring constants and smaller terms. O(1) dictionary lookup, O(log n) binary search, O(n) one loop, O(n log n) good sorts, O(n²) nested loops over the same data, O(2ⁿ) all subsets. It lets you predict whether a solution scales — e.g. O(n²) on a million items is ~10¹² operations, too slow.

## [Beginner|High] Array vs linked list — when do you use each?

Arrays (and `List<T>`) store elements contiguously: O(1) index access, cache-friendly iteration, but O(n) inserts/removes in the middle. Linked lists store nodes with pointers: O(1) insert/remove at a known node, but O(n) access by position and poor cache locality. In practice `List<T>` wins most of the time; linked lists suit frequent middle insertions with a node reference (LRU caches pair a linked list with a dictionary).

## [Beginner|High] How does a hash table (Dictionary) work?

It computes the key's hash code, maps it to a bucket (`hash % size`), and stores the entry there; lookups recompute the hash, go to the bucket and compare with `Equals`. Collisions are handled by chaining or probing; when the load factor grows, it resizes and rehashes. Average O(1) insert/lookup/delete, worst O(n) if many keys collide. Keys must have consistent `Equals`/`GetHashCode` and shouldn't change while stored.

## [Beginner|High] Stack vs queue — examples of where each is used?

Stack is LIFO: function call stack, undo/redo, browser back button, expression evaluation, DFS. Queue is FIFO: print jobs, request/message queues, thread-pool work items, BFS. Both have O(1) push/pop or enqueue/dequeue.

## [Beginner|High] Explain binary search. What is required to use it?

The data must be sorted. Compare the target with the middle element; if smaller, search the left half, otherwise the right half; repeat until found or the range is empty — O(log n). Compute the middle as `lo + (hi - lo) / 2` to avoid overflow. Database index seeks work on the same principle over B-tree pages.

## [Intermediate|High] Compare quicksort and merge sort.

Both average O(n log n). Merge sort is always O(n log n), stable, but needs O(n) extra memory — good for linked lists and external sorting of huge data. Quicksort sorts in place (O(log n) stack), is usually faster in practice thanks to cache locality, but is O(n²) in the worst case with bad pivots and is not stable. .NET's `Array.Sort` uses introsort to avoid the worst case.

## [Intermediate|High] What is a binary search tree? What happens if it becomes unbalanced?

A binary tree where every node's left subtree has smaller keys and right subtree larger keys, so search/insert/delete follow one path: O(height). Balanced height is log n; inserting sorted data into a plain BST makes it a linked list with O(n) operations. Self-balancing trees (AVL, red-black) and B-trees keep the height logarithmic — SQL Server indexes are B+ trees.

## [Intermediate|High] BFS vs DFS?

BFS explores level by level using a queue — finds the shortest path in unweighted graphs, uses memory proportional to the widest level. DFS goes as deep as possible using recursion or a stack — good for connectivity, cycle detection, topological sort and backtracking, uses memory proportional to depth. Both are O(V + E).

## [Intermediate|High] What is dynamic programming? How is it different from recursion?

DP solves problems with overlapping subproblems and optimal substructure by storing subproblem results (memoisation top-down, or a table bottom-up) so each is computed once. Plain recursion may recompute the same subproblem exponentially many times (naive Fibonacci O(2ⁿ) vs DP O(n)). Typical DP problems: coin change, knapsack, longest common subsequence, edit distance, climbing stairs.

## [Intermediate|Medium] What is a heap and what is it used for?

A complete binary tree stored in an array where each parent is smaller (min-heap) or larger (max-heap) than its children. Peek min/max O(1), insert and remove O(log n). Used for priority queues (`PriorityQueue<T,P>`), scheduling, top-K problems, merging sorted streams, Dijkstra's algorithm and heapsort.

## [Intermediate|Medium] What are greedy algorithms? When do they fail?

They pick the locally best option at each step without revisiting. They are correct only when the problem has the greedy-choice property — e.g. activity selection, Dijkstra, Huffman coding. They fail on problems like coin change with arbitrary coins (coins 1, 3, 4 for amount 6: greedy gives 4+1+1, optimal is 3+3), where DP is needed.

## [Advanced|Medium] How does a B-tree differ from a binary search tree and why do databases use it?

A B-tree node holds many keys and has many children (high fan-out), so the tree is very shallow — a few levels cover millions of rows. Each node maps to a disk/database page (8 KB in SQL Server), so a lookup reads only a handful of pages. B+ trees keep all data/rows at the leaf level and link leaves for fast range scans. Binary trees would be far deeper and cause many more page reads.

## [Advanced|Medium] How would you implement an LRU cache with O(1) operations?

Combine a dictionary (key → linked-list node) with a doubly linked list ordered by recent use. Get: look up the node in the dictionary, move it to the front. Put: update/move to front, or insert at the front; if over capacity, remove the tail node and its dictionary entry. Both operations are O(1). In .NET, `LinkedList<T>` + `Dictionary<K, LinkedListNode<T>>`.

## [Scenario|High] A report compares two lists of 200,000 customer ids with nested loops and takes 20 minutes. Fix it.

Nested loops are O(n × m) ≈ 4 × 10¹⁰ comparisons. Put one list into a `HashSet<int>` (O(m)) and check each id of the other list with `Contains` (O(1) average) — O(n + m), milliseconds. Or sort both and merge with two pointers (O(n log n)), or let SQL do it with an indexed JOIN/EXISTS.

## [Scenario|High] An autocomplete box queries `WHERE Name LIKE '%term%'` on 5 million products and is slow. How would you improve it?

A leading wildcard can't use a B-tree index, so every keystroke scans the table. Options: prefix search `LIKE 'term%'` on an indexed column (index seek), a trie or sorted in-memory list of names for prefix lookups, full-text search (SQL Server full-text index, Azure AI Search, Elasticsearch) for word matches, debounce keystrokes and limit to top 10, cache popular prefixes.

## [Scenario|Medium] You need the 10 most frequent error codes from 50 million log lines. What algorithm?

Stream the lines once, counting with a `Dictionary<string, int>` (O(n) time, O(k) memory for k distinct codes), then select the top 10 with a min-heap of size 10 (O(k log 10)) or sort the k entries. Don't load all lines into memory. For distributed data, count per partition and merge counts (map-reduce).

# Cheatsheet

## Complexity ladder

O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!). For n = 10⁶: O(n log n) OK, O(n²) not.

## Pick the structure

Index access → array/List · key lookup → Dictionary/HashSet · LIFO → Stack · FIFO → Queue · min/max fast → PriorityQueue · sorted + range → SortedDictionary / B-tree index · prefix → Trie · relationships → graph adjacency list.

## Sorting facts

Merge: n log n always, stable, O(n) space. Quick: n log n avg, n² worst, in place. Heap: n log n, O(1) space. Insertion: great for tiny/nearly sorted. .NET `Array.Sort` = introsort (unstable); LINQ `OrderBy` = stable.

## Patterns

Two pointers · sliding window · prefix sums · binary search (also on the answer) · BFS (shortest unweighted) · DFS/backtracking · heap for top-K · hash map for counting/lookups · DP for overlapping subproblems · greedy when locally optimal is globally optimal.

## Interview method

Clarify → examples → brute force + Big-O → optimise → code → test edge cases → state time/space.
