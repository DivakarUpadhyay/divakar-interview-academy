# Overview

**SSRS (SQL Server Reporting Services)** is Microsoft's server-based platform for **paginated reports** — pixel-perfect, printable reports (invoices, statements, operational lists) that page nicely to PDF, Excel, Word or print.

Components:

| Component | Role |
|---|---|
| **Report Designer** (Visual Studio Reporting Services Projects) / **Report Builder** | Author `.rdl` reports |
| **Report Server** (Windows service) | Processes and renders reports, runs subscriptions |
| **ReportServer** + **ReportServerTempDB** databases | Catalog (reports, data sources, security, schedules) and session/cache data |
| **Web portal** (`/Reports`) | Browse, run, manage reports, KPIs, mobile reports (retired in 2022) |
| **Web service** (`/ReportServer`) | SOAP/REST APIs, URL access |
| **Report Server Configuration Manager** | Configure URLs, service account, DB, email, encryption keys |

Report definitions are **RDL** (Report Definition Language) XML files. Shared data sources (`.rds`) and shared datasets (`.rsd`) are reusable.

**Paginated vs interactive:** SSRS/paginated reports are for fixed-layout operational output; **Power BI** reports are for interactive analytics and dashboards. **Power BI Report Server** (on-prem) hosts both. Power BI Service also hosts paginated reports.

# Lifecycle

**Report development lifecycle:** requirements (layout, parameters, audience, delivery) → design data model/queries (stored procedures preferred) → create data source and datasets → design layout (tablix, groups, charts) → add parameters and expressions → preview/test (accuracy, page breaks, export formats) → deploy to the report server (dev → test → prod) → configure security, caching, snapshots, subscriptions → monitor execution log → maintain.

**Report processing lifecycle (when a user runs a report):**

1. **Request** arrives via web portal or URL with parameters.
2. **Authentication/authorisation** — Windows (or custom/forms) authentication; role assignments checked on the item.
3. **Data processing** — the report processor executes dataset queries against data sources (unless served from cache/snapshot).
4. **Report processing** — combines data with the layout: grouping, sorting, aggregates, expressions → an intermediate format.
5. **Rendering** — the requested renderer produces HTML, PDF, Excel, Word, CSV, XML, TIFF/image, PowerPoint.
6. **Delivery** — returned to the browser, or for subscriptions emailed / written to a file share / SharePoint.
7. **Logging** — execution details go to `ExecutionLog3` (time in data retrieval vs processing vs rendering).

**Expression evaluation order** matters for things like `RunningValue`, page headers (can't reference dataset fields directly — use `ReportItems!TextboxName.Value`) and visibility.

# Module: Building Reports

## Lesson: [Basic|High] Data sources and datasets

- **Data source** — connection info (SQL Server, Azure SQL, Analysis Services, Oracle, ODBC, OLE DB, XML, SharePoint lists). **Shared** data sources live on the server and are reused; **embedded** ones live in one report.
- **Credentials**: Windows integrated (Kerberos needed for double-hop), stored credentials (required for subscriptions and caching), prompt user, none.
- **Dataset** — a query (text or **stored procedure**) + fields + parameters + filters. **Shared datasets** can be cached and reused across reports.

```sql
CREATE OR ALTER PROCEDURE rpt.usp_SalesByRegion @StartDate DATE, @EndDate DATE, @RegionIds VARCHAR(MAX)
AS
SELECT r.RegionName, p.Category, SUM(s.Amount) AS Amount, COUNT(*) AS Orders
FROM dbo.Sales s
JOIN dbo.Regions r ON r.RegionId = s.RegionId
JOIN dbo.Products p ON p.ProductId = s.ProductId
WHERE s.SaleDate >= @StartDate AND s.SaleDate < DATEADD(DAY, 1, @EndDate)
  AND s.RegionId IN (SELECT value FROM STRING_SPLIT(@RegionIds, ','))
GROUP BY r.RegionName, p.Category;
```

Best practice: keep heavy logic in SQL (stored procedures/views), return only the rows and columns the report shows.

## Lesson: [Basic|High] Report items: tablix, table, matrix, list, charts

- **Tablix** is the underlying data region; it appears as:
  - **Table** — fixed columns, dynamic rows (detail lists with row groups).
  - **Matrix** — dynamic rows **and** columns (cross-tab/pivot: regions × months).
  - **List** — free-form repeating layout (cards, labels, letters).
- **Chart**, **Gauge**, **Map**, **Data bar**, **Sparkline**, **Indicator**.
- **Textbox**, **Image**, **Rectangle** (container), **Line**, **Subreport**.
- **Header/Footer** — page numbers (`Globals!PageNumber`, `Globals!TotalPages`), title, run time (`Globals!ExecutionTime`).

## Lesson: [Basic|High] Grouping, sorting, totals and page breaks

- Row groups and column groups (parent/child/adjacent), with group headers/footers for subtotals.
- Group expressions like `=Fields!Region.Value`; sorting per group; **interactive sort** on column headers.
- Totals: right-click group → Add Total (Before/After).
- **Page breaks** between group instances (e.g. one region per page), repeat header rows on each page (`RepeatOnNewPage` via Advanced Mode in the Grouping pane), `KeepTogether`.
- **Recursive hierarchy** (parent-child data, e.g. org chart) using a group with a **recursive parent** and `Level()` for indentation.

## Lesson: [Intermediate|High] Expressions and built-in collections

Expressions start with `=` and use VB.NET syntax.

```vb
=Fields!Amount.Value                                 ' field
=Sum(Fields!Amount.Value)                            ' aggregate in current scope
=Sum(Fields!Amount.Value, "RegionGroup")             ' aggregate in a named scope
=Fields!Amount.Value / Sum(Fields!Amount.Value, "DataSet1")      ' % of total
=IIf(Fields!Amount.Value < 0, "Red", "Black")        ' conditional formatting (Color property)
=Switch(Fields!Score.Value >= 90, "A", Fields!Score.Value >= 75, "B", True, "C")
=Format(Fields!SaleDate.Value, "dd-MMM-yyyy")
=RunningValue(Fields!Amount.Value, Sum, "RegionGroup")
=RowNumber(Nothing)
=IIf(RowNumber(Nothing) Mod 2 = 0, "WhiteSmoke", "White")     ' green-bar (alternating) rows
=Lookup(Fields!ProductId.Value, Fields!ProductId.Value, Fields!Name.Value, "ProductsDS")   ' join another dataset
=Parameters!Region.Label                             ' parameter display text
=Globals!PageNumber & " of " & Globals!TotalPages
=User!UserID                                         ' current user
=Join(Parameters!Regions.Label, ", ")                ' multi-value parameter labels
```

Built-in collections: `Fields`, `Parameters`, `Globals`, `User`, `ReportItems`, `DataSources`, `DataSets`, `Variables`. Custom code: `Report Properties → Code` (VB functions called as `Code.MyFunction(...)`) or custom assemblies.

`Lookup`, `LookupSet` and `MultiLookup` (2008 R2+) join datasets in the report — useful when data comes from two sources.

# Module: Parameters and Interactivity

## Lesson: [Intermediate|High] Parameters, multi-value and cascading parameters

- **Report parameters** map to **query parameters** (`@StartDate`).
- Data types: Text, Boolean, Date/Time, Integer, Float. Allow null/blank, **multi-value**, hidden, internal.
- **Available values** from a dataset (drop-down) and **default values** (static, expression like `=Today()`, or a dataset).
- **Multi-value**: in an embedded SQL query `WHERE RegionId IN (@Regions)` works automatically; for a **stored procedure**, pass `=Join(Parameters!Regions.Value, ",")` and split it in SQL (`STRING_SPLIT`).
- **Cascading parameters** — the second parameter's available-values dataset uses the first (Country → State → City). Order matters in the parameter list.

```sql
-- dataset for the State parameter (depends on @Country)
SELECT StateId, StateName FROM dbo.States WHERE CountryId = @Country ORDER BY StateName;
```

## Lesson: [Intermediate|High] Drill-down, drill-through, subreports and document maps

| Feature | What | How |
|---|---|---|
| **Drill-down** | Expand/collapse detail rows in the same report | Group visibility hidden, toggled by a textbox (`+/-`) |
| **Drill-through** | Click → open **another report** with parameters | Textbox Action → *Go to report* + parameter mapping |
| **Subreport** | Embed a report inside another, executed per row/group | Subreport item + parameters (can be slow for many rows) |
| **Go to URL** | Open a web page | Action → *Go to URL* with an expression |
| **Bookmark / Document map** | Navigation within a long report | Bookmark action; Document map label on groups |

Prefer drill-through or a joined dataset/`Lookup` over subreports in large tables (each subreport instance runs its own query).

# Module: Server Features and Administration

## Lesson: [Intermediate|High] Deployment and security

- Deploy from Visual Studio (project properties: TargetServerURL, folders), by uploading `.rdl` in the web portal, or scripting with `rs.exe`/PowerShell ReportingServicesTools/REST API in CI/CD.
- **Security model**: role-based on folders/items, inherited down the folder tree. Item-level roles: **Browser**, **Content Manager**, **Publisher**, **Report Builder**, **My Reports**. System roles: **System Administrator**, **System User**.
- Authentication: Windows (NTLM/Kerberos) by default; custom forms authentication via extension.
- **Row-level data security**: pass `=User!UserID` to the query and filter by user, or rely on database security (Kerberos delegation).
- Back up the **encryption key** (Configuration Manager) along with the ReportServer databases — without it stored credentials can't be decrypted after a restore.

## Lesson: [Intermediate|High] Subscriptions, caching and snapshots

- **Standard subscription** — fixed recipients, schedule, format (e.g. PDF emailed every Monday 8 AM).
- **Data-driven subscription** (Enterprise edition) — recipients, parameters and formats come from a query (e.g. each sales manager gets their own region's report).
- Delivery extensions: **email** (SMTP configured), **file share**, SharePoint library, null (to pre-load cache).
- Schedules run through **SQL Server Agent** jobs (named by GUIDs) — Agent must be running.
- **Caching** — keep a temporary copy of a processed report for N minutes (per parameter combination) → faster repeated runs; requires stored credentials.
- **Snapshots** — report executed at a scheduled time and stored; users see that point-in-time data; **report history** keeps old snapshots.
- **Shared dataset caching** — cache the dataset for many reports.

## Lesson: [Advanced|Medium] Performance tuning and the execution log

```sql
SELECT TOP (50) ItemPath, UserName, Format, TimeStart,
       TimeDataRetrieval, TimeProcessing, TimeRendering, [RowCount], Status
FROM ReportServer.dbo.ExecutionLog3
ORDER BY TimeStart DESC;
```

- **TimeDataRetrieval high** → tune the SQL (indexes, stored procedures, return fewer rows, avoid `SELECT *`).
- **TimeProcessing high** → too much grouping/sorting/filtering in the report, complex expressions, subreports per row, `Lookup` over large datasets — push work to SQL.
- **TimeRendering high** → huge output, many pages, Excel exports of large data (consider CSV), images.
- Use caching/snapshots for expensive reports, schedule heavy reports via subscriptions off-peak, filter with parameters (never "all data by default"), avoid dataset **filters** (applied after fetching all rows) — filter in the query instead.

## Lesson: [Basic|Medium] SSRS vs Power BI vs Power BI Report Server

| | SSRS / paginated | Power BI (interactive) |
|---|---|---|
| Purpose | Pixel-perfect, printable, operational, many pages | Interactive analysis, dashboards, self-service |
| Authoring | Report Builder / Visual Studio (RDL) | Power BI Desktop (PBIX) |
| Data | Live queries per run | Import (VertiPaq), DirectQuery, Direct Lake |
| Exports | PDF, Excel, Word, CSV, print-ready | Limited pagination |
| Hosting | SSRS server, **Power BI Report Server**, Power BI Service (paginated) | Power BI Service, Power BI Report Server |

Microsoft's direction: Power BI Report Server for on-prem (hosts RDL + PBIX), Power BI Service/Fabric in the cloud.

# Interview

## [Beginner|High] What is SSRS and what are its main components?

SQL Server Reporting Services is a server-based reporting platform for creating, deploying and delivering paginated reports. Components: report designers (Visual Studio Reporting Services Projects, Report Builder), the Report Server Windows service (processing, rendering, scheduling), the ReportServer and ReportServerTempDB databases, the web portal and web service, and Report Server Configuration Manager. Reports are RDL (XML) files.

## [Beginner|High] What is the difference between a table, matrix and list?

All three are forms of the tablix data region. A table has fixed columns and dynamic rows (detail and group rows). A matrix has dynamic rows and dynamic columns based on groups — a pivot/cross-tab (e.g. products × months with totals). A list repeats a free-form layout per row or group — good for cards, labels or forms.

## [Beginner|High] What is the difference between a shared and an embedded data source?

A shared data source (.rds) is stored once on the report server and reused by many reports; changing it (e.g. server name, credentials) updates all of them. An embedded data source belongs to a single report. Shared ones simplify environment changes and credential management; subscriptions and caching need stored credentials.

## [Beginner|High] What are report parameters? How do you create cascading parameters?

Parameters let users filter reports (dates, region) and are passed into dataset queries. Cascading parameters are dependent: the available values of a child parameter come from a dataset that uses the parent parameter (Country → State → City). The parent must appear before the child in the parameter list; changing the parent refreshes the child's list.

## [Beginner|Medium] What rendering/export formats does SSRS support?

HTML (web), PDF, Excel (XLSX), Word (DOCX), PowerPoint (PPTX, 2016+), CSV, XML, TIFF/image, MHTML (web archive). Data-only formats (CSV, XML) ignore layout. Page breaks, page size and hidden items behave differently per renderer — test each required format.

## [Intermediate|High] What is the difference between drill-down and drill-through reports?

Drill-down shows/hides detail rows within the same report by toggling group visibility (+/− icons) — all data is already retrieved. Drill-through opens a different (target) report when you click an item, passing parameters (e.g. click a region total → regional detail report) — the target runs its own query only when requested.

## [Intermediate|High] How do you pass a multi-value parameter to a stored procedure?

Stored procedures can't receive SSRS multi-value arrays directly. In the dataset parameter, pass `=Join(Parameters!Region.Value, ",")` and split it in SQL using `STRING_SPLIT(@Regions, ',')` (2016+), a table-valued function or XML/JSON. With an embedded text query, `WHERE Region IN (@Region)` works natively because SSRS expands the list.

## [Intermediate|High] What are subscriptions? Standard vs data-driven?

Subscriptions automatically deliver reports on a schedule or event to email, a file share or SharePoint. Standard subscriptions have fixed recipients, parameters and format defined by the user. Data-driven subscriptions (Enterprise edition) get recipients, delivery settings and parameter values from a query at runtime, so each person receives a personalised report. Both rely on SQL Server Agent and stored credentials.

## [Intermediate|High] How do you improve SSRS report performance?

Check ExecutionLog3 to see whether data retrieval, processing or rendering dominates. Optimise queries/stored procedures and indexes, return only needed rows/columns, filter in SQL rather than dataset filters, push aggregations to SQL, avoid subreports in detail rows (use joins/Lookup/drill-through), reduce complex expressions, use caching, snapshots or shared dataset caching for expensive reports, and schedule heavy reports via subscriptions.

## [Intermediate|Medium] What is the difference between caching and snapshots?

A cached report is a temporary copy of a processed report (per parameter set) kept for a configured time after the first user runs it; it expires and refreshes on demand. A snapshot is executed on a schedule and stored as a point-in-time copy that all users see until the next snapshot; report history can retain old snapshots. Both require stored credentials and reduce load on the source database.

## [Intermediate|Medium] How do you show "Page X of Y" and alternating row colours?

Footer textbox: `="Page " & Globals!PageNumber & " of " & Globals!TotalPages`. Alternating rows: set the detail row's BackgroundColor to `=IIf(RowNumber(Nothing) Mod 2 = 0, "WhiteSmoke", "White")`.

## [Intermediate|Medium] How do you implement row-level security in SSRS?

Pass the built-in `User!UserID` (domain\user) to the dataset query or stored procedure and filter data by a user-to-region mapping table. Hide the parameter (or make it internal) so users can't change it. Alternatively use database-level security with Kerberos delegation (the user's identity flows to SQL Server with Row-Level Security). Item-level roles control who can open the report at all.

## [Advanced|Medium] What is the Lookup function? How is it different from a subreport?

`Lookup(source_expr, dest_expr, result_expr, "Dataset")` returns a value from another dataset by matching keys (`LookupSet` returns many, `MultiLookup` takes many keys). It combines data from two datasets (even different data sources) within one tablix without a SQL join. A subreport is a whole separate report rendered inside the container and executes its own query per instance — heavier. Lookup works in memory, so very large lookup datasets are slow too.

## [Advanced|Medium] What happened to SSRS after SQL Server 2022?

Microsoft announced that SQL Server 2022 Reporting Services is the last SSRS release; from SQL Server 2025, **Power BI Report Server** is the on-premises reporting solution, hosting both paginated (RDL) reports and Power BI reports. SSRS 2022 stays supported under its normal lifecycle. Cloud reporting moves to paginated reports in the Power BI service/Fabric. Existing RDL skills carry over.

## [Scenario|High] A report takes 3 minutes to open. ExecutionLog3 shows TimeDataRetrieval 170 seconds. What do you do?

The bottleneck is the query. Capture the dataset's SQL (stored procedure) with the actual execution plan; look for scans, missing indexes, non-SARGable predicates on date parameters, parameter sniffing (the same proc fast in SSMS but slow from SSRS — use `OPTION (RECOMPILE)` or local variables), and returning far more rows than displayed. Add covering indexes, pre-aggregate in SQL, limit default parameter ranges, and consider caching/snapshots or a summary table refreshed by ETL.

## [Scenario|High] Managers want each region's sales report emailed to them every Monday, but only their region. How?

Use a **data-driven subscription** (Enterprise edition): a query against a table of managers (Email, RegionId, Format) drives the subscription; map the Region parameter to RegionId and the To field to Email; schedule weekly Monday 8 AM; deliver as PDF. On Standard edition, create one standard subscription per manager, or use a SQL Agent job/.NET service that calls the SSRS REST/URL API to render per region and email it.

## [Scenario|Medium] A report looks fine in the browser but the PDF export has blank pages. Why?

The report body width + left/right margins exceeds the page width (Report Properties → Page size), so the renderer spills onto extra pages; or there's empty space at the right edge of the body; or `ConsumeContainerWhitespace` is false. Fix: make body width ≤ page width − margins, set ConsumeContainerWhitespace = True, shrink the body to fit the content, and check page break settings.

## [Scenario|Medium] Subscriptions suddenly stopped sending emails. How do you troubleshoot?

Check SQL Server Agent is running and the subscription jobs exist and succeed; review the subscription's status in the web portal; check the SSRS logs (`LogFiles` folder) and `ExecutionLog3`; verify the SMTP settings in Configuration Manager (server, port, sender address, authentication) and that the SMTP server accepts relays from the report server; confirm stored credentials of the data source are still valid (expired passwords break unattended runs); and check whether the report's parameters changed and invalidated the subscription.
